    60. 자바스크립트 이벤트 루프, Promise, async/await. 비동기 코드의 실행 순서를 손으로 추적하기¶

    직접 AI 없이 직접 할 수 있어야 하는 항목

    자바스크립트는 한 번에 한 가지만 실행한다. 그런데도 화면은 클릭에 답하고, 그동안 타이머와 네트워크 요청도 끝난다. 이 일들을 차례로 엮는 것이 이벤트 루프다. 비동기 코드는 쓴 차례와 실행 차례가 달라서, AI가 만든 코드도 순서를 잘못 짐작하는 일이 잦다. 직접형 항목이므로 출력 차례를 손으로 추적한 뒤 실행해 맞춘다. 예제는 node 파일이름.js로 실행한다(실습 환경). 브라우저 개발자 도구의 콘솔에 붙여 넣어도 차례는 같다.

    이 항목에서 배우는 것¶

    • 콜 스택, 태스크 큐, 마이크로태스크 큐가 하는 일을 그림으로 설명할 수 있다.
    • setTimeout, Promise, async/await가 섞인 코드의 출력 차례를 손으로 추적할 수 있다.
    • 오래 도는 동기 코드가 다른 일을 막는 까닭과, 기다림을 차례로 할 때와 함께 할 때의 차이를 재서 설명할 수 있다.

    1. 한 번에 하나만 돌고, 기다리는 일은 맡겨 두었다가 큐로 받는다¶

    • 자바스크립트는 콜 스택 하나로 함수를 하나씩 실행한다(9번(함수 호출과 메모리)). 타이머, 네트워크, 파일처럼 기다릴 일은 브라우저나 Node에 맡기고 다음 줄로 넘어간다.
    • 맡긴 일이 끝나면 그 콜백이 큐에 줄을 선다. 콜 스택이 빌 때마다 큐에서 일을 꺼내 실행하는 되풀이가 이벤트 루프다.
    • 그래서 동기 코드가 오래 돌면 아무것도 끼어들지 못한다. 이 PC에서 0ms 타이머를 건 뒤 동기 코드가 200ms 돌자, 타이머는 200.1~200.2ms 뒤에야 돌았다(3절 그림). 브라우저라면 그동안 클릭도 화면 그리기도 멈춘다.

    2. Promise의 콜백은 타이머보다 먼저, 큐가 빌 때까지 돈다¶

    직접 해 보기이벤트 루프 한 단계씩 보기코드를 골라 '한 단계'를 누르며, 콜 스택에서 무엇이 돌고 마이크로태스크 큐와 태스크 큐에 무엇이 줄을 서는지, 출력이 어떤 차례로 나오는지 본다
    새 창에서 크게 열기
    • 큐는 둘이다. setTimeout의 콜백, 요청·파일 완료, 클릭은 태스크 큐에 선다. Promise의 then 콜백과 await 다음 줄은 마이크로태스크 큐에 선다.
    • 콜 스택이 비면 마이크로태스크 큐를 끝까지 비우고, 그다음에 태스크를 하나만 꺼낸다. 그래서 setTimeout(fn, 0)은 "바로"가 아니라, 지금 줄 선 마이크로태스크가 다 끝난 뒤다.
    • then을 이어 붙이면, 뒤의 then은 앞의 then이 끝나야 줄을 선다(위젯의 "then 잇기").

    3. await는 함수를 거기서 멈추고, 그동안 다른 일이 돈다¶

    • await를 만나면 async 함수는 거기서 멈추고 콜 스택에서 내려온다. 기다리던 값이 준비되면 나머지가 마이크로태스크로 이어서 돈다(위젯의 "await").
    • 멈춘 동안 다른 코드가 돌기 때문에 기다림을 겹칠 수 있다. 100ms 기다리기 셋을 하나씩 await하면 321~332ms, Promise.all로 함께 기다리면 106~111ms였다.
    • 앞의 결과로 다음을 정하는 일처럼 차례가 중요하면 하나씩 기다려야 한다. 무엇을 겹쳐도 되는지는 코드를 쓰는 사람이 정한다.

    forEach는 콜백이 돌려주는 Promise를 기다리지 않는다. 세 콜백은 await에서 멈추고 돌아오고, forEach는 곧바로 끝나 "모두 끝"이 먼저 찍힌다. 처리 차례는 기다린 시간(10, 20, 30ms) 차례다. 다 끝난 뒤에 무엇을 하려면 await Promise.all(ids.map(async id => { … }))로 함께 기다리고(처리 1, 2, 3 뒤에 모두 끝), 하나씩 차례로 하려면 for (const id of ids) { await … }로 쓴다(처리 3, 1, 2 뒤에 모두 끝).   .then(users => console.log("all:", users.length))
  .catch(e => console.log("all 실패:", e.message));

Promise.allSettled([1, 0, 3].map(fetchUser))
  .then(rs => console.log("allSettled:", rs.map(r => r.status).join(", ")));

    all 실패: 없는 사용자: 0
allSettled: fulfilled, rejected, fulfilled
    • ids.map(id => fetchUser(id))가 요청 셋을 먼저 다 시작하고, Promise.all은 그 셋을 함께 기다린다. for 안에서 await하면 앞의 요청이 끝나야 다음을 시작한다.
    • Promise.all은 하나라도 실패하면 바로 그 오류로 끝난다. 나머지의 결과가 필요하면 Promise.allSettled로 저마다의 성공과 실패를 받는다.
    • 하나씩 기다리는 것이 맞는 경우도 있다. 서버가 동시 요청 수를 제한하거나, 앞의 결과로 다음 요청을 정할 때다.

    then에서 Promise를 돌려주면 두 번 더 미뤄진다

    then 콜백이 Promise를 돌려주면, 다음 then은 그 Promise가 끝나기를 기다리느라 마이크로태스크를 두 번 더 거친다. 아래에서 A는 둘째 then이지만 숫자 3 다음에 찍혔다. 이런 차례에 기대는 코드는 쓰지 않는다.

    Windows에서 타이머가 늦게 도는 까닭

    setTimeout(fn, ms)의 ms는 "적어도 그만큼 뒤"라는 뜻이다. 이 PC의 Node에서 1ms나 10ms 타이머를 20번씩 기다려 보니 한 번에 15.3~15.8ms(중앙값)가 걸렸다. Windows의 기본 타이머 간격(1/64초, 15.6ms)마다 깨어나기 때문이다. 100ms 타이머가 107~110ms 걸린 것도 같은 까닭이다. 시간을 정확히 맞춰야 하는 일에 타이머를 믿지 않는다.

    const wait = ms => new Promise(resolve => setTimeout(resolve, ms));

(async () => {
  for (const ms of [1, 10, 100]) {
    const xs = [];
    for (let i = 0; i < 20; i++) {
      const t = performance.now();
      await wait(ms);
      xs.push(performance.now() - t);
    }
    xs.sort((a, b) => a - b);
    console.log(`setTimeout ${ms} ms: median ${xs[10].toFixed(1)} ms`);
  }
})();
    이 항목의 측정 프로그램

    1절과 3절의 값과 그림은 이 PC(Core i9-14900KF, DDR5 64GB, Windows 11, Node.js v24.10.0)에서 아래 프로그램을 20번 넘게 실행한 범위다. busy는 정해진 시간 동안 CPU를 붙잡고 이벤트 루프에 아무것도 넘기지 않는다. 첫 줄(busy 0)은 막지 않아도 0ms 타이머가 0.1~16.5ms 뒤에 돈 것으로, 다음 타이머 눈금까지 기다리기 때문이다(앞의 접힘).

    // 60번 측정: (1) 동기 코드가 도는 동안 0ms 타이머는 얼마나 늦게 도나 (2) 100ms 기다리기 셋을 차례로 할 때와 함께 할 때
const wait = ms => new Promise(resolve => setTimeout(resolve, ms));

function busy(ms) {                          // ms 동안 CPU를 붙잡고 아무것도 넘기지 않는다
  const end = performance.now() + ms;
  while (performance.now() < end) {}
}

function timerDelay(busyMs) {                // setTimeout(0)을 걸고 busyMs 동안 막은 뒤, 타이머가 언제 도는지 잰다
  return new Promise(resolve => {
    const start = performance.now();
    setTimeout(() => resolve(performance.now() - start), 0);
    busy(busyMs);
  });
}

async function main() {
  for (const ms of [0, 50, 200]) {
    console.log(`busy ${ms} ms -> timer ran after ${(await timerDelay(ms)).toFixed(1)} ms`);
  }
  let t = performance.now();
  await wait(100); await wait(100); await wait(100);
  console.log(`sequential: ${(performance.now() - t).toFixed(1)} ms`);
  t = performance.now();
  await Promise.all([wait(100), wait(100), wait(100)]);
  console.log(`parallel: ${(performance.now() - t).toFixed(1)} ms`);
}

main();

    정리¶

    • 자바스크립트는 콜 스택 하나로 한 번에 하나씩 실행하고, 기다리는 일의 콜백은 큐에 줄을 선다. 동기 코드가 오래 돌면 모든 것이 멈춘다.
    • 콜 스택이 비면 마이크로태스크(then, await 다음)를 모두, 그다음 태스크(setTimeout, I/O, 클릭)를 하나 꺼낸다.
    • await는 함수를 멈추고 나머지를 미룬다. 겹쳐도 되는 기다림은 Promise.all로 함께 기다리고, forEach 안의 await는 기다려 주지 않는다는 것을 기억한다.
