    63. 시스템 간 데이터 교환: JSON과 직렬화¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    브라우저와 서버, 서비스와 서비스는 서로 다른 언어로 짜인 경우가 많다. 메모리 속 값은 그대로 건넬 수 없어서, 글이나 바이트로 바꿔 보내고 받는 쪽이 다시 값을 만든다. 웹 API는 대개 그 글로 JSON을 쓴다. 그런데 JSON에 담기지 않는 값이 있고, 같은 글도 언어마다 다르게 읽어 값이 바뀐다. 이 항목은 직렬화 결과를 먼저 예측하고 자바스크립트(Node)와 Python에서 확인한다.

    이 항목에서 배우는 것¶

    • 직렬화와 역직렬화를 설명하고, JSON이 담을 수 있는 값을 말할 수 있다.
    • JSON에 없는 값이 직렬화에서 어떻게 바뀌는지 예측할 수 있다.
    • 큰 정수와 날짜처럼 언어 사이에서 바뀌는 값을 알아채고, 안전하게 주고받는 모양을 정할 수 있다.

    1. 직렬화는 메모리 속 값을 글로 바꿔 보내는 일이다¶

    • 프로그램의 값은 메모리 속에서 서로를 가리키는 객체다. 그대로는 다른 프로세스나 다른 언어에 건넬 수 없어서, 정해진 형식의 글이나 바이트로 바꾼다(직렬화). 받는 쪽은 그 글로 자기 언어의 값을 다시 만든다(역직렬화).
    • JSON은 그 형식의 하나다. 값은 문자열, 수, true와 false, null, 배열, 객체뿐이고, 글은 UTF-8로 보낸다(4번(데이터 표현)).
    • 거의 모든 언어가 JSON을 읽고 써서 웹 API의 기본이 되었다. 대신 값이 JSON의 여섯 가지로 옮겨질 때마다 무엇인가 바뀔 수 있다.

    2. JSON에 없는 값은 바뀌거나 조용히 사라진다¶

    직접 해 보기JSON으로 보내면 무엇이 남나자바스크립트 값을 하나 골라, JSON.stringify가 만든 글과 그 글을 다시 읽은 값(자바스크립트와 Python)을 견주며 무엇이 바뀌거나 사라지는지 본다
    새 창에서 크게 열기
    • 날짜는 문자열로, Map과 Set은 빈 객체로, NaN은 null로 바뀐다. 값이 undefined이거나 함수인 속성은 빠진다. 오류가 나지 않으니 받는 쪽에서야 알아챈다.
    • BigInt(정해진 바꾸는 법이 없다)나 자기를 가리키는 객체(끝없이 이어진다)는 JSON.stringify가 오류를 낸다.
    • 그래서 무엇을 어떤 모양으로 보내는지 정해 둔다. 날짜처럼 JSON에 없는 값은 보낼 모양(예: ISO 8601 글)을 약속하고, 그 약속을 API 명세에 적는다(64번(REST API 설계)).

    3. 같은 글도 언어마다 다르게 읽어, 수와 날짜가 바뀐다¶

    • 자바스크립트의 수는 64비트 부동소수점이라(4번(데이터 표현)), 2⁵³(9007199254740992)을 넘으면 정수를 모두 담지는 못한다(…993처럼 빠지는 수가 생긴다). 데이터베이스의 큰 ID를 JSON의 수로 보내면 자바스크립트에서 다른 ID가 된다. Python은 같은 글을 그대로 읽는다. 큰 ID는 문자열로 보낸다.
    • 날짜는 JSON에 없어서 글로 보내는데, 시각까지 쓰고 시간대를 적지 않으면 읽는 쪽의 시간대로 읽혀 다른 순간이 된다. 시간대가 붙은 ISO 8601 글(…+09:00, …Z)로 보낸다.
    • 보내는 쪽과 받는 쪽이 같은 글을 같은 값으로 읽는지는 양쪽에서 실제로 읽어 봐야 안다(문제 1~3).

    예측해 보기¶

    문제 1. Python 서버가 json.dumps({"name": "김하나", "score": float("nan")}, ensure_ascii=False)로 응답을 만들었다. 브라우저가 이 글을 JSON.parse로 읽으면 무엇이 출력될까?

    const text = '{"name": "김하나", "score": NaN}';   // Python이 만든 글 그대로
const data = JSON.parse(text);
console.log(data.score); // 출력되지 않는다
    정답과 해설

    JSON.parse에서 SyntaxError가 나고, 아무것도 출력되지 않는다. 이 PC의 Node에서 SyntaxError: Unexpected token 'N', ..." "score": NaN}" is not valid JSON이었다. Python의 json.dumps는 기본으로 NaN과 Infinity를 그대로 NaN, Infinity라고 쓰는데, JSON 문법에는 없는 글자다. Python 자신은 이것을 다시 읽지만, 자바스크립트처럼 JSON 문법을 따르는 파서는 오류를 낸다. Python에서 allow_nan=False를 주면 보내기 전에 ValueError로 알려 주므로, NaN을 None으로 바꿔 보내게 고칠 수 있다.

    문제 2. 데이터베이스의 ID 넷을 JSON 배열로 받았다. 무엇이 출력될까?

    const ids = JSON.parse("[9007199254740991, 9007199254740992, 9007199254740993, 9007199254740995]");
console.log(ids.join(" "));
    정답과 해설 
    9007199254740991 9007199254740992 9007199254740992 9007199254740996

    2⁵³(…992)을 넘으면 짝수만 담을 수 있다. …993은 …992와 …994의 한가운데이고, …995는 …994와 …996의 한가운데다. 한가운데일 때는 두 수 가운데 가수(유효 숫자 53비트)의 끝 비트가 0인 쪽으로 맞춘다(짝수 쪽 반올림). 이 범위에서는 4의 배수인 쪽이라 …993은 …992로, …995는 …996으로 바뀌었다. 서로 다른 ID 둘이 같은 ID가 되었고, 오류는 나지 않았다. ID를 문자열로 보내면 그대로 남는다.

    문제 3. 사용자가 입력창에 고른 날짜와 시각을 시간대 없이 서버로 보냈다. 서버는 UTC로, 사용자의 PC는 한국 시간으로 돈다. 두 쪽이 읽은 순간은 몇 시간 차이 날까?

    const fromForm = "2026-10-15T09:00";            // 입력창이 준 날짜와 시각. 시간대가 없다
process.env.TZ = "UTC";                         // 서버는 UTC로 돈다고 하자(Node에서만 된다)
const atServer = new Date(fromForm);
process.env.TZ = "Asia/Seoul";                  // 사용자의 PC는 한국 시간이다
const atClient = new Date(fromForm);
console.log((atServer - atClient) / 3600000);
    정답과 해설

    9. 서버는 그 글을 UTC 9시로, 사용자의 PC는 한국 9시(UTC 0시)로 읽었다. 서버에는 9시간 뒤의 순간이 저장되어, 오전 9시 회의가 오후 6시가 된다. 시간대가 없는 글은 읽는 쪽의 시간대를 따른다. 사용자의 PC에서 new Date(fromForm).toISOString()처럼 시간대가 붙은 글로 바꿔 보낸다.

    직접 해보기¶

    실습: Python과 자바스크립트 사이에서 주문 주고받기

    1. 아래 Python 코드를 실행하면 오류가 난다. 까닭을 적고, id는 문자열로, created는 시간대가 붙은 ISO 8601 글로 바꿔 보내게 고친다.
    2. 고친 Python 코드가 출력한 글을 자바스크립트 코드에 붙여 넣고 JSON.parse로 읽어, id와 시각이 그대로인지 확인한다.
    3. id를 수 그대로 보내면 자바스크립트에서 무엇이 되는지 확인한다.

    import json
from datetime import datetime, timedelta, timezone

order = {"id": 9007199254740993, "customer": "김하나",
         "created": datetime(2026, 10, 15, 9, 0, tzinfo=timezone(timedelta(hours=9)))}
print(json.dumps(order))

    확인할 점

    1의 오류는 TypeError: Object of type datetime is not JSON serializable이다. Python의 날짜도 JSON에 없는 값이다. 고친 한 예다.

    import json
from datetime import datetime, timedelta, timezone

order = {"id": 9007199254740993, "customer": "김하나",
         "created": datetime(2026, 10, 15, 9, 0, tzinfo=timezone(timedelta(hours=9)))}
text = json.dumps({"id": str(order["id"]), "customer": order["customer"],
                   "created": order["created"].isoformat()}, ensure_ascii=False)
print(text)

    {"id": "9007199254740993", "customer": "김하나", "created": "2026-10-15T09:00:00+09:00"}

    2를 자바스크립트로 읽은 결과다. 시각은 UTC로 바꿔 찍어도 같은 순간이다.

    const text = '{"id": "9007199254740993", "customer": "김하나", "created": "2026-10-15T09:00:00+09:00"}';
const order = JSON.parse(text);
const created = new Date(order.created);
console.log(order.id, typeof order.id); // "9007199254740993 string"
console.log(created.toISOString()); // 2026-10-15T00:00:00.000Z
    • 3에서 str을 빼고 수로 보내면 자바스크립트의 order.id는 9007199254740992가 된다(문제 2). 같은 주문을 다시 찾을 때 엉뚱한 주문이 나온다.
    • 날짜를 isoformat()으로 보내면 시간대(+09:00)가 붙는다. 시간대가 없는 datetime이면 isoformat()에도 시간대가 없으니, 만들 때부터 시간대를 붙인다.

    AI와 함께 확인하기¶

    AI 활용 과제: 상태를 저장하고 불러오는 함수 검증하기

    1. AI에게 "웹 앱의 상태(Date와 Map이 들어 있다)를 JSON 글로 저장하는 save(state)와 다시 불러오는 load(text)를 짜 줘"라고 한다.
    2. 받은 두 함수 아래에 시험 코드를 붙여 실행한다. true true 2가 나와야 한다.
    3. 다르게 나오면 무엇이 바뀌었는지 AI에게 보여 주고 고치게 한다.

    const state = { updated: new Date(0), cart: new Map([["키보드", 2]]) };
const back = load(save(state));
console.log(back.updated instanceof Date, back.cart instanceof Map, back.cart.get("키보드"));

    확인할 점
    • JSON.stringify와 JSON.parse만 쓰는 답이면 TypeError: back.cart.get is not a function으로 멈춘다. Date는 문자열로, Map은 빈 객체로 와서 get이 없다.
    • JSON.stringify(state, (key, value) => value instanceof Date ? … : value)처럼 바꿔 쓰는 함수(replacer)에서 Date를 찾는 답이 흔한데, 이 조건은 늘 거짓이다. Date는 replacer에 오기 전에 이미 toJSON으로 문자열이 되어 있다. 원래 값은 this[key]로 본다. 한 예다.
    function save(state) {
  return JSON.stringify(state, function (key, value) {
    const raw = this[key];                        // value는 toJSON을 거친 값이라 Date가 이미 문자열이다
    if (raw instanceof Date) return { $type: "Date", iso: raw.toISOString() };
    if (raw instanceof Map) return { $type: "Map", entries: [...raw] };
    return value;
  });
}

function load(text) {
  return JSON.parse(text, (key, value) => {
    if (value && value.$type === "Date") return new Date(value.iso);
    if (value && value.$type === "Map") return new Map(value.entries);
    return value;
  });
}

const state = { updated: new Date(0), cart: new Map([["키보드", 2]]) };
const back = load(save(state));
console.log(back.updated instanceof Date, back.cart instanceof Map, back.cart.get("키보드")); // "true true 2"
    • 저장한 글을 다른 프로그램이 읽는다면 $type 같은 표시도 약속에 넣어야 한다. 한 프로그램 안에서 값을 복사만 하려면 JSON 대신 structuredClone(state)이 Date와 Map을 그대로 지킨다.

    더 알아보기¶

    한글은 몇 바이트로 가나

    JSON 글은 UTF-8로 보낸다. 자바스크립트의 JSON.stringify는 한글을 그대로 두지만, Python의 json.dumps는 기본으로 ASCII가 아닌 글자를 \uae40처럼 바꿔 쓴다. 둘 다 올바른 JSON이고 서로 읽을 수 있지만 길이가 다르다. {"name":"김하나"}가 자바스크립트에서는 20바이트, Python 기본값으로는 {"name": "\uae40\ud558\ub098"} 30바이트였다. Python에서 ensure_ascii=False를 주면 한글을 그대로 쓴다.

    const text = JSON.stringify({ name: "김하나" });
console.log(text, Buffer.byteLength(text));

    {"name":"김하나"} 20
    JSON 문법은 생각보다 엄격하다

    JSON에는 주석이 없고, 문자열과 이름은 큰따옴표로만 쓰며, 끝에 쉼표를 둘 수 없다. 사람이 손으로 고친 설정 파일이 여기서 자주 깨진다. 오류 문장은 언어마다 다르다.

    for (const text of ['{"a": 1,}', "{'a': 1}", '{"a": 1} // 설명']) {
  try { JSON.parse(text); } catch (e) { console.log(e.message); }
}

    Expected double-quoted property name in JSON at position 8 (line 1 column 9)
Expected property name or '}' in JSON at position 1 (line 1 column 2)
Unexpected non-whitespace character after JSON at position 9 (line 1 column 10)
    큰 정수를 정확히 읽기

    JSON.parse의 바꾸는 함수(reviver)는 셋째 인자의 source로 수나 문자열 같은 값의 원래 글을 받는다. 이것으로 큰 수를 BigInt로 읽을 수 있다. 이 PC의 Node v24.10.0과 Chrome 155에서 됐다. 다만 받는 쪽마다 이런 처리를 해야 하므로, 처음부터 문자열로 보내는 편이 간단하다.

    const data = JSON.parse('{"id": 9007199254740993}', (key, value, ctx) => key === "id" ? BigInt(ctx.source) : value);
console.log(data.id); // 9007199254740993n
    JSON이 아닌 직렬화 형식

    JSON은 사람이 읽을 수 있고 어디서나 쓰지만, 이름을 값마다 되풀이해 적어서 크고 느린 편이다. 서비스끼리 많이 주고받을 때는 Protocol Buffers처럼 모양(스키마)을 먼저 정해 두고 이진으로 보내는 형식도 쓴다. 어느 형식이든 "어떤 값을 어떤 모양으로 보내는가"를 양쪽이 같은 명세로 약속하는 것은 같다(64번(REST API 설계)).

    정리¶

    • 직렬화는 메모리 속 값을 글로, 역직렬화는 그 글을 다시 값으로 바꾸는 일이다. JSON 글에는 문자열, 수, true와 false, null, 배열, 객체만 있다.
    • 날짜, Map, Set, NaN, undefined처럼 JSON에 없는 값은 바뀌거나 조용히 사라지고, BigInt와 자기를 가리키는 객체는 오류가 난다.
    • 큰 정수는 자바스크립트에서 바뀌므로 문자열로, 날짜는 시간대가 붙은 ISO 8601 글로 보낸다. 같은 글을 양쪽 언어에서 실제로 읽어 확인한다.
