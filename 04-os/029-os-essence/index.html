    29. 운영체제의 본질: 하드웨어 추상화, 커널과 시스템 콜, 사용자 모드와 커널 모드¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    프로그램은 파일을 쓰고 화면에 글자를 찍지만, SSD나 그래픽 카드를 직접 다루지 않는다. 모두 운영체제에 부탁한다. 이 항목은 그 부탁이 어떤 길로 가는지, 프로그램이 왜 하드웨어를 직접 만질 수 없는지, 부탁 한 번에 시간이 얼마나 드는지를 이 PC에서 확인한다. 섹션 4의 예제는 C이고, Windows의 API를 그대로 부른다.

    이 항목에서 배우는 것¶

    • 운영체제가 하드웨어를 감추고 프로그램에 같은 방법(파일, 창, 소켓)을 주는 까닭을 설명할 수 있다.
    • 사용자 모드와 커널 모드의 차이와, 사용자 모드에서 막힌 일을 하면 어떻게 되는지 예측할 수 있다.
    • 시스템 콜이 함수 호출보다 훨씬 비싼 까닭을 설명하고, 라이브러리가 버퍼에 모아 쓰는 이유를 말할 수 있다.

    1. 프로그램은 하드웨어 대신 운영체제에 부탁한다¶

    • 운영체제는 SSD, 화면, 네트워크 카드의 차이를 감추고 "파일", "창", "소켓"처럼 같은 방법을 준다(하드웨어 추상화). 그래서 같은 fopen 코드가 SSD에서도 USB 메모리에서도 돈다.
    • 운영체제의 중심에서 하드웨어를 직접 다루는 부분이 커널이다. 프로그램은 여럿이어도 커널은 하나이고, 모든 프로그램의 부탁을 받아 차례를 정한다.
    • 프로그램이 커널에 부탁하는 정해진 입구가 시스템 콜이다. Windows에서는 WriteFile 같은 API가 ntdll.dll의 짧은 코드(NtWriteFile)를 거쳐 syscall 명령으로 커널에 들어간다.

    2. 사용자 모드에서는 하드웨어를 직접 만질 수 없다¶

    • CPU에는 모드가 있다. 프로그램은 사용자 모드, 커널은 커널 모드에서 돈다. 사용자 모드에서는 CPU를 멈추는 hlt 같은 특권 명령, 커널의 메모리, 장치를 직접 다루는 일이 막혀 있다.
    • 막힌 일을 하면 CPU가 예외를 내고, 운영체제가 그 프로그램만 끝낸다(아래 문제 1, 2). 프로그램 하나의 실수가 컴퓨터 전체를 멈추지 못하게 하는 장치다.
    • syscall 명령은 CPU를 커널 모드로 바꾸면서 커널이 미리 정해 둔 입구로만 들어가게 한다. 그래서 프로그램은 커널이 허락한 일만 부탁할 수 있다.
    • 커널 모드로 들어가는 길은 셋이다. 프로그램이 부탁하는 시스템 콜, 막힌 일을 했을 때의 예외(문제 1, 2), 장치가 CPU에 보내는 인터럽트(3번(컴퓨터 핵심 구성 요소))다. 인터럽트가 오면 CPU는 하던 일을 멈추고 커널의 처리 코드로 간다. 커널은 일을 마친 장치를 기다리던 프로그램을 깨우고, 시계가 일정한 간격으로 보내는 타이머 인터럽트로 프로그램의 차례를 바꾼다(32번(CPU 스케줄링과 컨텍스트 스위칭)).

    3. 시스템 콜은 비싸서 모아서 부른다¶

    직접 해 보기시스템 콜을 모아 부르면한 번에 쓰는 크기를 1바이트에서 64KiB까지 바꿔 가며, 1MiB를 파일에 쓸 때 시스템 콜 횟수와 걸린 시간이 어떻게 줄어드는지 이 PC에서 잰 값으로 본다
    새 창에서 크게 열기
    • 모드를 바꾸고, 부탁이 올바른지 검사하고, 돌아오는 일 때문에 시스템 콜은 함수 호출보다 훨씬 비싸다. 이 PC에서 함수 호출은 약 0.4ns, 시스템 콜 한 번(SetEvent)은 73~78ns로 약 200배였다.
    • 그래서 C의 fputc, fprintf는 파일에 쓸 때 글자를 바로 쓰지 않고 버퍼에 모았다가 한 번에 WriteFile을 부른다. 1MiB를 1바이트씩 쓸 때 WriteFile을 직접 부르면 1,048,576번에 2.3초가 걸렸고, fputc는 256번(4KiB씩)에 15~17ms였다. 파일에 쓰는 WriteFile 한 번(약 2.2µs)이 SetEvent보다 훨씬 비싼 것은 커널 안에서 파일 시스템과 캐시를 거치기 때문이다. 아무 일도 하지 않는 NUL 장치에 쓰면 106~109ns였다(위젯 위쪽).
    • GetCurrentProcessId처럼 커널에 가지 않고 답할 수 있는 API는 1.6~1.7ns로 함수 호출에 가깝다. 운영체제의 API라고 모두 시스템 콜은 아니다.

    예측해 보기¶

    문제 1. __halt()는 CPU의 hlt 명령을 그대로 넣는 MSVC 함수다. 무엇이 출력되고 어떻게 끝날까?

    #include <stdio.h>
#include <intrin.h>

int main(void) {
    printf("before\n");
    fflush(stdout);
    __halt();                 /* hlt: CPU를 멈추는 특권 명령 */
    printf("after\n");        /* 출력되지 않는다 */
    return 0;
}
    정답과 해설

    before. 그다음 __halt()에서 프로그램이 끝난다. 종료 코드는 0xC0000096(특권 명령)이다. hlt는 커널 모드에서만 쓸 수 있는 명령이라, 사용자 모드에서 실행하자 CPU가 예외를 내고 운영체제가 이 프로그램을 끝냈다. 컴퓨터는 멈추지 않는다.

    문제 2. 64비트 Windows에서 0xFFFF800000000000부터의 주소는 커널의 몫이다(8번(프로세스의 메모리 레이아웃)). 사용자 모드에서 그 주소를 읽으면?

    #include <stdio.h>

int main(void) {
    int *kernel = (int *)0xFFFF800000000000ull;   /* 커널 영역의 주소 */
    printf("read kernel\n");
    fflush(stdout);
    printf("%d\n", *kernel);                       /* 출력되지 않는다 */
    return 0;
}
    정답과 해설

    read kernel. 그다음 줄에서 종료 코드 0xC0000005(접근 위반)로 끝난다. 커널의 메모리는 사용자 모드에서 읽을 수도 쓸 수도 없게 표시되어 있다. 프로그램이 커널의 데이터를 엿보거나 망가뜨리지 못하게 하는 장치다.

    문제 3. 1MiB를 fputc로 1바이트씩 파일에 쓰면, C 라이브러리는 WriteFile을 몇 번 부를까?

    정답과 해설

    256번. 이 PC의 C 라이브러리(MSVC)는 파일마다 4,096바이트 버퍼를 두고, 버퍼가 찰 때마다 WriteFile을 한 번 부른다. 1,048,576 ÷ 4,096 = 256이다. GetProcessIoCounters로 센 쓰기 횟수도 256이었다(아래 "더 알아보기"의 측정 프로그램).

    직접 해보기¶

    실습: 내 PC에서 커널로 들어가는 길 확인하기

    1. 아래 프로그램으로 내 PC의 ntdll.dll에 있는 NtSetEvent, NtWriteFile, NtClose의 첫 24바이트를 찍는다. 0F 05(syscall)를 찾고, 그 앞의 B8 xx 00 00 00(mov eax, xx)에서 시스템 콜 번호를 읽는다.
    2. "더 알아보기"의 측정 프로그램으로 1MiB를 쓰는 크기를 바꿔 가며 쓰기 횟수와 시간을 잰다. 위젯의 값과 비교한다.
    #include <stdio.h>
#include <windows.h>

int main(void) {
    const char *names[] = { "NtSetEvent", "NtWriteFile", "NtClose" };
    HMODULE ntdll = GetModuleHandleA("ntdll.dll");
    for (int k = 0; k < 3; k++) {
        unsigned char *p = (unsigned char *)GetProcAddress(ntdll, names[k]);
        printf("%-12s", names[k]);
        for (int i = 0; i < 24; i++)
            printf(" %02X", p[i]);
        printf("\n");
    }
    return 0;
}
    확인할 점

    이 PC(Windows 11 빌드 26300)에서는 다음과 같았다.

    NtSetEvent   4C 8B D1 B8 0E 00 00 00 F6 04 25 08 03 FE 7F 01 75 03 0F 05 C3 CD 2E C3
NtWriteFile  4C 8B D1 B8 08 00 00 00 F6 04 25 08 03 FE 7F 01 75 03 0F 05 C3 CD 2E C3
NtClose      4C 8B D1 B8 0F 00 00 00 F6 04 25 08 03 FE 7F 01 75 03 0F 05 C3 CD 2E C3
    • 세 함수의 모양이 같고 번호만 다르다. NtSetEvent는 14(0x0E), NtWriteFile은 8, NtClose는 15(0x0F)다. 커널은 이 번호를 보고 어떤 일을 할지 고른다.
    • 번호는 Windows 판마다 달라질 수 있다. 그래서 프로그램은 번호를 직접 쓰지 않고 ntdll.dll을 거친다.
    • 측정 결과는 PC마다 다르지만, 쓰는 크기가 작을 때는 횟수가 줄어든 만큼 시간이 줄어드는 모양이 같다.
    • 보안 프로그램이 ntdll.dll을 고쳐 둔 PC에서는 첫 바이트가 E9(jmp)처럼 다르게 보일 수 있다.

    AI와 함께 확인하기¶

    AI 활용 과제: 백만 줄을 빨리 쓰는 코드

    1. AI에게 "C로 0부터 999,999까지의 수를 한 줄에 하나씩 파일에 쓰는 빠른 코드"를 짜 달라고 한다.
    2. 실행하기 전에 쓰기 시스템 콜이 몇 번쯤 불릴지 예측한다.
    3. 실행해 시간을 재고, 쓰기 앞뒤로 GetProcessIoCounters의 WriteOperationCount를 읽어 실제 횟수를 센다. AI의 설명과 대조한다.
    확인할 점
    • 파일 크기는 7,888,890바이트다. "w"(텍스트 모드)로 열면 Windows에서는 \n이 \r\n으로 바뀌어 줄마다 1바이트가 붙는다. "wb"로 열면 6,888,890바이트다.
    • fprintf로 쓰는 답이면, 이 PC에서 쓰기는 1,683번에 65~77ms였다. 버퍼에는 \r\n으로 바꾸기 전의 글자가 4KiB씩 모이므로, "wb"로 열면 6,888,890 ÷ 4,096을 올림한 1,682번이다. 텍스트 모드에서 한 번 더 많은 것은, 줄이 짧아 줄바꿈이 많은 첫 버퍼가 \r\n으로 바뀌며 길어져 두 번에 나뉘어 쓰였기 때문이다.
    • 줄마다 fflush를 부르는 답은 쓰기가 1,000,000번으로 늘고 2.4~2.9초가 걸렸다. "빠짐없이 저장하려고" 넣었다면 그 대가를 아는지 본다.

    더 알아보기¶

    ntdll의 시스템 콜 코드 읽기

    실습 1에서 찍은 바이트를 명령어로 나누면 다음과 같다.

    4C 8B D1                  mov r10, rcx
B8 08 00 00 00            mov eax, 8                  (시스템 콜 번호)
F6 04 25 08 03 FE 7F 01   test byte ptr [7FFE0308h], 1
75 03                     jne (아래 int 2Eh로)
0F 05                     syscall                     (커널 모드로)
C3                        ret
CD 2E                     int 2Eh                     (예전 방식의 입구)
C3                        ret

    인자는 레지스터로 넘기고, 커널은 eax의 번호로 할 일을 고른다. 0x7FFE0308은 커널이 모든 프로그램에 읽기 전용으로 보여 주는 공유 영역이다. 그 값에 따라 syscall 대신 예전 방식인 int 2Eh로 들어가기도 한다.

    이 항목의 측정 프로그램

    3절과 위젯의 값은 이 PC(Core i9-14900KF, DDR5 64GB, NVMe SSD, Windows 11 빌드 26300)에서 아래 두 프로그램을 cl /O2로 빌드해 5번씩 실행한 범위다. 함수 호출이 최적화로 사라지지 않았는지는 기계어(/FAs)에서 call add를 보고 확인했다.

    /* 29번 측정 1: 호출 한 번에 걸리는 시간 (ns) */
#include <stdio.h>
#include <windows.h>

static double now_ns(void) {
    static LARGE_INTEGER f; LARGE_INTEGER c;
    if (!f.QuadPart) QueryPerformanceFrequency(&f);
    QueryPerformanceCounter(&c);
    return (double)c.QuadPart * 1e9 / (double)f.QuadPart;
}

__declspec(noinline) static int add(int a, int b) { return a + b; }

int main(void) {
    HANDLE ev = CreateEventA(NULL, TRUE, FALSE, NULL);
    HANDLE nul = CreateFileA("NUL", GENERIC_WRITE, 0, NULL, OPEN_EXISTING, 0, NULL);
    volatile int sink = 0;
    for (int kind = 0; kind < 4; kind++) {
        const char *name[] = { "function", "GetCurrentProcessId", "SetEvent", "WriteFile(NUL)" };
        long long n = 0;
        double t0 = now_ns(), t1;
        do {
            for (int i = 0; i < 1000; i++) {
                DWORD w;
                switch (kind) {
                case 0: sink = add(sink, i); break;
                case 1: sink += (int)GetCurrentProcessId(); break;
                case 2: SetEvent(ev); break;
                case 3: WriteFile(nul, "x", 1, &w, NULL); break;
                }
            }
            n += 1000;
            t1 = now_ns();
        } while (t1 - t0 < 3e8);
        printf("%-20s %8.1f ns  (%lld)\n", name[kind], (t1 - t0) / n, n);
    }
    CloseHandle(nul);
    CloseHandle(ev);
    return 0;
}

    /* 29번 측정 2: 1MiB를 파일에 쓸 때 한 번에 쓰는 크기에 따른 쓰기 횟수와 시간 */
#include <stdio.h>
#include <windows.h>

#define TOTAL (1 << 20)

static double now_ms(void) {
    static LARGE_INTEGER f; LARGE_INTEGER c;
    if (!f.QuadPart) QueryPerformanceFrequency(&f);
    QueryPerformanceCounter(&c);
    return (double)c.QuadPart * 1000.0 / (double)f.QuadPart;
}

static ULONGLONG writes(void) {                 /* 이 프로세스가 지금까지 한 쓰기 횟수 */
    IO_COUNTERS io;
    GetProcessIoCounters(GetCurrentProcess(), &io);
    return io.WriteOperationCount;
}

static char buf[65536];

int main(void) {
    char path[MAX_PATH];
    GetTempPathA(MAX_PATH, path);
    lstrcatA(path, "cs29.bin");
    int sizes[] = { 1, 16, 256, 4096, 65536 };
    for (int k = 0; k < 5; k++) {
        HANDLE h = CreateFileA(path, GENERIC_WRITE, 0, NULL, CREATE_ALWAYS, FILE_ATTRIBUTE_NORMAL, NULL);
        ULONGLONG w0 = writes();
        double t0 = now_ms();
        for (int done = 0; done < TOTAL; done += sizes[k]) {
            DWORD w;
            WriteFile(h, buf, sizes[k], &w, NULL);
        }
        double t1 = now_ms();
        ULONGLONG w1 = writes();
        CloseHandle(h);
        printf("WriteFile %6d bytes  %8llu calls  %8.2f ms\n", sizes[k], w1 - w0, t1 - t0);
    }
    FILE *fp = fopen(path, "wb");
    ULONGLONG w0 = writes();
    double t0 = now_ms();
    for (int i = 0; i < TOTAL; i++)
        fputc('x', fp);
    fflush(fp);
    double t1 = now_ms();
    ULONGLONG w1 = writes();
    fclose(fp);
    printf("fputc     %6d bytes  %8llu calls  %8.2f ms\n", 1, w1 - w0, t1 - t0);
    DeleteFileA(path);
    return 0;
}

    정리¶

    • 운영체제는 하드웨어의 차이를 감추고 장치와 상관없이 같은 방법(파일, 창, 소켓)을 준다. 그 중심에서 하드웨어를 직접 다루는 부분이 커널이다.
    • 프로그램은 사용자 모드에서 돈다. 특권 명령, 커널 메모리, 장치 접근은 막혀 있고, 어기면 그 프로그램만 끝난다.
    • 커널에 부탁하는 입구가 시스템 콜이다. 함수 호출의 수백 배가 들어서, 라이브러리는 버퍼에 모았다가 한 번에 부른다.
