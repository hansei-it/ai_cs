    31. 프로세스 간 통신(IPC): 파이프, 소켓, 공유 메모리¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    30번(프로그램, 프로세스, 스레드)에서 프로세스끼리는 기본으로 서로의 메모리를 볼 수 없다는 것을 봤다. 그래도 프로그램은 서로 데이터를 주고받아야 한다. 명령 프롬프트에서 dir | findstr exe처럼 앞 프로그램의 출력을 뒤 프로그램에 넘기고, 브라우저는 웹 서버와 데이터를 주고받는다. 이 항목은 운영체제가 마련한 세 가지 길인 파이프, 소켓, 공유 메모리가 어떻게 다른지를 이 PC에서 확인한다.

    이 항목에서 배우는 것¶

    • 파이프, 소켓, 공유 메모리가 데이터를 어떤 길로 보내는지 설명할 수 있다.
    • 파이프와 TCP 소켓에서 "보낸 단위"와 "받는 단위"가 다를 수 있음을 예측하고, 경계를 표시하는 방법을 말할 수 있다.
    • 세 방법의 빠르기를 정하는 것(복사, 페이지 폴트, 신호 주고받기)을 설명할 수 있다.

    1. 프로세스끼리는 운영체제가 만든 길로 주고받는다¶

    • 파이프는 커널 안의 버퍼다. 한쪽이 쓰면 커널 버퍼에 들어가고, 다른 쪽이 읽으면 꺼내 간다. 보내는 쪽에서 커널로, 커널에서 받는 쪽으로 두 번 복사한다. 명령 프롬프트의 |가 이것이다.
    • 소켓은 네트워크로 주고받는 방법이다. 같은 PC 안이면 127.0.0.1로 보내는데, 받는 주소만 바꾸면 다른 PC와도 똑같이 주고받는다(41번(전송 계층 (TCP·UDP))).
    • 공유 메모리는 같은 실제 메모리를 두 프로세스의 주소 공간에 이어 둔다(37번(가상 메모리)). 한쪽이 쓰면 다른 쪽이 바로 읽어서 커널을 거치는 복사가 없다. 대신 "다 썼다"는 신호는 이벤트 같은 것으로 따로 보내야 한다.

    2. 파이프와 TCP는 경계 없는 바이트의 흐름이다¶

    직접 해 보기바이트의 흐름과 메시지보낼 말을 골라 차례로 쓰고 읽는 버퍼 크기를 바꿔 가며, 바이트 모드 파이프(TCP도 같다)와 메시지 모드 파이프가 어떻게 다르게 읽히는지 본다
    새 창에서 크게 열기
    • 이름 없는 파이프와 TCP 소켓에 "hello"와 "world"를 따로 써도, 받는 쪽은 "helloworld" 10바이트를 한 번에 받을 수 있다(문제 1). 반대로 한 번에 쓴 것이 여러 번에 나눠 오기도 한다. 이런 길을 바이트 스트림이라 한다.
    • 그래서 받는 쪽이 "어디까지가 한 메시지인지" 알 수 있게 줄바꿈을 붙이거나, 길이를 먼저 보낸다(실습 2). HTTP도 헤더 끝을 빈 줄로 표시하고 본문의 길이를 적어 보낸다(43번(HTTP)).
    • Windows의 이름 있는 파이프는 메시지 모드를 고를 수 있다. 쓴 단위를 하나의 메시지로 지켜 주고, 버퍼가 작으면 ERROR_MORE_DATA로 알린다(문제 2).

    3. 빠르기는 복사보다 준비와 신호가 정하기도 한다¶

    • 작은 공유 메모리(1MiB)를 되풀이해 쓰는 방법이 가장 빨랐다(36~37ms). 커널을 거치는 복사가 없고, 같은 1MiB를 다시 쓰니 캐시에도 남는다(38번(참조 지역성과 캐시 적중률)). 파이프는 45~49ms, TCP 소켓은 네트워크 처리를 거쳐 68~132ms였다.
    • 그런데 256MiB 공유 메모리를 새로 받아 한 번에 쓰면 151~158ms로 가장 느렸다. 새 메모리는 4KiB 페이지마다 처음 쓸 때 운영체제가 실제 메모리를 마련하는 페이지 폴트가 난다(37번(가상 메모리)). 쓰는 쪽에서 65,664번, 읽는 쪽에서 다시 65,665번이었다. 256MiB ÷ 4KiB = 65,536번에, 페이지 표를 담을 페이지가 2MiB마다 하나씩 더해진 수다(37번(가상 메모리)).
    • "복사가 없으니 공유 메모리가 늘 빠르다"는 말은 반만 맞다. 복사, 페이지 폴트, 신호 주고받기를 함께 따져야 하고, 결국 재 봐야 안다.

    예측해 보기¶

    문제 1. 이름 없는 파이프에 "hello"와 "world"를 따로 쓰고, 64바이트 버퍼로 한 번 읽는다. 무엇이 출력될까?

    #include <stdio.h>
#include <windows.h>

int main(void) {
    char buf[64];
    DWORD n, w;
    HANDLE rd, wr;
    CreatePipe(&rd, &wr, NULL, 0);
    WriteFile(wr, "hello", 5, &w, NULL);
    WriteFile(wr, "world", 5, &w, NULL);
    ReadFile(rd, buf, sizeof buf, &n, NULL);
    printf("%lu %.*s\n", n, (int)n, buf);
    return 0;
}
    정답과 해설

    10 helloworld. 파이프는 바이트의 흐름이라 두 번 쓴 것이 이어 붙어 한 번에 나온다. 몇 번에 나눠 썼는지는 받는 쪽이 알 수 없다. 127.0.0.1의 TCP 소켓으로 같은 일을 해도 이 PC에서 10 helloworld가 나왔다.

    문제 2. 이번에는 메시지 모드의 이름 있는 파이프에 똑같이 쓰고 64바이트로 두 번 읽는다. 무엇이 출력될까?

    #include <stdio.h>
#include <windows.h>

int main(void) {
    char buf[64];
    DWORD n, w;
    HANDLE srv = CreateNamedPipeA("\\\\.\\pipe\\cs31", PIPE_ACCESS_INBOUND, PIPE_TYPE_MESSAGE | PIPE_READMODE_MESSAGE,
                                  1, 4096, 4096, 0, NULL);
    HANDLE cli = CreateFileA("\\\\.\\pipe\\cs31", GENERIC_WRITE, 0, NULL, OPEN_EXISTING, 0, NULL);
    WriteFile(cli, "hello", 5, &w, NULL);
    WriteFile(cli, "world", 5, &w, NULL);
    for (int i = 0; i < 2; i++) {
        ReadFile(srv, buf, sizeof buf, &n, NULL);
        printf("%lu %.*s\n", n, (int)n, buf);
    }
    CloseHandle(cli);
    CloseHandle(srv);
    return 0;
}
    정답과 해설 
    5 hello
5 world

    메시지 모드는 쓴 단위를 하나의 메시지로 지킨다. 버퍼를 3바이트로 줄이면 hel과 함께 ERROR_MORE_DATA를 받고, 다시 읽으면 같은 메시지의 나머지 lo가 온다. 위젯의 메시지 모드에서 버퍼 3으로 확인할 수 있다.

    문제 3. 256MiB를 다른 프로세스에 보낼 때, 256MiB 공유 메모리를 새로 받아 한 번에 쓰는 방법과 파이프 중 어느 쪽이 빠를까?

    정답과 해설

    파이프가 빨랐다. 이 PC에서 파이프는 45~49ms, 새 공유 메모리는 151~158ms였다. 공유 메모리는 복사가 없지만 처음 쓰는 페이지마다, 그리고 다른 프로세스가 처음 읽는 페이지마다 페이지 폴트가 났다. 같은 1MiB 공유 메모리를 되풀이해 쓰면 페이지 폴트가 처음에 양쪽에서 256번(1MiB ÷ 4KiB)씩뿐이라 36~37ms로 가장 빨랐다.

    직접 해보기¶

    실습: 파이프로 주고받기

    1. C 라이브러리의 _popen으로 cmd /c echo hello를 실행하고, 그 출력을 파이프로 읽어 찍는다. 명령 프롬프트의 |가 하는 일이다.
    2. 이름 없는 파이프로 "hello"와 "world"를 보내되, 받는 쪽이 두 메시지를 따로 받게 한다. 길이(4바이트)를 먼저 보내고 내용을 보낸다.
    정답

    예시. 길이를 먼저 읽고 그만큼만 읽으면 경계가 지켜진다. ReadFile은 요청한 것보다 적게 돌려줄 수 있어서, 다 받을 때까지 되풀이해 읽는 read_all을 둔다.

    #include <stdio.h>
#include <string.h>
#include <windows.h>

/* 길이(4바이트)를 먼저 보내고 내용을 보낸다 */
static void send_msg(HANDLE h, const char *s) {
    DWORD len = (DWORD)strlen(s), w;
    WriteFile(h, &len, sizeof len, &w, NULL);
    WriteFile(h, s, len, &w, NULL);
}

/* n바이트를 다 받을 때까지 읽는다 (한 번에 다 오지 않을 수 있다) */
static int read_all(HANDLE h, void *buf, DWORD n) {
    DWORD got = 0, r;
    while (got < n) {
        if (!ReadFile(h, (char *)buf + got, n - got, &r, NULL) || r == 0)
            return 0;
        got += r;
    }
    return 1;
}

static int recv_msg(HANDLE h, char *buf, DWORD size) {
    DWORD len;
    if (!read_all(h, &len, sizeof len) || len >= size || !read_all(h, buf, len))
        return 0;
    buf[len] = '\0';
    return 1;
}

int main(void) {
    char line[64];
    FILE *p = _popen("cmd /c echo hello", "r");      /* 1. 자식 프로세스의 출력을 파이프로 읽는다 */
    fgets(line, sizeof line, p);
    _pclose(p);
    printf("%s", line);                              /* hello */

    HANDLE rd, wr;                                   /* 2. 길이를 붙여 보내고 받기 */
    char buf[64];
    CreatePipe(&rd, &wr, NULL, 0);
    send_msg(wr, "hello");
    send_msg(wr, "world");
    while (recv_msg(rd, buf, sizeof buf)) {
        printf("%s\n", buf);
        if (strcmp(buf, "world") == 0)
            break;
    }
    return 0;
}

    AI와 함께 확인하기¶

    AI 활용 과제: TCP 채팅 프로그램의 메시지 경계

    1. AI에게 "C(Winsock)로 클라이언트가 보낸 메시지를 한 줄씩 찍는 TCP 서버와 클라이언트"를 짜 달라고 한다.
    2. 클라이언트가 "hello"와 "world"를 쉬지 않고 연달아 보내게 바꾸고, 서버가 무엇을 찍을지 먼저 적는다.
    3. 실행해 대조하고, 틀렸으면 문제 1의 결과를 보여 주고 고치게 한다.
    확인할 점
    • recv 한 번을 메시지 하나로 여기는 코드가 많다. 이 PC에서 127.0.0.1로 연달아 보내자 recv 한 번에 "helloworld" 10바이트가 왔다. 서버가 두 줄이 아니라 한 줄을 찍으면 이 문제다.
    • 고친 코드는 줄바꿈을 붙여 보내고 받는 쪽이 \n까지 모으거나, 실습 2처럼 길이를 먼저 보낸다.
    • send도 한 번에 다 보내지 못하고 일부만 보냈다고 돌려줄 수 있다. 돌려받은 값을 보고 남은 것을 다시 보내는지 본다.

    더 알아보기¶

    그 밖의 방법

    운영체제마다 IPC 방법이 더 있다. Windows는 창끼리 메시지를 보내는 WM_COPYDATA, 여러 프로그램이 함께 쓰는 클립보드, 원격 프로시저 호출(RPC)을 준다. 리눅스는 시그널, 메시지 큐, 같은 PC 안에서만 쓰는 유닉스 도메인 소켓이 흔하다. 길은 달라도 "커널을 거쳐 복사하느냐, 메모리를 함께 보느냐"로 나누면 이 항목의 세 가지 중 하나와 닮았다.

    이 항목의 측정 프로그램

    3절과 그림의 값은 이 PC(Core i9-14900KF, DDR5 64GB, Windows 11)에서 아래 프로그램을 cl /O2로 빌드해 5번 실행한 범위다. 부모가 자기 실행 파일을 자식으로 실행하고, 자식이 256MiB를 64KiB씩 보내면 부모가 받은 바이트를 모두 더한다. 합계가 다섯 번 모두 1,879,048,192(256MiB × 7)로 맞았다. 페이지 폴트 횟수는 따로 GetProcessMemoryInfo의 PageFaultCount로 셌다. "자식만 만들기"(4.5~5.1ms)가 30번(프로그램, 프로세스, 스레드)의 3.8~3.9ms보다 긴 것은, 이 실행 파일이 소켓 라이브러리(ws2_32.dll)까지 올리고 100번의 평균이 아니라 한 번씩 쟀기 때문으로 보인다.

    /* 31번 측정: 자식 프로세스가 256MiB를 부모에게 보내고, 부모가 받은 바이트를 모두 더할 때까지 걸린 시간
   usage: ipcbench.exe  (자식으로 불릴 때는 none | pipe <핸들> | tcp <포트> | shm | ring) */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <winsock2.h>
#include <windows.h>
#pragma comment(lib, "ws2_32.lib")

#define TOTAL (256u << 20)
#define CHUNK (64u << 10)
#define RING (1u << 20)

static char buf[CHUNK];

static double now_ms(void) {
    static LARGE_INTEGER f; LARGE_INTEGER c;
    if (!f.QuadPart) QueryPerformanceFrequency(&f);
    QueryPerformanceCounter(&c);
    return (double)c.QuadPart * 1000.0 / (double)f.QuadPart;
}

static unsigned long long sum_all(const char *p, size_t n) {   /* 받은 바이트를 모두 읽는다 */
    unsigned long long s = 0;
    for (size_t i = 0; i < n; i++)
        s += (unsigned char)p[i];
    return s;
}

static int child(char **argv) {
    memset(buf, 7, sizeof buf);
    if (strcmp(argv[1], "pipe") == 0) {
        HANDLE wr = (HANDLE)(INT_PTR)_strtoi64(argv[2], NULL, 10);
        for (unsigned done = 0; done < TOTAL; done += CHUNK) {
            DWORD w;
            WriteFile(wr, buf, CHUNK, &w, NULL);
        }
        CloseHandle(wr);
    } else if (strcmp(argv[1], "tcp") == 0) {
        WSADATA wsa;
        WSAStartup(MAKEWORD(2, 2), &wsa);
        SOCKET c = socket(AF_INET, SOCK_STREAM, 0);
        struct sockaddr_in a = { 0 };
        a.sin_family = AF_INET;
        a.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
        a.sin_port = htons((u_short)atoi(argv[2]));
        connect(c, (struct sockaddr *)&a, sizeof a);
        for (unsigned done = 0; done < TOTAL; done += CHUNK)
            send(c, buf, CHUNK, 0);
        closesocket(c);
        WSACleanup();
    } else if (strcmp(argv[1], "shm") == 0) {       /* 256MiB 영역에 한 번에 쓴다 */
        HANDLE m = OpenFileMappingA(FILE_MAP_WRITE, FALSE, "Local\\cs31shm");
        char *p = MapViewOfFile(m, FILE_MAP_WRITE, 0, 0, TOTAL);
        for (unsigned done = 0; done < TOTAL; done += CHUNK)
            memcpy(p + done, buf, CHUNK);
        SetEvent(OpenEventA(EVENT_MODIFY_STATE, FALSE, "Local\\cs31full"));
    } else if (strcmp(argv[1], "ring") == 0) {      /* 1MiB 영역을 256번 되풀이해 쓴다 */
        HANDLE m = OpenFileMappingA(FILE_MAP_WRITE, FALSE, "Local\\cs31ring");
        char *p = MapViewOfFile(m, FILE_MAP_WRITE, 0, 0, RING);
        HANDLE full = OpenEventA(EVENT_MODIFY_STATE, FALSE, "Local\\cs31full");
        HANDLE empty = OpenEventA(SYNCHRONIZE, FALSE, "Local\\cs31empty");
        for (unsigned done = 0; done < TOTAL; done += RING) {
            WaitForSingleObject(empty, INFINITE);    /* 부모가 다 읽을 때까지 기다린다 */
            for (unsigned k = 0; k < RING; k += CHUNK)
                memcpy(p + k, buf, CHUNK);
            SetEvent(full);                          /* 채웠다고 알린다 */
        }
    }
    return 0;
}

static void spawn(const char *args, BOOL inherit, PROCESS_INFORMATION *pi) {
    char exe[MAX_PATH], cmd[MAX_PATH + 64];
    GetModuleFileNameA(NULL, exe, MAX_PATH);
    sprintf_s(cmd, sizeof cmd, "\"%s\" %s", exe, args);
    STARTUPINFOA si = { sizeof si };
    CreateProcessA(exe, cmd, NULL, NULL, inherit, 0, NULL, NULL, &si, pi);
}

static void finish(const char *name, double t0, unsigned long long s, PROCESS_INFORMATION *pi) {
    WaitForSingleObject(pi->hProcess, INFINITE);
    printf("%-5s %7.1f ms  %llu\n", name, now_ms() - t0, s);
    CloseHandle(pi->hProcess);
    CloseHandle(pi->hThread);
}

int main(int argc, char **argv) {
    if (argc > 1)
        return child(argv);
    char args[64];
    PROCESS_INFORMATION pi;
    unsigned long long s = 0;

    double t0 = now_ms();                            /* 0. 자식을 만들고 끝날 때까지만 */
    spawn("none", FALSE, &pi);
    finish("none", t0, 0, &pi);

    SECURITY_ATTRIBUTES sa = { sizeof sa, NULL, TRUE };   /* 1. 이름 없는 파이프 */
    HANDLE rd, wr;
    CreatePipe(&rd, &wr, &sa, CHUNK);
    SetHandleInformation(rd, HANDLE_FLAG_INHERIT, 0);
    t0 = now_ms();
    sprintf_s(args, sizeof args, "pipe %lld", (long long)(INT_PTR)wr);
    spawn(args, TRUE, &pi);
    CloseHandle(wr);
    for (DWORD n; ReadFile(rd, buf, CHUNK, &n, NULL) && n > 0;)
        s += sum_all(buf, n);
    finish("pipe", t0, s, &pi);
    CloseHandle(rd);

    WSADATA wsa;                                     /* 2. TCP 소켓 */
    WSAStartup(MAKEWORD(2, 2), &wsa);
    SOCKET ls = socket(AF_INET, SOCK_STREAM, 0);
    struct sockaddr_in a = { 0 };
    a.sin_family = AF_INET;
    a.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
    bind(ls, (struct sockaddr *)&a, sizeof a);
    int len = sizeof a;
    getsockname(ls, (struct sockaddr *)&a, &len);
    listen(ls, 1);
    t0 = now_ms();
    sprintf_s(args, sizeof args, "tcp %d", ntohs(a.sin_port));
    spawn(args, FALSE, &pi);
    SOCKET c = accept(ls, NULL, NULL);
    s = 0;
    for (int n; (n = recv(c, buf, CHUNK, 0)) > 0;)
        s += sum_all(buf, (size_t)n);
    finish("tcp", t0, s, &pi);
    closesocket(c); closesocket(ls); WSACleanup();

    HANDLE m = CreateFileMappingA(INVALID_HANDLE_VALUE, NULL, PAGE_READWRITE, 0, TOTAL, "Local\\cs31shm");   /* 3. 공유 메모리 256MiB */
    HANDLE full = CreateEventA(NULL, FALSE, FALSE, "Local\\cs31full");
    char *p = MapViewOfFile(m, FILE_MAP_READ, 0, 0, TOTAL);
    t0 = now_ms();
    spawn("shm", FALSE, &pi);
    WaitForSingleObject(full, INFINITE);
    s = sum_all(p, TOTAL);
    finish("shm", t0, s, &pi);
    UnmapViewOfFile(p); CloseHandle(m);

    m = CreateFileMappingA(INVALID_HANDLE_VALUE, NULL, PAGE_READWRITE, 0, RING, "Local\\cs31ring");   /* 4. 공유 메모리 1MiB 되풀이 */
    HANDLE empty = CreateEventA(NULL, FALSE, TRUE, "Local\\cs31empty");
    p = MapViewOfFile(m, FILE_MAP_READ, 0, 0, RING);
    t0 = now_ms();
    spawn("ring", FALSE, &pi);
    s = 0;
    for (unsigned done = 0; done < TOTAL; done += RING) {
        WaitForSingleObject(full, INFINITE);         /* 자식이 채울 때까지 */
        s += sum_all(p, RING);
        SetEvent(empty);                             /* 다 읽었다고 알린다 */
    }
    finish("ring", t0, s, &pi);
    UnmapViewOfFile(p); CloseHandle(m); CloseHandle(full); CloseHandle(empty);
    return 0;
}

    정리¶

    • 프로세스끼리는 운영체제가 만든 길로 주고받는다. 파이프와 소켓은 커널을 거쳐 두 번 복사하고, 공유 메모리는 같은 메모리를 함께 본다.
    • 파이프와 TCP는 경계 없는 바이트의 흐름이다. 메시지의 끝은 줄바꿈이나 길이로 직접 표시한다.
    • 공유 메모리는 복사가 없지만 처음 쓰는 페이지의 페이지 폴트와 신호 주고받기가 든다. 빠르기는 재 봐야 안다.
