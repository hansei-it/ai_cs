    30. 실행의 주체: 프로그램, 프로세스, 스레드의 정의와 메모리 구조¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    디스크에 있는 실행 파일을 두 번 실행하면 같은 코드가 두 번 돈다. 둘은 서로의 변수를 볼 수 있을까? 한 프로그램 안에서 일을 나눠 맡은 스레드끼리는 어떨까? 이 항목은 프로그램, 프로세스, 스레드가 무엇이고, 메모리 가운데 무엇을 함께 쓰고 무엇을 따로 가지는지를 이 PC에서 실행해 확인한다.

    이 항목에서 배우는 것¶

    • 프로그램, 프로세스, 스레드를 구분해 설명할 수 있다.
    • 프로세스끼리와 스레드끼리 메모리의 어느 부분을 함께 쓰는지 예측할 수 있다.
    • 프로세스를 만드는 일이 스레드를 만드는 일보다 훨씬 무거운 까닭을 설명할 수 있다.

    1. 프로세스는 주소 공간을, 스레드는 스택을 따로 가진다¶

    • 프로그램은 디스크에 있는 실행 파일이다. 실행하면 운영체제가 그 프로그램만의 주소 공간을 만들고 코드와 데이터를 올린다(8번(프로세스의 메모리 레이아웃)). 이렇게 실행 중인 프로그램이 프로세스다. 같은 파일을 두 번 실행하면 프로세스가 둘이 된다.
    • 스레드는 프로세스 안에서 코드를 따라가는 실행 흐름이다. 프로세스는 스레드 하나로 시작하고, 필요하면 더 만든다. CPU가 실제로 실행하는 단위는 스레드다(32번(CPU 스케줄링과 컨텍스트 스위칭)).
    • 같은 프로세스의 스레드는 코드, 전역 데이터, 힙을 함께 쓰고, 스택과 레지스터만 따로 가진다. 프로세스끼리는 기본으로 서로의 메모리를 볼 수 없고, 함께 쓰려면 운영체제에 따로 부탁해야 한다(31번(프로세스 간 통신(IPC))).

    2. 같은 주소라도 프로세스가 다르면 다른 메모리다¶

    일꾼 A와 B를 스레드 둘, 프로세스 둘로 바꿔 가며 전역 변수와 지역 변수를 늘려 본다.

    직접 해 보기스레드 둘, 프로세스 둘스레드 둘과 프로세스 둘을 바꿔 가며 각자 전역 변수 g와 지역 변수 x를 늘려 보고, 무엇을 함께 쓰고 무엇이 따로인지 본다
    새 창에서 크게 열기
    • 스레드 둘은 전역 변수를 함께 쓴다. 한 스레드가 바꾸면 다른 스레드에도 바로 보인다. 편하지만, 둘이 동시에 바꾸면 값이 꼬인다(34번(스레드 동기화)).
    • 프로세스 둘은 같은 프로그램이라 전역 변수의 주소까지 같았지만(문제 1), 값은 따로였다. 프로그램이 쓰는 주소는 프로세스마다 따로 있는 가상 주소이고, 운영체제가 프로세스마다 다른 실제 메모리에 잇는다(37번(가상 메모리)).
    • 지역 변수는 스레드마다 자기 스택에 있다. 이 PC에서 두 스레드의 스택은 1MiB 떨어져 있었다. 그래도 같은 주소 공간이라, 주소를 알면 다른 스레드의 지역 변수를 바꿀 수 있다(문제 2).

    3. 프로세스를 만드는 일이 훨씬 무겁다¶

    • 프로세스를 만들려면 주소 공간과 페이지 표, 열린 파일을 적어 둘 핸들 표를 새로 만들고, 실행 파일과 DLL을 올린 뒤 첫 스레드를 만든다. 스레드는 스택과 레지스터를 저장할 자리, 스레드 정보(TEB) 정도면 된다.
    • 이 PC에서 아무 일도 하지 않는 프로세스를 만들고 끝날 때까지 3.8~3.9ms, 스레드는 52~59µs로 약 70배 차이가 났다.
    • 그래서 한 프로그램 안에서 일을 나눌 때는 보통 스레드를 쓴다. 대신 한 스레드가 메모리를 망가뜨리면 프로세스 전체가 멈춘다. 브라우저처럼 탭마다 프로세스를 따로 두는 프로그램은 이 안전을 위해 비용을 치른다.

    예측해 보기¶

    문제 1. 부모 프로세스가 전역 변수 g를 42로 바꾼 뒤 같은 실행 파일로 자식 프로세스를 만든다. 자식에게는 부모의 &g 값을 넘겨, 자기 &g와 같은지 찍게 한다. 자식은 g를 7로 바꾸고 끝난다. 무엇이 출력될까?

    #include <stdio.h>
#include <stdlib.h>
#include <windows.h>

int g = 0;   /* 전역 변수 */

int main(int argc, char **argv) {
    if (argc > 1) {                                   /* 자식 프로세스 */
        void *parent_addr = (void *)_strtoui64(argv[1], NULL, 16);
        printf("child:  g = %d, same address = %d\n", g, (void *)&g == parent_addr);
        g = 7;
        return 0;
    }
    g = 42;                                           /* 부모 프로세스 */
    char exe[MAX_PATH], cmd[MAX_PATH + 40];
    GetModuleFileNameA(NULL, exe, MAX_PATH);
    sprintf_s(cmd, sizeof cmd, "\"%s\" %p", exe, (void *)&g);
    STARTUPINFOA si = { sizeof si };
    PROCESS_INFORMATION pi;
    fflush(stdout);
    CreateProcessA(exe, cmd, NULL, NULL, FALSE, 0, NULL, NULL, &si, &pi);
    WaitForSingleObject(pi.hProcess, INFINITE);
    CloseHandle(pi.hProcess);
    CloseHandle(pi.hThread);
    printf("parent: g = %d\n", g);
    return 0;
}
    정답과 해설 
    child:  g = 0, same address = 1
parent: g = 42

    자식은 부모가 바꾼 42가 아니라 처음 값 0을 본다. 실행 파일을 새로 올렸을 뿐 부모의 메모리를 물려받지 않기 때문이다. 주소는 같았다(same address = 1). Windows는 같은 실행 파일을 재부팅할 때까지 같은 주소에 올린다(8번(프로세스의 메모리 레이아웃)). 같은 주소라도 프로세스마다 다른 메모리라서, 자식이 g를 7로 바꿔도 부모의 g는 42 그대로다.

    문제 2. 스레드 둘이 각각 전역 변수 g에 10을 더하고, 자기 지역 변수의 주소를 적어 둔다. 1번 스레드는 main의 지역 변수 mine을 포인터로 바꾼다. 두 스레드가 살아 있는 동안 세 줄을 찍는다. 무엇이 출력될까?

    #include <stdio.h>
#include <windows.h>

int g = 0;             /* 전역 변수: 모든 스레드가 함께 쓴다 */
int *main_local;       /* main의 지역 변수를 가리킨다 */
char *where[2];        /* 두 스레드의 지역 변수 주소 */
HANDLE go;

DWORD WINAPI worker(LPVOID arg) {
    int id = (int)(INT_PTR)arg;
    int local = id;                    /* 지역 변수: 스레드마다 자기 스택에 */
    where[id] = (char *)&local;
    if (id == 1)
        *main_local = 99;              /* 다른 스레드(main)의 스택을 바꾼다 */
    InterlockedAdd((LONG *)&g, 10);    /* 두 스레드가 동시에 더해도 안전하게 (34번). main은 g가 20이 되면 찍는다 */
    WaitForSingleObject(go, INFINITE); /* 두 스레드가 함께 살아 있게 기다린다 */
    return 0;
}

int main(void) {
    int mine = 1;
    main_local = &mine;
    go = CreateEventA(NULL, TRUE, FALSE, NULL);
    HANDLE t[2];
    for (int i = 0; i < 2; i++)
        t[i] = CreateThread(NULL, 0, worker, (LPVOID)(INT_PTR)i, 0, NULL);
    while (where[0] == NULL || where[1] == NULL || g < 20)
        Sleep(1);
    long long gap = where[0] - where[1];
    printf("%d\n", g);
    printf("%d\n", mine);
    printf("%lld MiB\n", ((gap < 0 ? -gap : gap) + 512 * 1024) / (1024 * 1024));   /* 두 지역 변수 사이 */
    SetEvent(go);
    WaitForMultipleObjects(2, t, TRUE, INFINITE);
    return 0;
}
    정답과 해설 
    20
99
1 MiB

    전역 변수 g는 하나를 함께 쓰므로 10 + 10 = 20이다. main의 mine은 1번 스레드가 포인터로 99를 써 넣었다. 스택은 스레드마다 따로지만 같은 주소 공간에 있어서 막혀 있지 않다. 두 스레드의 지역 변수는 이 PC에서 1,023~1,025KiB 떨어져 있었다. 스레드마다 1MiB씩 스택을 따로 받기 때문이다(9번(함수 호출과 메모리)).

    문제 3. 아무 일도 하지 않는 스레드를 만드는 일은, 아무 일도 하지 않는 프로세스를 만드는 일보다 몇 배쯤 빠를까?

    정답과 해설

    약 70배. 이 PC에서 만들고 끝날 때까지 프로세스는 3.8~3.9ms, 스레드는 52~59µs였다(아래 "더 알아보기"의 측정 프로그램). 프로세스는 주소 공간을 새로 만들고 실행 파일과 DLL을 올려야 한다.

    직접 해보기¶

    실습: 자식이 바꾼 값을 부모가 받기

    1. 문제 1의 프로그램을 실행해 결과를 확인한다.
    2. 자식이 바꾼 g(7)를 부모가 알 수 있게 고친다. 자식은 g를 종료 코드로 돌려주고(return g;), 부모는 GetExitCodeProcess로 읽는다. 부모는 자기 g와 받은 값을 한 줄에 찍는다.
    3. 문제 2의 프로그램에서 스레드를 4개로 늘리고, g가 얼마가 되는지 예측한 뒤 실행한다.
    정답
    1. 문제 1의 정답과 같다.

    2. 예시. 종료 코드는 운영체제가 자식의 마지막 상태로 적어 두는 숫자다. 프로세스끼리 값을 주고받는 가장 단순한 길이고, 더 많은 데이터는 31번(프로세스 간 통신(IPC))의 방법으로 보낸다.

      #include <stdio.h>
#include <windows.h>

int g = 0;

int main(int argc, char **argv) {
    (void)argv;
    if (argc > 1) {           /* 자식: g를 바꾸고 그 값을 종료 코드로 돌려준다 */
        g = 7;
        return g;
    }
    g = 42;
    char exe[MAX_PATH], cmd[MAX_PATH + 16];
    GetModuleFileNameA(NULL, exe, MAX_PATH);
    sprintf_s(cmd, sizeof cmd, "\"%s\" child", exe);
    STARTUPINFOA si = { sizeof si };
    PROCESS_INFORMATION pi;
    CreateProcessA(exe, cmd, NULL, NULL, FALSE, 0, NULL, NULL, &si, &pi);
    WaitForSingleObject(pi.hProcess, INFINITE);
    DWORD code;
    GetExitCodeProcess(pi.hProcess, &code);
    CloseHandle(pi.hProcess);
    CloseHandle(pi.hThread);
    printf("%d %lu\n", g, code);   /* 42 7 */
    return 0;
}

    3. 4개면 g는 40이다. for와 where, t, WaitForMultipleObjects의 개수를 4로 늘리고, 기다리는 조건을 g < 40으로 바꾼다. 스택 간격은 스레드마다 1MiB쯤이다.

    AI와 함께 확인하기¶

    AI 활용 과제: 스레드가 함께 쓰는 것

    1. AI에게 "같은 프로세스의 스레드끼리 공유하는 것과 공유하지 않는 것"을 표로 정리해 달라고 한다.
    2. 표의 칸마다 이 항목의 프로그램(문제 1, 2)으로 확인할 수 있는지 표시한다.
    3. 실행 결과와 다른 칸이 있으면 결과를 보여 주고 고치게 한다.
    확인할 점
    • "코드, 전역 데이터, 힙, 열린 파일은 공유하고 스택과 레지스터는 따로"는 맞다.
    • "다른 스레드의 스택(지역 변수)에는 접근할 수 없다"고 쓰면 틀렸다. 따로 받을 뿐 막혀 있지 않아서, 문제 2처럼 주소만 알면 읽고 쓸 수 있다. 다만 지역 변수의 주소를 다른 스레드에 넘기면, 그 함수가 끝난 뒤에는 이미 다른 값이 들어 있을 자리를 가리키게 된다.
    • "자식 프로세스는 부모의 메모리를 복사해 받는다"는 리눅스의 fork에 맞는 말이다. Windows의 CreateProcess는 실행 파일을 새로 올리므로 자식은 처음 값(문제 1의 0)으로 시작한다. AI가 어느 운영체제를 말하는지 본다.

    더 알아보기¶

    리눅스의 fork

    리눅스와 macOS의 fork()는 지금 프로세스를 그대로 복사해 자식을 만든다. 자식은 부모의 변수 값을 그대로 가지고 시작하고, 그 뒤로는 따로 바뀐다. 실제로 메모리를 다 복사하지는 않고, 둘 중 하나가 쓰기 전까지 같은 실제 메모리를 함께 보다가 쓰는 순간 그 페이지만 복사한다(쓸 때 복사, copy-on-write, 37번(가상 메모리)). Windows의 CreateProcess에는 이런 복사가 없고, 새 프로그램을 처음부터 올린다.

    이 항목의 측정 프로그램

    3절의 시간은 이 PC(Core i9-14900KF, DDR5 64GB, Windows 11)에서 아래 프로그램을 cl /O2로 빌드해 5번 실행한 범위다. 프로세스는 100번, 스레드는 5,000번 만들고 끝날 때까지 기다려 평균을 냈다. 프로세스를 만드는 시간에는 보안 프로그램이 새 프로세스를 검사하는 시간도 들어 있을 수 있다.

    /* 30번 측정: 아무 일도 하지 않는 프로세스와 스레드를 만들고 끝날 때까지 기다리는 데 걸린 시간 */
#include <stdio.h>
#include <string.h>
#include <windows.h>

static double now_us(void) {
    static LARGE_INTEGER f; LARGE_INTEGER c;
    if (!f.QuadPart) QueryPerformanceFrequency(&f);
    QueryPerformanceCounter(&c);
    return (double)c.QuadPart * 1e6 / (double)f.QuadPart;
}

static DWORD WINAPI nothing(LPVOID arg) { (void)arg; return 0; }

int main(int argc, char **argv) {
    if (argc > 1 && strcmp(argv[1], "child") == 0)
        return 0;                              /* 자식 프로세스는 바로 끝난다 */
    char exe[MAX_PATH], cmd[MAX_PATH + 16];
    GetModuleFileNameA(NULL, exe, MAX_PATH);
    sprintf_s(cmd, sizeof cmd, "\"%s\" child", exe);

    int np = 100;
    double t0 = now_us();
    for (int i = 0; i < np; i++) {
        STARTUPINFOA si = { sizeof si };
        PROCESS_INFORMATION pi;
        CreateProcessA(exe, cmd, NULL, NULL, FALSE, 0, NULL, NULL, &si, &pi);
        WaitForSingleObject(pi.hProcess, INFINITE);
        CloseHandle(pi.hProcess);
        CloseHandle(pi.hThread);
    }
    double t1 = now_us();

    int nt = 5000;
    for (int i = 0; i < nt; i++) {
        HANDLE h = CreateThread(NULL, 0, nothing, NULL, 0, NULL);
        WaitForSingleObject(h, INFINITE);
        CloseHandle(h);
    }
    double t2 = now_us();
    printf("process %.1f us\n", (t1 - t0) / np);
    printf("thread  %.1f us\n", (t2 - t1) / nt);
    return 0;
}

    정리¶

    • 프로그램은 파일, 프로세스는 주소 공간을 가진 실행 중인 프로그램, 스레드는 프로세스 안의 실행 흐름이다.
    • 스레드끼리는 코드, 전역 데이터, 힙을 함께 쓰고 스택과 레지스터만 따로 가진다. 프로세스끼리는 같은 주소라도 다른 메모리다.
    • 프로세스를 만드는 일은 스레드보다 훨씬 무겁다(이 PC에서 약 70배). 대신 프로세스는 서로를 망가뜨리지 못한다.
