    38. 참조 지역성(시간/공간)과 캐시 적중률¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    5번(메모리 계층 구조)에서 캐시는 64바이트 줄 단위로 가져오고, 2차원 배열을 행 순서로 읽으면 열 순서보다 열 배 넘게 빠르다는 것을 봤다. 작은 캐시가 통하는 것은 프로그램이 메모리를 아무 데나 쓰지 않기 때문이다. 이 항목은 그 성질인 지역성을 두 가지로 나누어 보고, 순서와 자리만 바꿔도 적중률이 바뀌는 예를 이 PC에서 잰다. 여러 코어가 각자 캐시를 가질 때 생기는 일도 본다.

    이 항목에서 배우는 것¶

    • 시간 지역성과 공간 지역성을 구분하고, 코드에서 각각을 찾을 수 있다.
    • 보폭과 반복 순서가 캐시 적중률과 실행 시간을 어떻게 바꾸는지 예측할 수 있다.
    • 거짓 공유가 왜 생기는지 코어마다 따로 있는 캐시로 설명할 수 있다.

    1. 지역성은 두 가지다¶

    • 시간 지역성은 방금 쓴 것을 곧 다시 쓰는 성질이다. 반복문의 기계어와 반복할 때마다 쓰는 sum, i가 그렇다. 캐시는 최근에 쓴 줄을 남겨 두어 이를 살린다.
    • 공간 지역성은 방금 쓴 것의 옆을 곧 쓰는 성질이다. 배열을 차례로 읽는 a[i]가 그렇다. 캐시는 64바이트 줄을 통째로 가져와 이를 살린다. int 16개가 한 줄이라 그림의 24칸에서 놓침은 두 번뿐이다(문제 1).
    • 다음 노드가 어디 있을지 모르는 연결 리스트는 공간 지역성이 약하다(20번(자료구조의 필요성)). 스레드가 바뀌면 다른 스레드의 데이터가 캐시를 채워, 돌아온 스레드는 캐시에 남겨 둔 줄을 잃고 시간 지역성의 덕을 못 본다(32번(CPU 스케줄링과 컨텍스트 스위칭)).

    2. 공간 지역성의 단위는 64바이트 줄이다¶

    • 256MiB int 배열에서 s칸마다 하나씩 3을 곱했다. 보폭을 4바이트에서 64바이트로 늘리면 곱셈 수는 16분의 1이 되는데, 시간은 25.4~29.2ms에서 12.6~13.6ms로 절반쯤밖에 줄지 않았다. 어느 보폭이든 64바이트 줄은 하나도 빠짐없이 가져와야 하기 때문이다.
    • 보폭이 줄보다 커져야 가져오는 줄이 줄어 시간이 크게 준다(256바이트에서 6.0~8.0ms). 줄 안의 옆 칸은 줄을 가져오는 것보다 훨씬 싸고, 비용은 가져오는 줄 수가 정한다.
    • 그래서 같은 계산도 안쪽 반복이 메모리를 차례로 지나가게 순서를 정하면 빨라진다. 행렬 곱은 반복 순서만 바꿔도 크게 달라진다(문제 3).

    3. 코어마다 캐시가 따로 있다¶

    직접 해 보기코어마다 따로 있는 캐시두 변수를 같은 줄이나 다른 줄에 두고 '한 걸음'을 눌러, 두 코어가 번갈아 쓰거나 읽을 때 줄이 코어 사이를 오가는 모습과 적중 횟수를 본다
    새 창에서 크게 열기
    • L1, L2 캐시는 코어마다 따로 있다(이 PC의 E-코어는 넷이 L2 하나를 함께 쓴다). L3는 모든 코어가 함께 쓴다. 어느 코어가 줄에 쓰려면 다른 코어에 있는 그 줄의 복사본을 먼저 지운다. 그래야 모든 코어가 같은 값을 본다.
    • 두 스레드가 서로 다른 변수에 쓰더라도 두 변수가 한 줄에 있으면, 줄이 두 코어 사이를 오가며 서로 계속 놓친다. 이것이 거짓 공유다(문제 2).
    • 이 PC에서 두 스레드가 각자 자기 카운터를 InterlockedIncrement64로 1억 번 올렸다(34번(스레드 동기화)). 두 카운터가 한 줄에 있으면 1,092~1,510ms, 64바이트 띄우면 318~325ms였다. 결과는 같고 자리만 다르다.

    예측해 보기¶

    문제 1. 그림 1의 반복문에서 배열을 double(8바이트) 24칸으로 바꾸면, 배열에서 놓침은 몇 번일까? long long(8바이트) 64칸이면? 배열은 줄의 처음에서 시작한다고 한다.

    정답과 해설

    3번, 8번. 64바이트 줄 하나에 8바이트 칸이 8개 들어간다. 24칸은 줄 3개(a[0], a[8], a[16]에서 놓침), 64칸은 줄 8개다. 칸이 클수록 한 줄로 적중하는 횟수가 줄어든다. 놓침의 수는 칸의 수가 아니라 지나간 줄의 수다.

    문제 2. 위젯에서 "x와 y가 같은 줄"과 "쓰기"를 고르고 끝까지 진행하면, 12번 접근 가운데 적중은 몇 번일까? "읽기만"으로 바꾸면?

    정답과 해설

    0번, 10번. 쓰기에서는 코어가 쓸 때마다 다른 코어의 복사본을 지우므로, 다음 차례의 코어는 언제나 줄이 없다. 줄이 11번 오갔다. 읽기만 하면 두 코어가 복사본을 함께 가질 수 있어 처음 한 번씩만 놓친다. 거짓 공유는 같은 줄에 누군가 쓸 때 생긴다.

    문제 3. 1024 × 1024 행렬의 곱을 두 가지 순서로 구한다. 두 순서는 같은 곱셈을 같은 횟수만큼 하고 결과도 같다. Release로 실행하면 어느 쪽이 빠를까? 몇 배쯤?

    #include <stdio.h>
#include <windows.h>

#define N 1024
static double A[N][N], B[N][N], C[N][N];   /* 행렬 하나가 8MiB */

static double now_ms(void) {
    LARGE_INTEGER f, c;
    QueryPerformanceFrequency(&f);
    QueryPerformanceCounter(&c);
    return (double)c.QuadPart * 1000.0 / (double)f.QuadPart;
}

int main(void) {
    for (int i = 0; i < N; i++)
        for (int j = 0; j < N; j++) {
            A[i][j] = (i + j) % 7;
            B[i][j] = (i * j) % 5;
        }

    double t = now_ms();
    for (int i = 0; i < N; i++)              /* (가) 안쪽 반복이 j */
        for (int k = 0; k < N; k++)
            for (int j = 0; j < N; j++)
                C[i][j] += A[i][k] * B[k][j];
    printf("(가) %.0f ms, C[7][9] = %.0f\n", now_ms() - t, C[7][9]);

    for (int i = 0; i < N; i++)
        for (int j = 0; j < N; j++) C[i][j] = 0;
    t = now_ms();
    for (int j = 0; j < N; j++)              /* (나) 안쪽 반복이 i */
        for (int k = 0; k < N; k++)
            for (int i = 0; i < N; i++)
                C[i][j] += A[i][k] * B[k][j];
    printf("(나) %.0f ms, C[7][9] = %.0f\n", now_ms() - t, C[7][9]);
    return 0;
}
    정답과 해설

    (가)가 수십 배 빠르다. 이 PC에서 cl /O2로 6번 실행하니 (가)는 151~232ms, (나)는 4,534~7,585ms였다. 두 순서 모두 C[7][9]는 6136으로 같았다.

    안쪽 반복이 무엇을 지나가는지 보면 된다. (가)는 j가 늘며 C[i][j]와 B[k][j]를 옆으로 지나가, 줄 하나에서 double 8개를 쓴다. (나)는 i가 늘며 C[i][j]와 A[i][k]를 아래로 지나가, 한 번에 한 행(8KiB)씩 건너뛰므로 칸마다 다른 줄이다. 5번(메모리 계층 구조)의 열 순서 읽기와 같은 모양이다.

    직접 해보기¶

    실습: 내 PC에서 줄과 코어 재 보기

    1. "더 알아보기"의 측정 프로그램 1을 Release로 실행해 보폭마다 시간을 적는다. 곱셈 수가 반으로 줄 때 시간도 반으로 주는지 보폭마다 비교한다.
    2. 측정 프로그램 2를 share.exe 2 4처럼 논리 프로세서 번호 두 개를 주어 실행한다. share.exe 2 3처럼 이웃한 번호로도 실행해 비교한다.
    3. 위젯에서 네 가지 조합(같은 줄·다른 줄 × 쓰기·읽기)의 적중 수를 적고, 측정 프로그램 2의 결과와 연결해 설명한다.
    확인할 점
    • 이 PC에서 보폭 4바이트에서 64바이트까지 곱셈 수는 16분의 1이 됐지만 시간은 절반쯤(25.4~29.2ms에서 12.6~13.6ms)만 줄었다. 줄을 건너뛰기 시작한 128바이트와 256바이트에서는 10.0~11.0ms, 6.0~8.0ms로 줄었다. 곱셈 수보다 가져오는 줄 수를 따라간다.
    • 이 PC에서 share.exe 2 3은 같은 줄 722~753ms, 다른 줄 743~752ms로 차이가 없었다. 논리 프로세서 2와 3은 같은 물리 코어의 두 논리 프로세서(하이퍼스레딩)라서 L1 캐시를 함께 쓰기 때문이다. 이 PC는 두 번호씩(0과 1, 2와 3, …) 한 P-코어다(GetLogicalProcessorInformationEx로 확인). 거짓 공유는 줄이 서로 다른 캐시 사이를 오갈 때 생긴다.
    • 번호와 코어의 짝은 PC마다 다르고, 하이퍼스레딩이 없는 CPU도 있다. 내 PC에서는 작업 관리자의 성능 탭(코어 수와 논리 프로세서 수)이나 GetLogicalProcessorInformationEx로 먼저 확인한다. 논리 프로세서가 측정 프로그램이 묶는 번호(2, 4, 6, 8)보다 적으면 번호를 바꾼다.

    AI와 함께 확인하기¶

    AI 활용 과제: AI가 짠 병렬 코드에서 거짓 공유 찾기

    1. AI에게 "스레드 4개가 큰 int 배열을 넷으로 나눠 짝수의 개수를 세고, 마지막에 합치는 C 프로그램(Windows 스레드)"을 짜 달라고 한다.
    2. 각 스레드가 세는 카운터가 어디 있는지 찾는다. 한 배열의 칸(count[t])이면 그 칸들이 한 줄(64바이트)에 들어가는지 계산한다.
    3. AI에게 이 코드에 거짓 공유가 있는지, 고치면 얼마나 빨라지는지 묻는다. 그다음 최적화 없이 빌드할 때와 Release에서 재 보고 AI의 답을 판정한다.
    확인할 점
    • long long count[4]는 32바이트라 한 줄에 다 들어간다. 스레드마다 count[t]++를 하면 거짓 공유다.
    • 이 PC에서 "더 알아보기"의 측정 프로그램 3으로 재니, 최적화 없이 빌드하면 붙어 있는 칸이 150~181ms, 64바이트씩 띄운 칸이 71~78ms로 2배쯤 차이 났다. Release(/O2)에서는 47~63ms와 44~56ms로 차이가 작았다. 기계어를 보면 Release에서도 count[t]++는 반복마다 메모리에 더하는 명령으로 남아 있어, 컴파일러가 거짓 공유를 없앤 것은 아니다. 같은 코드도 빌드와 CPU에 따라 다르다. "언제나 몇 배 느려진다"는 답도, "요즘 CPU에서는 상관없다"는 답도 재 보기 전에는 믿을 수 없다.
    • 가장 좋은 고침은 스레드마다 지역 변수에 세고 끝에 한 번만 쓰는 것이다. Release에서 가장 빨랐다(27~38ms). 컴파일러가 지역 변수를 레지스터에 두고 세어, 반복마다 메모리에 쓰는 일 자체가 없어지기 때문이다. 여러 스레드가 함께 쓰는 줄도 저절로 없어진다.
    • 읽기만 하는 변수도 조심한다. 측정 프로그램 3의 처음 판은 배열 주소를 전역 변수 data에서 반복마다 읽었는데, data가 count와 같은 줄에 놓였다. 최적화 없는 빌드에서는 그 줄이 계속 지워져, 붙어 있는 칸이 317~362ms로 차이가 4~5배까지 부풀었다. 지금 판은 주소를 지역 변수 d로 받는다.

    더 알아보기¶

    미리 가져오기(프리페치)

    CPU는 차례로 읽는 모양을 알아채고 다음 줄을 미리 가져온다. 그래서 차례로 읽으면 줄을 새로 가져오더라도 기다리는 시간이 짧다. 5번(메모리 계층 구조)의 측정에서 칸들을 무작위 순서로 이은 것도 이 기능을 피하려는 것이었다.

    인텔 CPU의 L2 캐시에는 줄을 가져올 때 128바이트로 짝을 이루는 옆 줄까지 함께 가져오는 기능이 있다(인텔 최적화 설명서의 spatial prefetcher). 2절의 그림에서 보폭 128바이트가 64바이트보다 조금밖에 빠르지 않은 것과 맞는다.

    이 항목의 측정 프로그램

    2절과 3절의 값은 이 PC(Core i9-14900KF, DDR5 64GB, Windows 11)에서 아래 프로그램들을 cl /O2로 빌드해 실행한 범위다(측정 프로그램 1은 8번, 2는 8번, 3은 5번). 측정 프로그램 3은 최적화 없이(cl 기본 옵션)도 5번 실행했다. 이 PC의 논리 프로세서 0~15번은 P-코어 8개(두 번호씩 한 코어), 16~31번은 E-코어 16개다.

    /* 38번 측정 1: 256MiB int 배열에서 s칸마다 하나씩 3을 곱하는 시간
   잴 때마다 먼저 다른 64MiB 배열을 읽어, 앞에서 읽은 줄이 캐시에 남지 않게 한다 */
#include <stdio.h>
#include <windows.h>

#define N (64 * 1024 * 1024)        /* int 6,710만 개 = 256MiB */
#define M (16 * 1024 * 1024)        /* 캐시를 비우는 데 쓰는 64MiB */
static int a[N], other[M];

int main(void) {
    LARGE_INTEGER f, t0, t1;
    QueryPerformanceFrequency(&f);
    SetThreadAffinityMask(GetCurrentThread(), 1 << 2);   /* 2번 논리 프로세서(P-코어)에서만 */
    for (int i = 0; i < N; i++) a[i] = i;
    for (int i = 0; i < M; i++) other[i] = i;
    long long junk = 0;
    for (int s = 1; s <= 64; s *= 2) {
        for (int i = 0; i < M; i++) junk += other[i];
        QueryPerformanceCounter(&t0);
        for (int i = 0; i < N; i += s)
            a[i] *= 3;
        QueryPerformanceCounter(&t1);
        double ms = (double)(t1.QuadPart - t0.QuadPart) * 1000.0 / (double)f.QuadPart;
        printf("step %2d (%3d bytes): %5.1f ms for %8d multiplies\n", s, s * 4, ms, N / s);
    }
    printf("(%lld)\n", junk + a[12345]);   /* 결과를 써야 최적화로 반복이 사라지지 않는다 */
    return 0;
}

    /* 38번 측정 2: 두 스레드가 각자 자기 카운터를 InterlockedIncrement64로 1억 번 올린다.
   두 카운터가 같은 64바이트 줄에 있을 때와 64바이트 떨어져 있을 때의 시간
   usage: share.exe <스레드 1의 논리 프로세서> <스레드 2의 논리 프로세서> */
#include <stdio.h>
#include <stdlib.h>
#include <windows.h>

#define ROUNDS 100000000
static __declspec(align(64)) volatile LONG64 cnt[16];   /* 128바이트. cnt[0]과 cnt[1]은 같은 줄, cnt[8]은 다음 줄 */
static volatile LONG64 *mine[2];

static DWORD WINAPI work(LPVOID arg) {
    volatile LONG64 *c = mine[(INT_PTR)arg];
    for (int i = 0; i < ROUNDS; i++)
        InterlockedIncrement64(c);
    return 0;
}

static double run(int second, int cpu1, int cpu2) {
    mine[0] = &cnt[0];
    mine[1] = &cnt[second];
    HANDLE t[2];
    for (int i = 0; i < 2; i++) {
        t[i] = CreateThread(NULL, 0, work, (LPVOID)(INT_PTR)i, CREATE_SUSPENDED, NULL);
        SetThreadAffinityMask(t[i], (DWORD_PTR)1 << (i ? cpu2 : cpu1));
    }
    LARGE_INTEGER f, t0, t1;
    QueryPerformanceFrequency(&f);
    QueryPerformanceCounter(&t0);
    for (int i = 0; i < 2; i++) ResumeThread(t[i]);
    WaitForMultipleObjects(2, t, TRUE, INFINITE);
    QueryPerformanceCounter(&t1);
    for (int i = 0; i < 2; i++) CloseHandle(t[i]);
    return (double)(t1.QuadPart - t0.QuadPart) * 1000.0 / (double)f.QuadPart;
}

int main(int argc, char **argv) {
    int cpu1 = argc > 2 ? atoi(argv[1]) : 2, cpu2 = argc > 2 ? atoi(argv[2]) : 4;
    double same = run(1, cpu1, cpu2);    /* cnt[0]과 cnt[1]: 8바이트 떨어져 같은 줄 */
    double apart = run(8, cpu1, cpu2);   /* cnt[0]과 cnt[8]: 64바이트 떨어져 다른 줄 */
    printf("cpu %d, %d: same line %.0f ms, different lines %.0f ms\n", cpu1, cpu2, same, apart);
    return 0;
}

    /* 38번 측정 3: 스레드 4개가 1GiB int 배열을 넷으로 나눠 짝수를 센다. 세는 자리 세 가지
   (가) 붙어 있는 배열 칸 count[t]  (나) 64바이트씩 띄운 칸  (다) 스레드의 지역 변수에 세고 끝에 한 번 쓰기 */
#include <stdio.h>
#include <stdlib.h>
#include <windows.h>

#define N (1 << 28)                 /* int 2억 6,843만 개 = 1GiB */
#define T 4
static int *data;
static __declspec(align(64)) long long count[T];   /* 32바이트: 한 줄(64바이트)의 앞쪽에 네 칸이 다 들어간다 */
static struct { __declspec(align(64)) long long v; } padded[T];   /* 칸마다 64바이트 */
static long long result[T];
static int way;

static DWORD WINAPI work(LPVOID arg) {
    int t = (int)(INT_PTR)arg;
    const int *d = data;            /* 배열 주소는 지역 변수로 받는다 (전역 변수를 반복마다 읽지 않게) */
    size_t from = (size_t)N / T * t, to = (size_t)N / T * (t + 1);
    if (way == 0) {
        for (size_t i = from; i < to; i++) if (d[i] % 2 == 0) count[t]++;
    } else if (way == 1) {
        for (size_t i = from; i < to; i++) if (d[i] % 2 == 0) padded[t].v++;
    } else {
        long long c = 0;
        for (size_t i = from; i < to; i++) if (d[i] % 2 == 0) c++;
        result[t] = c;
    }
    return 0;
}

int main(void) {
    data = malloc((size_t)N * sizeof(int));
    for (size_t i = 0; i < N; i++) data[i] = (int)(i * 2654435761u >> 7);
    for (way = 0; way < 3; way++) {
        LARGE_INTEGER f, t0, t1;
        QueryPerformanceFrequency(&f);
        HANDLE h[T];
        QueryPerformanceCounter(&t0);
        for (int t = 0; t < T; t++) {
            h[t] = CreateThread(NULL, 0, work, (LPVOID)(INT_PTR)t, CREATE_SUSPENDED, NULL);
            SetThreadAffinityMask(h[t], (DWORD_PTR)1 << (2 + 2 * t));   /* 2, 4, 6, 8번: 서로 다른 P-코어 */
            ResumeThread(h[t]);
        }
        WaitForMultipleObjects(T, h, TRUE, INFINITE);
        QueryPerformanceCounter(&t1);
        long long total = 0;
        for (int t = 0; t < T; t++) {
            total += way == 0 ? count[t] : way == 1 ? padded[t].v : result[t];
            CloseHandle(h[t]);
        }
        printf("(%c) %4.0f ms, %lld evens\n", "ABC"[way], (double)(t1.QuadPart - t0.QuadPart) * 1000.0 / (double)f.QuadPart, total);
    }
    return 0;
}

    정리¶

    • 시간 지역성은 방금 쓴 것을 곧 다시, 공간 지역성은 그 옆을 곧 쓰는 성질이다. 캐시는 최근에 쓴 줄을 남겨 두고 64바이트 줄을 통째로 가져와 둘을 살린다.
    • 줄 안의 옆 칸은 줄을 가져오는 것보다 훨씬 싸고, 비용은 가져오는 줄 수가 정한다. 안쪽 반복이 메모리를 차례로 지나가게 하면 행렬 곱에서는 수십 배 빨라졌다.
    • 코어마다 캐시가 따로라서, 다른 스레드가 쓰는 변수와 한 줄을 나눠 쓰면 줄이 코어 사이를 오간다(거짓 공유). 변수 사이를 64바이트 띄우거나 지역 변수에 모아 끝에 한 번 쓴다.

    관련 항목¶

    • 5번(메모리 계층 구조): 캐시 줄, 적중률과 평균 접근 시간
