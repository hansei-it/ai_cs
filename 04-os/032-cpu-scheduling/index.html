    32. CPU 스케줄링(선점/비선점)과 컨텍스트 스위칭의 오버헤드¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    이 PC의 코어는 24개(논리 프로세서 32개)인데, 작업 관리자를 열면 스레드가 수천 개다. 논리 프로세서 하나는 한 번에 스레드 하나만 돌린다. 운영체제는 어떤 스레드를 언제, 얼마 동안 돌릴지를 정하고, 스레드를 바꿀 때마다 하던 일을 저장하고 꺼낸다. 이 항목은 그 차례 정하기(스케줄링)와 바꾸는 비용(컨텍스트 스위칭)을 이 PC에서 확인한다.

    이 항목에서 배우는 것¶

    • 스레드의 상태(준비, 실행, 대기)와 선점·비선점 스케줄링의 차이를 설명할 수 있다.
    • FCFS, SJF, 라운드 로빈으로 작업의 실행 차례와 기다린 시간을 손으로 구할 수 있다.
    • 시간 조각과 컨텍스트 스위칭 비용 사이의 맞바꿈을 설명할 수 있다.

    1. 스레드는 준비, 실행, 대기를 오간다¶

    • 논리 프로세서마다 실행 중인 스레드는 하나다. 돌 수 있지만 차례를 기다리는 스레드는 준비 상태로 줄을 서고, 파일 읽기나 Sleep처럼 다른 일을 기다리는 스레드는 대기 상태라 줄에도 서지 않는다.
    • 운영체제의 스케줄러가 준비된 스레드 가운데 다음에 돌릴 것을 고른다. 실행 중인 스레드를 시간이 다 됐다는 이유로 빼앗을 수 있으면 선점, 스레드가 스스로 내놓을 때까지 기다리면 비선점 스케줄링이다.
    • Windows, 리눅스, macOS는 모두 선점형이다. 시계가 주기적으로 보내는 타이머 인터럽트(29번(운영체제의 본질))가 커널을 깨워, 끝없이 도는 스레드가 있어도 다른 스레드에게 차례가 간다(문제 1).

    2. 무엇을 먼저 돌리느냐가 기다리는 시간을 정한다¶

    직접 해 보기CPU 스케줄링 시뮬레이터작업 묶음과 스케줄링 방법(FCFS, SJF, 라운드 로빈), 바꿀 때 드는 시간을 골라 가며, 코어 하나의 실행 차례와 평균 기다린 시간, 바뀐 횟수를 비교한다
    새 창에서 크게 열기
    • FCFS(먼저 온 것부터)는 도착한 차례대로 끝까지 돌린다. 긴 작업이 먼저 오면 짧은 작업들이 줄줄이 기다린다(위젯의 "긴 작업이 먼저").
    • SJF(짧은 것부터)는 모든 작업이 함께 와 있으면 평균 기다린 시간이 가장 짧다. 다만 작업이 얼마나 걸릴지 미리 알아야 하는데, 실제 운영체제는 알 수 없다.
    • 라운드 로빈(RR)은 정해진 시간 조각(q)만큼 돌리고 줄 끝으로 보낸다. 짧은 작업이 오래 갇히지 않는다. 대신 자주 바꿀수록 바꾸는 비용이 쌓인다(위젯에서 "바꿀 때 드는 시간"을 0.5칸으로 바꿔 본다).

    3. 조각은 길고, 바꾸는 비용은 짧다¶

    • 한 논리 프로세서에 두 스레드를 묶고 둘 다 끝없이 돌리자, 32.1~32.9ms(중앙값)씩 번갈아 돌았다. 시스템 시계 틱(15.625ms) 두 번쯤이 한 조각이다.
    • 스레드를 바꾸는 컨텍스트 스위칭은 레지스터를 저장하고 다음 스레드의 것을 꺼내는 일이다. 두 스레드가 이벤트로 차례를 주고받게 하니, 이벤트를 다루는 시스템 콜까지 합쳐 같은 코어에서 한 번에 0.55~0.63µs가 걸렸다. 조각 길이의 5만 분의 1쯤이라 이 조각 길이에서는 거의 보이지 않는다.
    • 그래도 조각을 아주 짧게 하면 바꾸는 비용이 쌓이고, 캐시에 있던 데이터도 다른 스레드의 것으로 바뀐다(38번(참조 지역성과 캐시 적중률)). 조각 길이는 "빨리 돌아가며 응답하기"와 "일을 많이 하기" 사이의 맞바꿈이다.

    예측해 보기¶

    문제 1. 프로세스를 논리 프로세서 하나에 묶고, 쉬지 않고 도는 스레드 둘을 만든다. 두 스레드는 CPU를 스스로 내놓지 않는다. 1초 뒤 두 스레드가 한 번이라도 돌았는지 찍는다. 무엇이 출력될까?

    #include <stdio.h>
#include <windows.h>

static volatile LONG stop;
static volatile long long count[2];

static DWORD WINAPI spin(LPVOID arg) {
    int id = (int)(INT_PTR)arg;
    while (!stop)            /* 쉬지 않고 돈다. CPU를 스스로 내놓지 않는다 */
        count[id]++;
    return 0;
}

int main(void) {
    SetProcessAffinityMask(GetCurrentProcess(), 1 << 2);   /* 논리 프로세서 2 하나에만 */
    HANDLE t[2];
    for (int i = 0; i < 2; i++)
        t[i] = CreateThread(NULL, 0, spin, (LPVOID)(INT_PTR)i, 0, NULL);
    Sleep(1000);
    stop = 1;
    WaitForMultipleObjects(2, t, TRUE, INFINITE);
    printf("%d %d\n", count[0] > 0, count[1] > 0);
    return 0;
}
    정답과 해설

    1 1. 둘 다 돌았다. Windows는 선점형이라, 먼저 잡은 스레드가 쉬지 않아도 시간 조각이 끝나면 빼앗아 다른 스레드에 준다. Sleep에서 깨어난 main도 차례를 받아 stop을 바꿀 수 있었다. 비선점이었다면 먼저 잡은 스레드가 영원히 코어를 차지해, 이 프로그램은 끝나지 않는다.

    문제 2. P1(0에 도착, 8칸), P2(1에 도착, 4칸), P3(2에 도착, 2칸)을 코어 하나에서 돌린다. FCFS, SJF(비선점), RR(q = 2)에서 각 작업이 기다린 시간과 그 평균은? RR에서는 같은 시각에 도착한 작업이 그 시각에 밀려난 작업보다 앞에 선다.

    정답과 해설

    기다린 시간 = 끝난 시각 − 도착 − 실행 시간이다.

    • FCFS: P1 0~8, P2 8~12, P3 12~14. 기다린 시간 0, 7, 10, 평균 약 5.67칸.
    • SJF: P1 0~8(시각 0에는 P1뿐), P3 8~10, P2 10~14. 기다린 시간 0, 9, 6, 평균 5칸.
    • RR(q = 2): P1 0~2, P2 2~4, P3 4~6, P1 6~8, P2 8~10, P1 10~14. 기다린 시간 6, 5, 2, 평균 약 4.33칸. 대신 작업이 5번 바뀌었다(FCFS와 SJF는 2번).

    여기서는 RR이 SJF보다 짧았다. 비선점 SJF는 혼자 먼저 온 P1(8칸)을 끝까지 돌리기 때문이다. SJF가 가장 짧은 것은 모든 작업이 함께 와 있을 때다.

    위젯의 "기본" 묶음에서 세 방법을 눌러 확인할 수 있다.

    문제 3. 두 스레드가 이벤트로 차례를 주고받는다. 두 스레드가 같은 논리 프로세서에 있을 때와 서로 다른 프로세서에 있을 때, 어느 쪽이 빠를까?

    정답과 해설

    같은 프로세서가 빨랐다. 이 PC에서 한 번 넘기는 데 같은 프로세서는 0.55~0.63µs, 서로 다른 프로세서(2번과 4번)는 3.5~4.2µs였다. 다른 프로세서로 넘길 때는 그 프로세서에 알리고, 쉬고 있던 그 프로세서가 깨어나 스레드를 잡는 시간이 더해진다. "코어가 많으면 무조건 빠르다"가 아닌 예다(33번(동시성과 병렬성)).

    직접 해보기¶

    실습: 내 PC의 스케줄러 재 보기

    1. "더 알아보기"의 측정 프로그램 1을 slices.exe 2처럼 실행해 내 PC의 시간 조각을 잰다. 다른 번호의 논리 프로세서로도 재 본다.
    2. 측정 프로그램 2를 같은 번호(switch.exe 2 2)와 다른 번호(switch.exe 2 4)로 실행해 비교한다.
    3. 위젯에서 "긴 작업이 먼저" 묶음을 FCFS와 RR q=1로 돌려 평균 기다린 시간을 비교하고, 바꿀 때 드는 시간을 0.5칸으로 바꾸면 어떻게 되는지 본다.
    확인할 점
    • 조각 길이는 PC와 설정에 따라 다르다. 이 PC에서 P-코어에 속한 0, 2, 8번 논리 프로세서는 중앙값이 32~34ms로 고르게 나왔고, E-코어인 31번은 중앙값이 22~29ms로 들쭉날쭉했다(이 PC의 논리 프로세서 0~15번은 P-코어 8개, 16~31번은 E-코어 16개다). 다른 프로그램의 스레드가 그 프로세서를 함께 써서 조각이 중간에 끊기기 때문이다.
    • "긴 작업이 먼저"에서 평균 기다린 시간은 FCFS 8.25칸, RR q=1 2.25칸이다. 바꾸는 데 0.5칸이 들면 RR q=1은 3.5칸으로 늘어난다.

    AI와 함께 확인하기¶

    AI 활용 과제: Sleep(1)은 몇 ms를 자나

    1. AI에게 "Windows에서 Sleep(1)은 몇 ms 동안 스레드를 재우는가"와 "Windows의 시간 조각은 몇 ms인가"를 묻는다.
    2. Sleep(1)을 100번 부르고 QueryPerformanceCounter로 잰 시간을 100으로 나눠 한 번의 시간을 잰다.
    3. AI의 답과 대조하고, 다르면 결과를 보여 주고 이유를 설명하게 한다.
    확인할 점
    • 이 PC에서 Sleep(1)은 한 번에 15.3~15.4ms였다. 스레드는 시계 틱(15.625ms)에 맞춰 깨어나기 때문이다. timeBeginPeriod(1)로 시계를 촘촘하게 하면 1.4~1.7ms였다.
    • "1ms 잔다"고만 답하면 틀렸다. Sleep은 시계 틱에 맞춰 깨어나므로 요청한 시간과 다르고, 1ms를 부탁하면 대개 훨씬 길게 잔다. 게임이나 측정 코드에서 Sleep(1)로 1ms 간격을 맞추려다 생기는 버그다.
    • 시간 조각 길이는 Windows 판과 설정(전경 앱 우대 등)에 따라 다르다. 한 숫자를 단정하는 답보다, 재 보라고 하는 답이 낫다. 이 PC의 측정값은 32.1~32.9ms였고, 앞에 띄운 콘솔 창(Windows Terminal, 옛 콘솔 창 모두)에서 재도 32.0~32.6ms로 같았다.

    더 알아보기¶

    우선순위와 실제 스케줄러

    Windows의 스케줄러는 0~31의 우선순위를 쓴다. 준비된 스레드 가운데 우선순위가 가장 높은 것을 돌리고, 같은 우선순위끼리는 라운드 로빈으로 돌린다. 키보드 입력을 받은 스레드나 기다리던 일이 끝난 스레드는 잠깐 우선순위를 올려 빨리 응답하게 한다. 리눅스의 스케줄러(6.6판 전의 CFS, 그 뒤로는 이를 고친 EEVDF)는 스레드마다 "지금까지 쓴 CPU 시간"을 재어 덜 쓴 것에 먼저 차례를 준다. 이 항목의 FCFS, SJF, RR은 이런 실제 스케줄러를 이해하기 위한 기본 모형이다.

    이 항목의 측정 프로그램

    3절과 그림의 값은 이 PC(Core i9-14900KF, DDR5 64GB, Windows 11)에서 아래 두 프로그램을 cl /O2로 빌드해 여러 번(조각 길이 16번, 차례 넘기기 같은 코어 8번·다른 코어 5번) 실행한 범위다. 시계 틱은 GetSystemTimeAdjustment가 돌려준 156,250(100ns 단위)이다.

    /* 32번 측정 1: 한 논리 프로세서에 묶은 두 스레드가 끝없이 돌 때, 한 번 잡으면 얼마 동안 계속 도는지
   두 스레드는 "지금 도는 스레드" 변수를 보며 돌다가, 그 값이 자기가 아니면 바뀐 시각을 적고 자기로 바꾼다.
   usage: slices.exe <논리 프로세서 번호> */
#include <stdio.h>
#include <stdlib.h>
#include <windows.h>

#define MAXS 2000
static LARGE_INTEGER freq;
static volatile LONG cur = -1;          /* 지금 도는 스레드 */
static double when[MAXS];              /* 도는 스레드가 바뀐 시각 (ms) */
static int n;
static volatile LONG stop;

static double now_ms(void) {
    LARGE_INTEGER c;
    QueryPerformanceCounter(&c);
    return (double)c.QuadPart * 1000.0 / (double)freq.QuadPart;
}

static DWORD WINAPI spin(LPVOID arg) {
    LONG id = (LONG)(INT_PTR)arg;
    while (!stop) {
        if (cur != id) {                    /* 내가 다시 잡았다 */
            if (n < MAXS) when[n++] = now_ms();
            cur = id;
        }
    }
    return 0;
}

static int cmp(const void *a, const void *b) {
    double x = *(const double *)a, y = *(const double *)b;
    return (x > y) - (x < y);
}

int main(int argc, char **argv) {
    int cpu = argc > 1 ? atoi(argv[1]) : 0;
    QueryPerformanceFrequency(&freq);
    SetProcessAffinityMask(GetCurrentProcess(), (DWORD_PTR)1 << cpu);
    HANDLE t[2];
    for (int i = 0; i < 2; i++)
        t[i] = CreateThread(NULL, 0, spin, (LPVOID)(INT_PTR)i, 0, NULL);
    Sleep(3000);
    stop = 1;
    WaitForMultipleObjects(2, t, TRUE, INFINITE);
    static double len[MAXS];
    int m = 0;
    for (int i = 2; i < n; i++)               /* 처음 두 번은 시작하는 중이라 뺀다 */
        len[m++] = when[i] - when[i - 1];
    qsort(len, m, sizeof(double), cmp);
    printf("cpu %d: %d switches in 3 s, slice median %.2f ms, middle half %.2f~%.2f ms, max %.2f ms\n",
           cpu, n - 1, len[m / 2], len[m / 4], len[3 * m / 4], len[m - 1]);
    return 0;
}

    /* 32번 측정 2: 두 스레드가 이벤트로 차례를 주고받는 데 걸린 시간 (한 번 넘길 때마다 스레드가 바뀐다)
   usage: switch.exe <스레드 A의 논리 프로세서> <스레드 B의 논리 프로세서> */
#include <stdio.h>
#include <stdlib.h>
#include <windows.h>

#define ROUNDS 100000
static HANDLE ev[2];

static DWORD WINAPI pong(LPVOID arg) {
    (void)arg;
    for (int i = 0; i < ROUNDS; i++) {
        WaitForSingleObject(ev[1], INFINITE);   /* 내 차례를 기다린다 */
        SetEvent(ev[0]);                        /* 상대에게 넘긴다 */
    }
    return 0;
}

int main(int argc, char **argv) {
    int a = argc > 2 ? atoi(argv[1]) : 2, b = argc > 2 ? atoi(argv[2]) : 2;
    LARGE_INTEGER f, t0, t1;
    QueryPerformanceFrequency(&f);
    ev[0] = CreateEventA(NULL, FALSE, FALSE, NULL);
    ev[1] = CreateEventA(NULL, FALSE, FALSE, NULL);
    SetThreadAffinityMask(GetCurrentThread(), (DWORD_PTR)1 << a);
    HANDLE t = CreateThread(NULL, 0, pong, NULL, CREATE_SUSPENDED, NULL);
    SetThreadAffinityMask(t, (DWORD_PTR)1 << b);
    ResumeThread(t);
    QueryPerformanceCounter(&t0);
    for (int i = 0; i < ROUNDS; i++) {
        SetEvent(ev[1]);
        WaitForSingleObject(ev[0], INFINITE);
    }
    QueryPerformanceCounter(&t1);
    WaitForSingleObject(t, INFINITE);
    double us = (double)(t1.QuadPart - t0.QuadPart) * 1e6 / (double)f.QuadPart;
    printf("cpu %d <-> cpu %d: %.2f us per hand-off\n", a, b, us / ROUNDS / 2);
    return 0;
}

    정리¶

    • 스레드는 준비, 실행, 대기를 오가고, 스케줄러가 준비된 스레드 가운데 다음에 돌릴 것을 고른다. 시간이 다 되면 빼앗는 것이 선점이다.
    • FCFS는 단순하지만 긴 작업 뒤에 짧은 작업이 갇히고, SJF는 작업이 함께 와 있으면 평균 기다림이 가장 짧지만 실행 시간을 알아야 하며, RR은 고르게 돌리지만 자주 바꾼다.
    • 이 PC의 시간 조각은 약 32.5ms, 같은 코어에서 스레드를 바꾸는 데는 약 0.6µs였다. 조각이 짧을수록 바꾸는 비용과 캐시 손실이 커진다.
