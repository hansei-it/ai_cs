    33. 동시성과 병렬성의 구분¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    "여러 일을 동시에 한다"는 말에는 두 뜻이 섞여 있다. 코어 하나가 여러 일을 번갈아 조금씩 진행하는 것과, 코어 여럿이 여러 일을 정말 같은 순간에 하는 것이다. 앞의 것이 동시성, 뒤의 것이 병렬성이다. 둘을 구분하면 "스레드를 늘렸는데 왜 안 빨라지지?"와 "코어가 하나인데 왜 빨라졌지?"에 답할 수 있다. 이 PC(P-코어 8개, E-코어 16개, 논리 프로세서 32개)에서 확인한다.

    이 항목에서 배우는 것¶

    • 동시성과 병렬성을 구분하고, 각각이 어떤 일을 빠르게 하는지 설명할 수 있다.
    • 기다리는 일과 계산하는 일을 스레드로 나눴을 때 걸리는 시간을 예측할 수 있다.
    • 스레드를 늘려도 그만큼 빨라지지 않는 까닭(나눌 수 없는 부분, 코어의 차이, 일의 불균형)을 설명할 수 있다.

    1. 동시성은 번갈아, 병렬성은 정말 동시에¶

    • 동시성(concurrency)은 여러 일이 한 기간 안에 함께 진행 중인 것이다. 코어 하나라도 스케줄러가 조금씩 번갈아 돌리면(32번(CPU 스케줄링과 컨텍스트 스위칭)) 동시성이 생긴다. 한순간에는 하나만 돈다.
    • 병렬성(parallelism)은 여러 일이 같은 순간에 실제로 실행되는 것이다. 코어가 여럿이어야 한다.
    • 동시성은 "여러 일을 다루는 구조", 병렬성은 "여러 일을 한꺼번에 처리하는 실행"이다. 여러 스레드로 짠 동시성 프로그램은 코어가 여럿이면 병렬로도 돌 수 있다.

    2. 기다리는 일은 코어 하나로도 겹친다¶

    • 일 네 개를 스레드 네 개로 시켰다. 일 하나는 혼자 하면 약 100ms다. 파일이나 네트워크를 기다리는 일(여기서는 Sleep(100))은 코어 하나에서도 101~115ms에 다 끝났다. 기다리는 동안은 코어를 쓰지 않으므로, 그 사이에 다른 스레드가 돈다.
    • 계산하는 일은 코어 하나에서 386~412ms로 네 배가 걸렸다. 번갈아 할 뿐 계산의 양은 그대로다. P-코어 8개를 쓰게 하자 97~103ms로 줄었다. 계산을 빠르게 하는 것은 병렬성이다.
    • 그래서 웹 서버처럼 기다리는 일이 대부분인 프로그램은 동시성이, 영상 처리처럼 계산이 대부분인 프로그램은 병렬성이 중요하다(36번(I/O 모델)).

    3. 코어를 늘려도 그만큼 빨라지지 않는다¶

    직접 해 보기스레드를 늘리면 몇 배 빨라지나이 PC에서 같은 계산을 스레드 1~32개로 나눠 잰 빨라진 배수를 보고, 나눌 수 없는 부분의 비율을 바꿔 가며 암달의 법칙 곡선과 비교한다
    새 창에서 크게 열기
    • 혼자 하면 약 2.3초 걸리는 계산을 똑같이 나눴더니 스레드 8개에서 7.6배, 32개에서 21.7배 빨라졌다. 32배가 아닌 것은 코어가 같지 않아서다. 스레드가 8개를 넘으면 일부가 더 느린 E-코어에서 도는데, 이 계산은 E-코어에서 1.3~1.4배 느렸다. 똑같이 나눴으므로 늦게 끝나는 스레드가 전체 시간을 정한다.
    • 일에 나눌 수 없는 부분이 있으면 한계가 더 낮다. 일의 10%가 혼자 해야 하는 부분이면, 스레드가 아무리 많아도 10배를 넘지 못한다(암달의 법칙).
    • 나누는 방법도 중요하다. 일을 똑같이 나눈 것 같아도 어떤 스레드는 일찍 끝나 놀고, 가장 늦은 스레드가 전체 시간을 정한다(아래 "AI와 함께 확인하기").

    예측해 보기¶

    문제 1. 아래 프로그램은 일 네 개를 스레드 네 개로 동시에 시킨다. 일은 "100ms 기다리기"이거나 "혼자 돌면 약 100ms 걸리는 계산"이다. 코어 하나에 묶었을 때와 P-코어 8개를 쓸 때, 네 경우의 전체 시간은 각각 몇 ms쯤일까?

    /* 일 네 개를 스레드 네 개로 동시에 시킨다 */
#include <stdio.h>
#include <windows.h>

static long long iters;          /* 혼자 돌면 약 100ms 걸리는 반복 횟수 (처음에 잰다) */
static volatile unsigned sink;

static unsigned work(long long n) {
    unsigned x = 1;
    for (long long i = 0; i < n; i++)
        x = x * 1103515245u + 12345u;
    return x;
}

static DWORD WINAPI task(LPVOID arg) {
    if (arg) Sleep(100);         /* 기다리는 일 (파일, 네트워크를 기다리는 것과 같다) */
    else sink += work(iters);    /* 계산하는 일 */
    return 0;
}

static double run4(int waiting) {
    LARGE_INTEGER f, a, b;
    QueryPerformanceFrequency(&f);
    QueryPerformanceCounter(&a);
    HANDLE t[4];
    for (int i = 0; i < 4; i++)
        t[i] = CreateThread(NULL, 0, task, (LPVOID)(INT_PTR)waiting, 0, NULL);
    WaitForMultipleObjects(4, t, TRUE, INFINITE);
    QueryPerformanceCounter(&b);
    for (int i = 0; i < 4; i++) CloseHandle(t[i]);
    return (double)(b.QuadPart - a.QuadPart) * 1000.0 / f.QuadPart;
}

int main(void) {
    LARGE_INTEGER f, a, b;
    QueryPerformanceFrequency(&f);
    SetProcessAffinityMask(GetCurrentProcess(), 1 << 2);          /* 논리 프로세서 2 하나에서 */
    iters = 10000000;
    QueryPerformanceCounter(&a);
    sink += work(iters);
    QueryPerformanceCounter(&b);
    iters = (long long)(iters * 100.0 / ((double)(b.QuadPart - a.QuadPart) * 1000.0 / f.QuadPart));
    printf("one core: wait %.0f ms, compute %.0f ms\n", run4(1), run4(0));
    SetProcessAffinityMask(GetCurrentProcess(), (1 << 16) - 1);   /* P-코어 8개(논리 프로세서 0~15)에서 */
    printf("8 cores:  wait %.0f ms, compute %.0f ms\n", run4(1), run4(0));
    return 0;
}
    정답과 해설

    이 PC에서 cl /O2로 5번 실행한 범위다.

    • 코어 하나, 기다리기: 101~115ms. 넷이 함께 기다린다(동시성).
    • 코어 하나, 계산: 386~412ms. 번갈아 해도 계산 양은 네 배다.
    • P-코어 8개, 기다리기: 102~115ms. 코어가 늘어도 기다리는 시간은 그대로다.
    • P-코어 8개, 계산: 97~103ms. 넷이 정말 동시에 돈다(병렬성).

    기다리기가 100ms보다 조금 긴 것은 Sleep이 시계 틱(15.625ms)에 맞춰 깨어나기 때문이다(32번(CPU 스케줄링과 컨텍스트 스위칭)).

    문제 2. 프로그램의 실행 시간 중 10%는 한 스레드가 차례로 해야 하는 부분이다. 나머지 90%는 얼마든지 나눌 수 있다. 코어가 무한히 많으면 몇 배까지 빨라질까? 코어 32개로는?

    정답과 해설

    10배, 코어 32개로는 약 7.8배. 나눌 수 있는 부분이 0에 가까워져도 10%는 그대로 남는다. 빨라지는 배수는 1 ÷ (0.1 + 0.9 ÷ N)이고, N = 32이면 1 ÷ 0.128125 ≈ 7.8이다. 위젯에서 "10%"를 눌러 확인할 수 있다.

    문제 3. 논리 프로세서가 32개인 이 PC에서, 나눌 수 없는 부분이 없는 계산을 스레드 32개로 똑같이 나누면 몇 배 빨라질까?

    정답과 해설

    약 21.7배였다. 이론으로는 32배지만 논리 프로세서 32개가 같은 코어 32개가 아니다. 16개는 P-코어 8개가 하이퍼스레딩으로 둘씩 보인 것이고, 나머지 16개는 E-코어다. 이 계산은 한 P-코어의 두 논리 프로세서에서 함께 돌아도 느려지지 않았지만, E-코어에서는 1.3~1.4배 느렸다(측정 프로그램 3). 똑같이 나눴으므로 E-코어에 간 스레드가 늦게 끝나 전체 시간을 정한다.

    직접 해보기¶

    실습: 내 PC에서 재 보기

    1. 문제 1의 프로그램을 내 PC에서 실행한다. 내 PC의 논리 프로세서 수는 작업 관리자나 GetSystemInfo로 확인하고, 마지막 SetProcessAffinityMask의 값을 내 PC에 맞게 바꾼다(예: 논리 프로세서 8개면 (1 << 8) - 1).
    2. "더 알아보기"의 측정 프로그램 1로 스레드 수에 따른 시간을 재고, 빨라진 배수를 그래프로 그린다. 어디서부터 처지는지 본다.
    확인할 점
    • 기다리는 일은 어느 PC에서나 100ms 남짓이다. 계산하는 일은 코어 하나에서 약 4배, 코어가 4개 이상이면 약 1배가 나와야 한다.
    • 빨라진 배수가 처지기 시작하는 곳은 그 PC의 코어 구성에 따라 다르다. 이 PC는 P-코어 수인 8에서 처지기 시작했다. 스레드가 그보다 많으면 일부가 더 느린 E-코어에서 돈다.

    AI와 함께 확인하기¶

    AI 활용 과제: 소수 세기를 스레드 8개로 나누기

    1. AI에게 "0부터 2,999,999까지의 소수 개수를 C(Windows API)로 스레드 8개에 나눠 빠르게 세는 코드"를 짜 달라고 한다.
    2. 실행하기 전에, 나눈 방법을 보고 스레드마다 일의 양이 같을지 예측한다.
    3. 스레드마다 걸린 시간을 재어 출력하게 고치고 실행한다. 가장 빨리 끝난 스레드와 가장 늦게 끝난 스레드를 비교한다.
    확인할 점
    • 답은 216,816개다(Python으로 따로 확인했다).
    • 구간을 똑같이 8등분하는 답이 흔하다. 큰 수일수록 소수 판정이 오래 걸려서, 이 PC에서 스레드마다 19~25ms에 끝난 것부터 59~81ms 걸린 것까지 차이가 났고 전체는 59~82ms였다.
    • "번갈아 나누기"(n % 8)는 더 나빴다. 짝수만 맡은 스레드 넷은 바로 끝나고(0ms) 홀수를 맡은 넷이 일을 다 했다. 전체 86~105ms.
    • 1만 개씩 묶음을 먼저 끝난 스레드가 가져가게 하면(InterlockedAdd로 다음 묶음 번호를 나눈다) 스레드마다 47~57ms로 고르고 전체 50~57ms로 가장 빨랐다. 가장 늦은 스레드가 전체 시간을 정한다.

    더 알아보기¶

    한 코어 안의 병렬성

    코어 하나도 안에서 병렬로 일한다. 한 명령어로 수 여러 개를 한꺼번에 더하는 SIMD 명령(x86의 AVX)이 있고, 서로 상관없는 명령어 여러 개를 한 클록에 동시에 실행하기도 한다. 그래픽 카드(GPU)는 단순한 코어 수천 개로 같은 계산을 데이터 수천 개에 한꺼번에 적용한다. 행렬 곱이 대부분인 AI 학습이 GPU에서 빠른 까닭이다.

    이 항목의 측정 프로그램

    값은 이 PC(Core i9-14900KF: P-코어 8개 + E-코어 16개, 논리 프로세서 32개, DDR5 64GB, Windows 11)에서 아래 프로그램을 cl /O2로 빌드해 5번씩 실행한 범위다. 논리 프로세서 0~15번이 P-코어, 16~31번이 E-코어인 것은 GetLogicalProcessorInformationEx로 확인했다.

    /* 33번 측정 1: 같은 양의 계산을 스레드 N개로 똑같이 나눴을 때 걸린 시간 (N = 1, 2, 4, 8, 16, 24, 32) */
#include <stdio.h>
#include <windows.h>

#define TOTAL 3200000000LL       /* 전체 반복 횟수 */
static long long share;
static volatile unsigned sink;

static DWORD WINAPI task(LPVOID arg) {
    (void)arg;
    unsigned x = 1;
    for (long long i = 0; i < share; i++)
        x = x * 1103515245u + 12345u;
    InterlockedAdd((volatile LONG *)&sink, (LONG)x);
    return 0;
}

int main(void) {
    int ns[] = { 1, 2, 4, 8, 16, 24, 32 };
    LARGE_INTEGER f, a, b;
    QueryPerformanceFrequency(&f);
    for (int k = 0; k < 7; k++) {
        int n = ns[k];
        share = TOTAL / n;
        HANDLE t[32];
        QueryPerformanceCounter(&a);
        for (int i = 0; i < n; i++)
            t[i] = CreateThread(NULL, 0, task, NULL, 0, NULL);
        WaitForMultipleObjects(n, t, TRUE, INFINITE);
        QueryPerformanceCounter(&b);
        for (int i = 0; i < n; i++) CloseHandle(t[i]);
        printf("%2d threads: %7.1f ms\n", n, (double)(b.QuadPart - a.QuadPart) * 1000.0 / f.QuadPart);
    }
    return 0;
}

    /* 33번 측정 2: 0~2,999,999의 소수 세기를 스레드 8개로 나누는 세 방법. 스레드마다 걸린 시간을 잰다
   0: 구간을 8등분  1: 번갈아(n % 8)  2: 1만 개씩 묶음을 먼저 끝난 스레드가 가져가기 */
#include <stdio.h>
#include <windows.h>

#define N 3000000
#define T 8
#define BLOCK 10000
static int mode;
static volatile LONG next;      /* 2번 방법에서 다음에 가져갈 묶음의 시작 */
static long counts[T];
static double ms[T];
static LARGE_INTEGER freq;

static int is_prime(int n) {
    if (n < 2) return 0;
    for (int d = 2; (long long)d * d <= n; d++)
        if (n % d == 0) return 0;
    return 1;
}

static DWORD WINAPI task(LPVOID arg) {
    int id = (int)(INT_PTR)arg;
    LARGE_INTEGER a, b;
    QueryPerformanceCounter(&a);
    long c = 0;
    if (mode == 0) {
        for (int n = id * (N / T); n < (id + 1) * (N / T); n++) c += is_prime(n);
    } else if (mode == 1) {
        for (int n = id; n < N; n += T) c += is_prime(n);
    } else {
        for (LONG s; (s = InterlockedAdd(&next, BLOCK) - BLOCK) < N;)
            for (int n = s; n < s + BLOCK && n < N; n++) c += is_prime(n);
    }
    QueryPerformanceCounter(&b);
    counts[id] = c;
    ms[id] = (double)(b.QuadPart - a.QuadPart) * 1000.0 / freq.QuadPart;
    return 0;
}

int main(void) {
    const char *name[] = { "8 ranges", "n % 8", "blocks" };
    QueryPerformanceFrequency(&freq);
    SetProcessAffinityMask(GetCurrentProcess(), (1 << 16) - 1);   /* P-코어 8개(논리 프로세서 0~15)에서 */
    for (mode = 0; mode < 3; mode++) {
        HANDLE t[T];
        LARGE_INTEGER a, b;
        next = 0;
        QueryPerformanceCounter(&a);
        for (int i = 0; i < T; i++) t[i] = CreateThread(NULL, 0, task, (LPVOID)(INT_PTR)i, 0, NULL);
        WaitForMultipleObjects(T, t, TRUE, INFINITE);
        QueryPerformanceCounter(&b);
        long total = 0;
        double lo = 1e9, hi = 0;
        for (int i = 0; i < T; i++) { total += counts[i]; if (ms[i] < lo) lo = ms[i]; if (ms[i] > hi) hi = ms[i]; }
        printf("%-8s primes %ld, total %3.0f ms, threads %2.0f~%2.0f ms\n", name[mode], total,
               (double)(b.QuadPart - a.QuadPart) * 1000.0 / freq.QuadPart, lo, hi);
    }
    return 0;
}

    측정 프로그램 3은 측정 1의 계산을 논리 프로세서에 묶어 돌린다. 이 PC에서 P-코어 하나에 혼자 293~297ms, 한 P-코어의 두 논리 프로세서에 함께 묶으면 284~296ms, 서로 다른 P-코어 둘이면 283~299ms, E-코어 하나에 혼자 377~418ms였다. 이 계산은 앞 곱셈의 결과를 기다리며 도는 시간이 대부분이라, 한 코어의 계산 장치를 둘이 나눠 써도 서로 늦추지 않은 것으로 보인다. 계산 장치를 쉬지 않고 쓰는 계산이라면 결과가 다를 수 있다.

    /* 33번 측정 3: 측정 1의 계산(4억 번)을 정한 논리 프로세서에 묶어 돌린 시간. 번호는 이 PC에 맞춘 것이다
   (0과 1은 한 P-코어의 두 논리 프로세서, 2는 다른 P-코어, 16은 E-코어) */
#include <stdio.h>
#include <windows.h>

static long long share;
static volatile unsigned sink;
static double ms[2];
static LARGE_INTEGER f;

static DWORD WINAPI task(LPVOID arg) {
    int id = (int)(INT_PTR)arg;
    LARGE_INTEGER a, b;
    QueryPerformanceCounter(&a);
    unsigned x = 1;
    for (long long i = 0; i < share; i++)
        x = x * 1103515245u + 12345u;
    InterlockedAdd((volatile LONG *)&sink, (LONG)x);
    QueryPerformanceCounter(&b);
    ms[id] = (double)(b.QuadPart - a.QuadPart) * 1000.0 / f.QuadPart;
    return 0;
}

static void run(const char *name, int n, int cpu0, int cpu1) {
    HANDLE t[2];
    int cpu[2] = { cpu0, cpu1 };
    for (int i = 0; i < n; i++) {
        t[i] = CreateThread(NULL, 0, task, (LPVOID)(INT_PTR)i, CREATE_SUSPENDED, NULL);
        SetThreadAffinityMask(t[i], (DWORD_PTR)1 << cpu[i]);
        ResumeThread(t[i]);
    }
    WaitForMultipleObjects(n, t, TRUE, INFINITE);
    for (int i = 0; i < n; i++) CloseHandle(t[i]);
    printf("%-26s %5.0f ms%s", name, ms[0], n == 2 ? "" : "\n");
    if (n == 2) printf(", %5.0f ms\n", ms[1]);
}

int main(void) {
    QueryPerformanceFrequency(&f);
    share = 400000000LL;
    run("P-core, alone (0)", 1, 0, 0);
    run("same P-core, two (0, 1)", 2, 0, 1);
    run("two P-cores (0, 2)", 2, 0, 2);
    run("E-core, alone (16)", 1, 16, 0);
    return 0;
}

    정리¶

    • 동시성은 여러 일을 번갈아 진행하는 것, 병렬성은 여러 코어가 정말 같은 순간에 실행하는 것이다.
    • 기다리는 일은 코어 하나로도 겹쳐 빨라지고(동시성), 계산하는 일은 코어가 여럿이어야 빨라진다(병렬성).
    • 스레드를 늘려도 나눌 수 없는 부분, 코어의 차이, 일의 불균형 때문에 그만큼 빨라지지 않는다. 가장 늦게 끝나는 스레드가 전체 시간을 정한다.
