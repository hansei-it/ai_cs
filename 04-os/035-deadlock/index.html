    35. 교착 상태: 발생 조건 4가지와 해결 기법¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    34번(스레드 동기화)에서 경쟁 상태를 잠금으로 막았다. 그런데 잠금이 둘 이상이 되면 새 문제가 생긴다. 두 스레드가 서로 상대가 쥔 잠금을 기다리며 영원히 멈추는 교착 상태(deadlock)다. 프로그램은 죽지도 않고 오류도 없이 그대로 멈춰 있어서, 원인을 찾기 어렵다. 이 항목은 교착을 직접 만들어 보고, 생기는 조건과 깨는 방법을 이 PC에서 확인한다.

    이 항목에서 배우는 것¶

    • 두 스레드와 두 잠금으로 교착이 생기는 순서를 설명하고, 코드를 보고 교착 가능성을 예측할 수 있다.
    • 교착이 생기는 네 조건을 말하고, 각 해결 기법이 그중 무엇을 깨는지 설명할 수 있다.
    • 잠그는 순서를 정하는 방법으로 교착을 막을 수 있다.

    1. 서로 상대가 쥔 잠금을 기다리면 영원히 멈춘다¶

    • T1은 잠금 A를 잡은 뒤 B를, T2는 B를 잡은 뒤 A를 잡으려 한다. T1이 A를, T2가 B를 잡은 순간 둘은 상대가 쥔 잠금을 기다린다. 어느 쪽도 쥔 것을 내려놓지 않으므로 영원히 기다린다.
    • 이 PC에서 그렇게 짠 프로그램은 5번 모두 멈췄다(문제 1). 잡는 사이에 10ms를 쉬지 않아도, 두 계좌 사이에 1씩 10만 번 옮기는 프로그램에서 5번 모두 멈췄다(실습).
    • 운영체제가 재워 두는 잠금이면 교착은 CPU를 쓰지 않는다. 스레드는 대기 상태로 멈춰 있을 뿐이라(32번(CPU 스케줄링과 컨텍스트 스위칭)) 작업 관리자에서 CPU 0%로 보이고, 창이 있는 프로그램이면 "응답 없음"이 뜬다.

    2. 네 조건이 모두 있어야 생긴다¶

    • 교착은 네 조건이 모두 있을 때만 생긴다. 상호 배제(한 번에 하나만 쓴다), 점유와 대기(쥔 채로 기다린다), 비선점(빼앗을 수 없다), 순환 대기(기다림이 원을 이룬다)다.
    • 그래서 하나만 깨면 된다. 가장 흔한 방법은 순환 대기를 깨는 것, 곧 모든 스레드가 잠금을 같은 순서로 잡게 하는 것이다(문제 2).
    • 쥔 것을 스스로 내려놓게 해서 비선점을 깨는 방법도 있다. 두 번째 잠금을 TryEnterCriticalSection으로 시도하고, 못 잡으면 첫 번째를 풀었다가 다시 한다. 이 PC에서 1~3번 물러선 뒤 모두 끝났다.

    3. 순서를 정하면 원이 생기지 않는다¶

    직접 해 보기식사하는 철학자철학자 다섯을 눌러 포크를 하나씩 들게 하며 교착 상태를 직접 만들어 보고, 번호가 작은 포크부터 드는 규칙으로 바꿔 순환 대기가 사라지는지 본다
    새 창에서 크게 열기
    • 철학자 다섯이 모두 왼쪽 포크부터 들면, 다섯이 동시에 왼쪽을 쥐는 순간 모두 오른쪽을 기다려 원이 생길 수 있다. 위젯에서 무작위로 300단계를 돌리면 100번 중 100번 교착에 빠졌다.
    • "번호가 작은 포크부터"로 바꾸면 철학자 4만 오른쪽(0번)을 먼저 든다. 그러면 기다림이 한 바퀴를 돌 수 없어서, 100번 모두 교착 없이 300단계를 마쳤다.
    • 실제 프로그램에서는 계좌 번호, 메모리 주소처럼 모든 잠금에 정해진 차례를 매겨 늘 작은 것부터 잡는다.

    예측해 보기¶

    문제 1. T1은 A를 잡고 10ms 뒤 B를, T2는 B를 잡고 10ms 뒤 A를 잡는다. main은 두 스레드를 2초까지 기다린다. 무엇이 출력될까?

    #include <stdio.h>
#include <windows.h>

CRITICAL_SECTION A, B;

DWORD WINAPI t1(LPVOID arg) {
    (void)arg;
    EnterCriticalSection(&A);
    Sleep(10);
    EnterCriticalSection(&B);
    LeaveCriticalSection(&B);
    LeaveCriticalSection(&A);
    return 0;
}

DWORD WINAPI t2(LPVOID arg) {
    (void)arg;
    EnterCriticalSection(&B);       /* T1과 반대 순서 */
    Sleep(10);
    EnterCriticalSection(&A);
    LeaveCriticalSection(&A);
    LeaveCriticalSection(&B);
    return 0;
}

int main(void) {
    InitializeCriticalSection(&A);
    InitializeCriticalSection(&B);
    HANDLE t[2] = { CreateThread(NULL, 0, t1, NULL, 0, NULL), CreateThread(NULL, 0, t2, NULL, 0, NULL) };
    DWORD r = WaitForMultipleObjects(2, t, TRUE, 2000);      /* 2초까지 기다린다 */
    printf("%s\n", r == WAIT_TIMEOUT ? "stuck" : "done");
    return 0;
}
    정답과 해설

    stuck. T1이 A를, T2가 B를 잡고 10ms를 쉬는 동안 둘 다 첫 잠금을 쥐었다. 그다음 서로 상대의 잠금을 기다린다. 이 PC에서 5번 모두 멈췄다. 멈춘 스레드가 있어도 main에서 돌아오면 C 런타임이 ExitProcess를 불러 그 스레드까지 함께 끝낸다.

    문제 2. 문제 1의 t2를 t1과 같은 순서(A 다음 B)로 바꾸면?

    #include <stdio.h>
#include <windows.h>

CRITICAL_SECTION A, B;

DWORD WINAPI worker(LPVOID arg) {
    (void)arg;
    EnterCriticalSection(&A);       /* 두 스레드 모두 A, B 순서 */
    Sleep(10);
    EnterCriticalSection(&B);
    LeaveCriticalSection(&B);
    LeaveCriticalSection(&A);
    return 0;
}

int main(void) {
    InitializeCriticalSection(&A);
    InitializeCriticalSection(&B);
    HANDLE t[2] = { CreateThread(NULL, 0, worker, NULL, 0, NULL), CreateThread(NULL, 0, worker, NULL, 0, NULL) };
    DWORD r = WaitForMultipleObjects(2, t, TRUE, 2000);
    printf("%s\n", r == WAIT_TIMEOUT ? "stuck" : "done");
    return 0;
}
    정답과 해설

    done. 먼저 A를 잡은 스레드가 B까지 잡고 다 풀 때까지, 다른 스레드는 A에서 기다린다. A를 쥐지 못한 스레드는 아무것도 쥐고 있지 않으므로 원이 생기지 않는다. 이 PC에서 5번 모두 끝났다.

    문제 3. 식사하는 철학자 다섯이 모두 "왼쪽 포크부터" 든다. 철학자 4 한 명만 "오른쪽 포크부터"로 바꾸면 교착이 생길 수 있을까?

    정답과 해설

    생기지 않는다. 포크 번호로 보면 철학자 4의 오른쪽은 0번이라, 한 명만 바꾼 규칙이 곧 "번호가 작은 포크부터"다. 원이 생기려면 다섯 모두 하나씩 쥐고 있어야 하는데, 철학자 4는 0번을 먼저 집어야 하므로 철학자 0과 0번을 다툰다. 둘 중 하나는 아무것도 쥐지 못해 원이 끊긴다. 위젯의 "번호가 작은 포크부터"로 확인할 수 있다.

    직접 해보기¶

    실습: 계좌마다 잠금을 두기

    1. 34번(스레드 동기화)의 실습 3을 계좌마다 잠금을 하나씩 두도록 바꾼다. transfer(from, to)는 from의 잠금, to의 잠금 순서로 잡는다. 스레드 하나는 0번에서 1번으로, 다른 하나는 1번에서 0번으로 1씩 10만 번 옮기고, 5초 안에 끝나지 않으면 stuck을 찍는다.
    2. 계좌 번호가 작은 쪽의 잠금을 먼저 잡도록 고쳐, 늘 1000 1000이 나오게 한다.
    정답

    1을 실행하면 이 PC에서 5번 모두 stuck이었다. 잡는 사이에 쉬지 않아도 10만 번 중 언젠가는 두 스레드가 첫 잠금을 하나씩 쥔다. 2는 잠그는 순서만 바꾼다.

    #include <stdio.h>
#include <windows.h>

struct account { int id; int balance; CRITICAL_SECTION lock; };
struct account acc[2];

void transfer(struct account *from, struct account *to) {
    struct account *first = from, *second = to;
    if (from->id > to->id) { first = to; second = from; }   /* 번호가 작은 계좌부터 잠근다 */
    EnterCriticalSection(&first->lock);
    EnterCriticalSection(&second->lock);
    from->balance -= 1;
    to->balance += 1;
    LeaveCriticalSection(&second->lock);
    LeaveCriticalSection(&first->lock);
}

DWORD WINAPI zero_to_one(LPVOID arg) { (void)arg; for (int i = 0; i < 100000; i++) transfer(&acc[0], &acc[1]); return 0; }
DWORD WINAPI one_to_zero(LPVOID arg) { (void)arg; for (int i = 0; i < 100000; i++) transfer(&acc[1], &acc[0]); return 0; }

int main(void) {
    for (int i = 0; i < 2; i++) { acc[i].id = i; acc[i].balance = 1000; InitializeCriticalSection(&acc[i].lock); }
    HANDLE t[2] = { CreateThread(NULL, 0, zero_to_one, NULL, 0, NULL), CreateThread(NULL, 0, one_to_zero, NULL, 0, NULL) };
    if (WaitForMultipleObjects(2, t, TRUE, 5000) == WAIT_TIMEOUT)
        printf("stuck\n");
    else
        printf("%d %d\n", acc[0].balance, acc[1].balance);
    return 0;
}

    1000 1000

    AI와 함께 확인하기¶

    AI 활용 과제: 계좌마다 잠금이 있는 이체 함수

    1. AI에게 "계좌 구조체마다 잠금이 있을 때, 두 계좌 사이에 돈을 옮기는 스레드 안전한 C(Windows) transfer(from, to, amount) 함수"를 짜 달라고 한다.
    2. 실습의 시험(서로 반대 방향으로 10만 번)과 transfer(&a, &a, 1)(같은 계좌끼리)을 돌리기 전에 결과를 예측한다.
    3. 실행해 대조하고, 멈추는 경우가 있으면 그 시험을 보여 주고 고치게 한다.
    확인할 점
    • from부터 잠그는 답은 반대 방향 이체가 동시에 일어나면 멈춘다. 계좌 번호나 주소로 순서를 정하는지 본다.
    • 같은 계좌끼리 옮기면 같은 잠금을 두 번 잡는다. 이 PC에서 CRITICAL_SECTION은 같은 스레드가 두 번 잡아도 그대로 진행했지만, SRWLOCK은 두 번째에서 영원히 멈췄다. 자기 자신을 기다리는 교착이다. from == to를 먼저 처리하는지 본다.
    • "타임아웃을 두면 교착이 해결된다"는 설명은 반만 맞다. 멈춘 것을 알아챌 수는 있지만, 쥔 잠금을 내려놓고 다시 하는 코드가 있어야 풀린다.

    더 알아보기¶

    교재에서 쓰는 이름: 예방, 회피, 탐지와 복구

    운영체제 교재는 교착에 맞서는 방법을 넷으로 나눈다. 이 항목의 방법(순서 정하기, 못 잡으면 내놓기)처럼 네 조건 가운데 하나를 미리 깨는 것이 예방이다. 회피는 자원을 내줄 때마다 앞으로 교착이 생길 수 있는지 따져 보고, 위험하면 기다리게 하는 것이다. 은행원 알고리즘이 대표인데, 각 스레드가 앞으로 필요한 자원을 미리 알아야 해서 보통의 프로그램에서는 거의 쓰지 않는다. 탐지와 복구는 아래 데이터베이스처럼 생긴 뒤에 찾아서 푸는 것이고, 무시는 드물다고 보고 그냥 두는 것이다. 문제 1처럼 Windows도 프로그램이 잠금을 잘못 잡아 생긴 교착은 막아 주지 않는다.

    탐지하고 되돌리기

    데이터베이스는 교착을 막기보다 생기면 찾아서 푼다. 사용자가 마음대로 짜는 질의가 많아 잠그는 순서를 미리 정하기 어렵기 때문이다(53번(트랜잭션과 락)). 누가 누구를 기다리는지 그래프를 그려 원이 보이면, 그 원에 든 트랜잭션 하나를 골라 취소하고 처음 상태로 되돌린다. 취소된 쪽은 오류를 받고(SQL Server는 1205번), 응용 프로그램이 다시 시도한다. 쥔 것을 내려놓고 다시 하는 방법은 둘이 같은 박자로 물러났다가 다시 부딪치기를 되풀이할 수 있다(라이브락). 물러나는 시간을 무작위로 다르게 하는 이유다.

    이 항목의 측정 프로그램

    1절과 2절의 결과는 이 PC(Core i9-14900KF, Windows 11)에서 아래 프로그램을 기본 옵션(cl)으로 빌드해 방법마다 5번 실행한 것이다. 인자 0은 서로 반대 순서, 1은 같은 순서, 2는 못 잡으면 내놓고 다시 하기다. 출력의 둘째 수는 물러선 횟수다.

    /* 35번 측정: 잠금 둘을 잡는 방법에 따라 2초 안에 끝나는지 (usage: dead.exe <0|1|2>) */
#include <stdio.h>
#include <windows.h>

static CRITICAL_SECTION A, B;
static int mode;
static volatile LONG retries;

static void lock_two(CRITICAL_SECTION *first, CRITICAL_SECTION *second) {
    for (;;) {
        EnterCriticalSection(first);
        Sleep(10);                                       /* 그사이 다른 스레드가 다른 잠금을 잡는다 */
        if (mode < 2) { EnterCriticalSection(second); return; }
        if (TryEnterCriticalSection(second)) return;     /* 둘 다 잡았다 */
        LeaveCriticalSection(first);                     /* 못 잡으면 쥔 것을 내놓는다 */
        InterlockedIncrement(&retries);
        Sleep(1);                                        /* 물러났다가 다시 */
    }
}

static DWORD WINAPI t1(LPVOID arg) {
    (void)arg;
    lock_two(&A, &B);
    LeaveCriticalSection(&B); LeaveCriticalSection(&A);
    return 0;
}

static DWORD WINAPI t2(LPVOID arg) {
    (void)arg;
    if (mode == 1) lock_two(&A, &B); else lock_two(&B, &A);
    LeaveCriticalSection(&A); LeaveCriticalSection(&B);
    return 0;
}

int main(int argc, char **argv) {
    mode = argc > 1 ? argv[1][0] - '0' : 0;
    InitializeCriticalSection(&A);
    InitializeCriticalSection(&B);
    HANDLE t[2] = { CreateThread(NULL, 0, t1, NULL, 0, NULL), CreateThread(NULL, 0, t2, NULL, 0, NULL) };
    DWORD r = WaitForMultipleObjects(2, t, TRUE, 2000);    /* 2초 안에 끝나는지 */
    printf("%s %ld\n", r == WAIT_TIMEOUT ? "stuck" : "done", retries);
    return 0;
}

    정리¶

    • 두 스레드가 서로 상대가 쥔 잠금을 기다리면 영원히 멈춘다. 오류 없이 그대로 멈춰 있다.
    • 교착은 상호 배제, 점유와 대기, 비선점, 순환 대기가 모두 있을 때 생기고, 하나만 깨면 생기지 않는다.
    • 가장 흔한 해결은 모든 잠금에 차례를 매겨 늘 같은 순서로 잡는 것이다. 못 잡으면 쥔 것을 스스로 내려놓는 방법도 있다.
