    95. AI 기능의 평가: 비결정적 출력의 테스트와 평가셋(evals) 구축¶

    직접 AI 없이 직접 할 수 있어야 하는 항목

    94번(AI를 소프트웨어에 결합하기)의 상담 AI에 문의를 배송, 배송비, 쿠폰, 환불, 교환으로 나누는 기능을 붙였다. 나눈 결과로 맞는 문서를 찾아 넣거나 담당자에게 넘긴다. 몇 번 물어보니 잘 나눈다. 이제 내보내도 될까? 프롬프트를 고친 새 판이 더 나은지는 어떻게 알까? AI 기능은 같은 입력에도 답이 흔들리므로(93번(LLM의 동작 원리)), assertEqual 하나로 끝나는 보통의 테스트로는 답할 수 없다. 이 항목에서는 실행마다 답이 흔들리는 흉내 낸 분류 기능으로 평가셋(evals)을 직접 만들고 돌린다.

    이 항목에서 배우는 것¶

    • AI 기능을 사례 여러 개로 여러 번 돌려 통과 비율로 재고, 사례 수가 적을 때 점수가 얼마나 흔들리는지 설명할 수 있다.
    • 사례와 채점 규칙으로 평가셋을 만들고, 할 수 있는 채점은 코드로 짤 수 있다.
    • 판을 바꿀 때마다 같은 평가셋으로 사례별로 견주고, 실패한 일을 사례로 더할 수 있다.

    1. 한 번 돌려 본 것은 평가가 아니다¶

    직접 해 보기사례가 적으면 점수가 흔들린다평가셋의 사례 수와 B의 실제 실력을 바꾸고 평가를 여러 번 돌려, 잰 통과율이 얼마나 흔들리는지, 나아지지 않은 판이 나아 보이거나 나아진 판이 못해 보일 확률이 얼마인지 본다
    새 창에서 크게 열기
    • AI 기능은 같은 입력에도 답이 흔들리고, 사용자는 처음 보는 질문을 한다. 그래서 사례(입력과 기대하는 답의 짝, 테스트 케이스와 같다) 여러 개를 여러 번 돌려 통과한 비율로 잰다.
    • 그 비율도 흔들린다. 사례가 적으면 나아지지 않은 판이 나아 보이고, 나아진 판이 못해 보인다(문제 1). 사례를 늘리고, 두 판의 차이가 흔들림보다 큰지 본다.

    2. 평가셋은 사례와 채점 규칙의 묶음이다¶

    • 사례는 실제로 들어올 입력과 기대(정답, 또는 지켜야 할 성질)의 짝이다. 쉬운 것만 넣지 말고 애매한 것과 틀렸던 것을 넣는다.
    • 무엇을 통과로 볼지 정한 것이 채점 규칙이고, 그것을 코드로 옮긴 것이 채점기다. 채점은 할 수 있으면 코드로 한다. JSON으로 답했는지, 분류가 맞는지는 코드가 빠르고 정확하게 가른다. 맞는 꼴이 여럿인 글은 모델이나 사람이 채점하되, 그 채점부터 믿을 만한지 시험한다.

    3. 판을 바꿀 때마다 같은 평가셋으로, 사례별로 견준다¶

    • 전체 점수가 올라도 어떤 사례는 망가질 수 있다(실습). 테스트처럼 바꿀 때마다 돌리고(84번(테스트 설계), 89번(CI/CD)), 사례별로 보며, 새로 찾은 실패는 사례로 더한다.
    • 채점 규칙이 무엇을 좋게 볼지 정한다. 틀린 답과 "모른다"를 어떻게 다르게 칠지가 그 예다(문제 2, 93번(LLM의 동작 원리)).

    예측해 보기¶

    문제 1. B가 A보다 실제로 5%p 낫다고 하자(85%와 80%). 사례 10개로 한 번씩 재면 B의 점수가 A보다 높게 나올 확률은 얼마일까? 300개면? 위젯은 B가 90%로 시작하므로, 답을 적은 뒤 85%를 눌러 확인한다.

    from math import comb


def pmf(n, p):                                   # 사례 n개 가운데 k개를 통과할 확률: k개를 고르는 가짓수 × 그렇게 될 확률
    return [comb(n, k) * p ** k * (1 - p) ** (n - k) for k in range(n + 1)]


def b_wins(n, pa, pb):                           # B의 통과 수가 A보다 많을 확률
    a, b = pmf(n, pa), pmf(n, pb)
    return round(sum(a[i] * b[j] for i in range(n + 1) for j in range(i + 1, n + 1)), 3)


print(b_wins(10, 0.8, 0.85), b_wins(300, 0.8, 0.85))
    정답과 해설

    0.499 0.941. 사례 10개로는 나은 판이 이길 확률이 절반뿐이다. 나머지 절반은 두 판이 같게 나오거나(22.8%) A가 더 높게 나온다(27.4%). 300개로 늘려야 94.1%가 된다. 두 판의 실력이 똑같아도 10개로 재면 38.8%는 B가 높게 나온다(위젯에서 B를 80%로). "새 프롬프트로 몇 개 돌려 보니 더 좋았다"는 이 정도로 흔들리는 근거다. 이 계산은 사례마다, 그리고 A와 B 사이에서도 통과 여부가 따로 정해지고, 모든 사례의 어려움이 같다고 본 것이다. 실제로는 사례마다 어려움이 다르다. 같은 사례로 두 판을 견주면 사례의 쉽고 어려움이 두 판에 똑같이 걸려 상쇄되므로 흔들림이 줄지만, 실행마다 흔들리는 몫은 남는다.

    문제 2. 질문 10개에 판 P는 6개를 맞히고 4개를 틀렸다(모를 때도 찍는다). 판 Q는 5개를 맞히고 5개는 "모른다"고 했다. 맞으면 1점일 때, 틀려도 0점인 채점과 틀리면 1점을 빼는 채점에서 각각 누가 이길까?

    def score(answers, penalty=0):                   # 맞으면 1점, "모른다"는 0점, 틀리면 penalty점을 뺀다
    return answers.count("맞음") - penalty * answers.count("틀림")


p = ["맞음"] * 6 + ["틀림"] * 4                  # P: 모를 때도 찍는다
q = ["맞음"] * 5 + ["모름"] * 5                  # Q: 모르면 모른다고 한다
print(score(p), score(q))
print(score(p, 1), score(q, 1))
    정답과 해설 
    6 5
2 5

    틀려도 0점이면 P, 틀리면 1점을 빼면 Q가 이긴다. 맞힌 수만 세는 채점에서는 찍는 쪽이 손해를 보지 않으니, 그 점수를 올리도록 고친 AI 기능은 모를 때도 그럴듯하게 답하게 된다. 상담 AI가 없는 규정을 지어내 안내하면 "모른다, 상담원에게 넘긴다"보다 나쁘다. 그 손해를 점수에 넣어야 평가가 바라는 쪽을 가리킨다. 93번(LLM의 동작 원리)의 "모른다고 답하게 하려면"에서 본 논문(Kalai 외, 2025)은 "확신이 t보다 클 때만 답하라. 틀리면 t/(1−t)점을 뺀다"처럼 벌점을 문제에 밝히자고 하는데, 1점을 빼는 채점은 t = 0.5인 경우다.

    직접 해보기¶

    실습: 문의 분류 기능의 평가셋 만들기

    아래 fake_ai.py가 문의 분류 기능을 흉내 낸다. 실제로는 AI API를 부르는 자리이고, 같은 질문에도 실행마다 답이 흔들린다. 평가하는 쪽은 안을 모른다고 치고, classify(질문, 판, seed)가 돌려주는 글만 본다. seed(난수의 시드)는 같은 실행을 다시 만들어 결과를 대조하려고 둔 것이다.

    1. fake_ai.py와 evals.py를 같은 폴더에 저장하고 python -i evals.py로 연다. evaluate("v1", 1)로 사례마다 한 번씩 돌린다. 이 결과로 "정확도 89%"라고 해도 될까?
    2. evaluate("v1", 20)으로 사례마다 20번 돌린다. 어느 사례가 흔들리고, 어느 사례가 거의 늘 틀리는가?
    3. 3절 그림의 결과를 직접 재현한다. 프롬프트를 고친 새 판을 evaluate("v2", 20)으로 잰다. v1과 전체 점수, 사례별 점수를 견준다. 나빠진 사례는 classify의 답을 직접 모아 무엇으로 틀렸는지 본다. v2를 내보내도 될까?
    4. 고객 문의 기록에서 "FREESHIP은 언제까지 써요?"가 배송 문의로 분류되어 잘못 안내된 일을 찾았다. 이 사례를 평가셋에 더하고 두 판으로 돌린다.
    fake_ai.py: 흉내 낸 AI 기능(안은 평가를 마친 뒤에 본다) 

    # fake_ai.py: 실제 AI 대신 쓰는 흉내 낸 "문의 분류" 기능. 같은 질문에도 실행마다 답이 흔들린다
# classify(질문, 판, seed)는 AI가 낸 글을 돌려준다. seed를 주면 그 실행을 다시 만들 수 있다(평가를 되풀이해 확인하려고)
import random

         ("배송비", "배송비"), ("며칠", "배송"), ("언제", "배송")]
NOISE = {"v1": 0.10, "v2": 0.05}                 # 엉뚱한 분류를 낼 확률

def classify(question, version="v1", seed=None):
    rng = random.Random(seed)
    r_format, r_noise, r_pick, r_swap = rng.random(), rng.random(), rng.random(), rng.random()
    label = next((lab for word, lab in HINTS if word in question), None)
    if label is None:                            # 실마리가 없으면 아무거나 고른다
        label = LABELS[int(r_pick * len(LABELS))]
    elif r_noise < NOISE[version]:               # 가끔 엉뚱한 분류
        others = [lab for lab in LABELS if lab != label]
        label = others[int(r_pick * len(others))]
    if version == "v2" and label == "교환" and r_swap < 0.4:
        label = "환불"                            # v2에서 바뀐 동작
    if r_format < FORMAT_SLIP[version]:
        return f"이 문의는 {label} 문의입니다."
    return '{"분류": "' + label + '"}'

import json
from collections import Counter

from fake_ai import classify

CASES = [                                        # (질문, 기대하는 분류)
    ("환불은 며칠 안에 신청해야 하나요?", "환불"),
    ("제주도는 며칠 걸려요?", "배송"),
    ("쿠폰 두 개를 같이 쓸 수 있나요?", "쿠폰"),
    ("주문한 옷이 작아서 돈으로 돌려받고 싶어요", "환불"),
    ("3만 원 넘게 사면 배송비가 없나요?", "배송비"),
    ("빨간색으로 바꾸고 싶어요", "교환"),
    ("교환 신청은 어디서 하나요?", "교환"),
    ("어제 주문했는데 언제 와요?", "배송"),
    ("WELCOME10은 몇 % 깎아 줘요?", "쿠폰"),
]


def grade(answer, expected):                     # 채점: JSON으로 답했나, 분류가 기대와 같은가
    try:
        label = json.loads(answer)["분류"]
    except (json.JSONDecodeError, KeyError, TypeError):
        return "형식"
    return "통과" if label == expected else "틀림"


def evaluate(version, trials, cases=CASES):      # 사례마다 trials번 돌린다. seed로 같은 실행을 다시 만들 수 있다
    total = Counter()
    for i, (question, expected) in enumerate(cases):
        got = Counter(grade(classify(question, version, seed=i * 1000 + t), expected) for t in range(trials))
        total += got
        print(f"{got['통과']:2}/{trials} 형식 {got['형식']} 틀림 {got['틀림']}  {question}")
    print(f"전체 {total['통과']}/{len(cases) * trials}")

    AI와 함께 확인하기¶

    AI 활용 과제: AI가 짠 채점기 검토하기

    1. AI에게 "문의 분류 기능의 답을 채점하는 Python 함수를 짜 줘. 답은 {"분류": "환불"} 같은 JSON이고, 기대한 분류와 같으면 통과다"라고 한다.
    2. 받은 채점기를 실행하기 전에, 아래 답들을 넣으면 무엇이 나올지 먼저 적는다: '{"분류": "환불"}', '{"분류": " 환불"}', '이 문의는 환불 문의입니다.', '{"분류": "환불", "이유": "돈을 돌려받고 싶다고 했다"}', '["환불"]', ''.
    3. 실행해 예측과 견주고, 채점기가 틀리게 통과시키거나 멈추는 답이 있으면 근거와 함께 AI에게 고치게 한다.
    확인할 점
    • 실습의 grade로 넣어 보면 첫째와 넷째가 통과, 둘째가 틀림(앞에 빈칸), 셋째, 다섯째, 여섯째가 형식이다. 다섯째(["환불"])는 JSON이지만 목록이라 ["분류"]에서 TypeError가 나고, 여섯째(빈 글)는 JSONDecodeError가 난다. 이것들을 잡지 않은 채점기는 평가 도중 멈춘다.
    • 둘째처럼 빈칸이 붙은 답을 통과로 볼지는 채점 규칙으로 정할 일이다. 프로그램이 그 값을 그대로 쓴다면 틀림이 맞다. 채점기가 너그러우면 점수가 실제보다 좋아 보인다.
    • 기대한 분류가 글 안에 있는지만 보는 채점기(expected in answer)는 둘째, 셋째, 다섯째도 통과시킨다. 채점기도 맞는 답과 틀린 답을 넣어 먼저 시험한다(2절 그림).

    더 알아보기¶

    모델로 채점하기

    요약이나 상담 답처럼 맞는 꼴이 여럿인 답은 코드로 채점하기 어렵다. 그래서 채점 기준을 적어 주고 다른 LLM에게 채점하게 하는 일이 많다. 빠르고 유연하지만, 채점하는 모델도 흔들리고 틀린다(93번(LLM의 동작 원리)). 사람이 채점한 사례 몇십 개와 견주어 두 채점이 얼마나 맞는지 먼저 재고, 채점 기준은 "좋은가" 대신 "규정에 없는 내용을 지어냈는가"처럼 확인할 수 있는 말로 쓴다. Anthropic의 문서는 코드 채점이 가장 빠르고 믿을 만하며, 조금 덜 정확해도 자동으로 채점한 많은 사례가 사람이 손으로 채점한 적은 사례보다 낫다고 적는다.

    평가셋을 어디에 두고 언제 돌리나

    평가셋도 코드와 함께 저장소에 두고 판을 매긴다(83번(Git 실천)). 프롬프트, 모델, RAG의 문서, 채점기 가운데 무엇을 바꾸든 같은 평가셋으로 돌려 사례별 결과를 남긴다. 돌릴 때마다 돈과 시간이 드는 AI 기능은 빠른 일부만 커밋마다(89번(CI/CD)) 돌리고, 전체는 내보내기 전에 돌리기도 한다. 실제 사용 기록(72번(관측성))에서 실패를 찾아 사례로 더하면 평가셋이 실제 사용자를 닮아 간다.

    정리¶

    • AI 기능은 사례 여러 개를 여러 번 돌려 통과 비율로 잰다. 사례가 적으면 점수가 흔들려, 나아졌는지 가를 수 없다.
    • 평가셋은 사례(입력과 기대)와 채점 규칙의 묶음이다. 채점은 할 수 있으면 코드로 하고, 채점기도 시험한다.
    • 판을 바꿀 때마다 같은 평가셋으로 사례별로 견주고, 찾은 실패는 사례로 더한다. 채점 규칙이 무엇을 좋게 볼지 정한다.
