    93. AI·머신러닝·딥러닝의 구조와 LLM의 동작 원리: 왜 그럴듯하게 틀리는가(환각, 비결정성)¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    AI 도구는 코드를 짜 주고 질문에 막힘없이 답한다. 그런데 없는 함수를 지어내기도 하고, 같은 질문에 매번 다르게 답하기도 한다. 이 항목은 LLM이 글을 만드는 방식을 아주 작은 모델로 돌려 보며, 왜 그럴듯하게 틀리고 왜 답이 매번 다른지 예측해 본다. 실제 LLM은 쓰지 않는다. 모델은 Python 표준 라이브러리로 짠 서른 줄쯤이다.

    이 항목에서 배우는 것¶

    • AI, 머신러닝, 딥러닝, LLM이 어떤 포함 관계인지와 머신러닝의 학습이 무엇을 하는지 설명할 수 있다.
    • LLM이 다음 토큰의 확률을 계산해 하나씩 고르는 과정과, 온도가 그 확률을 어떻게 바꾸는지 예측할 수 있다.
    • 그럴듯한 문장과 맞는 문장이 왜 다른지(환각) 설명할 수 있다.

    1. 머신러닝은 규칙을 데이터에서 배우고, LLM은 다음 토큰 맞히기를 배운다¶

    • 머신러닝은 규칙을 사람이 쓰지 않는다. 예시를 넣어 예측하고, 정답과 견주고, 틀린 만큼 숫자(매개변수)를 고치기를 되풀이한다. 딥러닝은 여러 층으로 쌓은 신경망을 쓰는 머신러닝이고, 고칠 숫자가 아주 많다.
    • LLM(대규모 언어 모델)은 엄청난 양의 글로 "앞의 글을 보고 다음 토큰(낱말이나 낱말 조각)을 맞히기"를 먼저 학습한 딥러닝 모델이다. 이 첫 학습을 사전 학습이라 한다. 그 뒤 대화에 맞게 더 다듬지만, 글을 만드는 방식은 그대로 다음 토큰을 하나씩 고르는 것이다.

    2. LLM은 다음 토큰의 확률을 계산하고, 그 확률대로 하나를 뽑는다¶

    직접 해 보기다음 낱말을 확률로 고른다시작 낱말과 온도를 고르고 '다음 낱말 고르기'나 '100번 만들기'를 눌러, 다음 낱말의 확률과, 사실과 맞고 틀린 문장이 얼마나 나오는지 본다
    새 창에서 크게 열기
    • 다음에 올 수 있는 토큰마다 확률을 매기고, 하나를 뽑아 붙이고, 늘어난 글로 다시 다음을 계산한다. 위젯의 모델은 앞 낱말 하나만 보고, 학습 글(모델이 배운 글. 흔히 학습 데이터라 한다)에서 센 횟수로 확률을 정한다. LLM은 앞의 글을 정해진 길이까지 길게 보고 신경망으로 확률을 계산한다는 점이 다르지만, 하나씩 뽑아 잇는 방식은 같다.
    • 확률대로 뽑으므로 같은 질문에도 답이 달라진다(비결정성). 온도는 확률을 얼마나 고르게 펼지 정하는 값이다. 낮추면 높은 확률 쪽으로 쏠리고, 0이면 늘 가장 높은 것을 골라 같은 답을 낸다(문제 2). 원리상 그렇고, 실제 서비스는 온도 0에서도 답이 달라질 수 있다(더 알아보기).

    3. 그럴듯한 것과 맞는 것은 다르다¶

    • 모델은 본 조각을 이어 붙여 학습 글에 없던 문장도 만든다. 맞으면 일반화, 틀리면 환각이라 부르지만 모델에게는 같은 일이다. 모델 안에는 사실인지 따지는 단계가 없다. 검색 같은 확인은 모델 밖에 붙인다(94번(AI를 소프트웨어에 결합하기)).
    • 자주 본 말이 드물게 본 사실을 이긴다(문제 1, 3). 그리고 LLM은 늘 무언가를 고르므로 모를 때도 답하기 쉽다(더 알아보기). 그래서 LLM의 답은 확인할 거리이지, 그대로 믿을 사실이 아니다(97번(AI 출력 검증)).

    예측해 보기¶

    문제는 위젯과 같은 모델을 Python으로 짠 next_word.py로 푼다. 파일로 저장해 python -i next_word.py로 실행하면 >>> 뒤에 문제의 코드를 이어 칠 수 있다.

    # next_word.py: 학습 글에서 낱말 다음에 온 낱말을 세고, 그 횟수로 다음 낱말을 고른다(아주 작은 언어 모델)
import random
from collections import Counter, defaultdict

TEXT = [("서울은 한국의 수도다 .", 2), ("서울은 한국의 가장 큰 도시다 .", 1),
        ("도쿄는 일본의 수도다 .", 2), ("오사카는 일본의 큰 도시다 .", 1),
        ("오타와는 캐나다의 수도다 .", 1), ("토론토는 캐나다의 가장 큰 도시다 .", 3)]   # (문장, 나온 횟수)

follow = defaultdict(Counter)                    # follow["캐나다의"]["가장"]: "캐나다의" 다음에 "가장"이 나온 횟수
for sentence, n in TEXT:
    words = sentence.split()
    for a, b in zip(words, words[1:]):
        follow[a][b] += n


def probs(word, temp=1.0):                       # 다음 낱말의 확률. 온도가 낮을수록 많이 본 낱말로 쏠린다
    counts = follow[word]
    if temp == 0:                                # 온도 0: 가장 많이 본 낱말 하나만 고른다
        return {max(counts, key=counts.get): 1.0}
    weight = {w: c ** (1 / temp) for w, c in counts.items()}
    total = sum(weight.values())
    return {w: round(x / total, 3) for w, x in weight.items()}


def generate(start, temp=1.0):                   # 마침표가 나올 때까지 다음 낱말을 하나씩 고른다
    words = [start]
    while words[-1] != ".":
        p = probs(words[-1], temp)
        words.append(random.choices(list(p), weights=list(p.values()))[0])
    return " ".join(words)

    문제 1. 3절 그림에서 "오타와는"으로 시작한 문장은 75%가 사실과 틀렸다. 학습 글에는 맞는 말만 있는데 왜일까? probs("캐나다의")가 찍을 값을 학습 글에서 세어 먼저 적어 본다.

    print(probs("캐나다의"))
    정답과 해설

    {'수도다': 0.25, '가장': 0.75}. 학습 글에서 "캐나다의" 다음에 "수도다"는 오타와 문장에서 1번, "가장"은 토론토 문장에서 3번(그 문장이 3번 나왔다) 나왔다. 모델은 앞 낱말 "캐나다의"만 보므로 앞이 오타와인지 토론토인지 모른다. 그래서 오타와로 시작한 문장의 75%가 "오타와는 캐나다의 가장 큰 도시다 ."로 틀린다. 학습 글에는 맞는 말만 있었는데도 그렇다. 드물게 나온 사실(오타와가 수도)이 자주 나온 말(캐나다의 가장 큰 도시)에 밀렸다. 실제로 1,000번 만들어 보면 이 PC의 Python 3.14에서 다음과 같았다.

    random.seed(93)
print(Counter(generate("오타와는") for _ in range(1000)))

    Counter({'오타와는 캐나다의 가장 큰 도시다 .': 745, '오타와는 캐나다의 수도다 .': 255})

    문제 2. 온도를 0.5와 0으로 낮추면 오타와 문장은 더 잘 맞을까?

    print(probs("캐나다의", 0.5))
print(probs("캐나다의", 0))
    정답과 해설 
    {'수도다': 0.1, '가장': 0.9}
{'가장': 1.0}

    더 자주 틀린다. 온도를 낮추면 이미 높은 쪽("가장")으로 더 쏠려 틀릴 확률이 90%가 되고, 0이면 늘 "가장"을 골라 몇 번을 만들어도 틀린다. 온도 0은 답을 늘 같게 만들 뿐, 맞게 만들지는 않는다. 온도를 2로 높이면 {'수도다': 0.366, '가장': 0.634}로 덜 쏠린다(위젯에서는 37%, 63%). 온도는 답의 다양함을 정하는 손잡이이고, 어느 쪽도 사실 확인은 아니다. 실제 LLM은 후보마다 점수(로짓)를 내고 그 점수를 온도로 나누어 확률로 바꾼다. 점수를 log(횟수)로 보면, 확률은 exp(점수 ÷ 온도)에 비례하고 exp(log c ÷ T) = c^(1/T)이므로 next_word.py의 c ** (1 / temp)와 같은 계산이다.

    문제 3. 오타와 문장이 틀리지 않게, 학습 글에 "오타와는 캐나다의 수도다 ."를 3번 더 넣었다. 오타와 문장과 토론토 문장은 각각 어떻게 될까?

    follow["캐나다의"]["수도다"] += 3                 # "오타와는 캐나다의 수도다 ."를 3번 더 넣은 것과 같다
print(probs("캐나다의"))
    정답과 해설

    {'수도다': 0.571, '가장': 0.429}. 오타와 문장이 틀릴 확률은 75%에서 42.9%로 줄지만, 토론토 문장은 "토론토는 캐나다의 수도다 ."로 틀릴 확률이 25%에서 57.1%로 는다. 앞 낱말 하나만 보는 모델은 두 도시를 가를 수 없어서, 한쪽을 고치면 다른 쪽이 틀린다. LLM은 앞의 글을 길게 보므로 "토론토는"을 놓치지 않고 다음을 고른다(실습). 그래도 같은 원리는 남는다. 학습 글에 드물게 나온 사실일수록 비슷한 자리에 자주 나온 말에 밀리기 쉽다.

    직접 해보기¶

    실습: 앞 낱말을 둘 보게 고치기

    1. 위젯에서 다섯 도시로 각각 "100번 만들기"를 누르고, 사실과 틀린 문장이 몇 번 나오는지 적는다. 온도 0에서도 해 본다.
    2. next_word.py에 앞 낱말 두 개를 보고 다음 낱말을 고르는 generate2를 더한다(follow2["오타와는", "캐나다의"]["수도다"]처럼 센다). "오타와는 캐나다의"와 "토론토는 캐나다의"로 시작해 각각 100번 만들고, 틀린 문장을 센다.
    3. 학습 글에 없는 "몬트리올은 캐나다의"로 시작하면 어떻게 되는지 본다.
    확인할 점

    1단계: 온도 1에서 틀린 문장은 오사카 67%, 오타와 75%, 토론토 25%의 확률로 나온다. 100번이라 그 근처에서 누를 때마다 달라진다. 서울과 도쿄는 틀린 문장이 나오지 않는다. 온도 0에서는 오사카와 오타와가 100번 모두 틀린다.

    2단계의 한 예다. 문제 3에서 바꾼 follow는 쓰지 않고, TEXT에서 새로 센다.

    follow2 = defaultdict(Counter)                   # follow2["오타와는", "캐나다의"]["수도다"]: 앞 두 낱말 다음에 나온 횟수
for sentence, n in TEXT:
    words = sentence.split()
    for a, b, c in zip(words, words[1:], words[2:]):
        follow2[a, b][c] += n


def generate2(start):                            # start는 두 낱말이다: "오타와는 캐나다의"
    words = start.split()
    while words[-1] != ".":
        counts = follow2[words[-2], words[-1]]
        words.append(random.choices(list(counts), weights=list(counts.values()))[0])
    return " ".join(words)


random.seed(93)
for start in ["오타와는 캐나다의", "토론토는 캐나다의"]:
    print(Counter(generate2(start) for _ in range(100)))

    Counter({'오타와는 캐나다의 수도다 .': 100})
Counter({'토론토는 캐나다의 가장 큰 도시다 .': 100})
    • 2단계: 두 도시 모두 틀린 문장이 0번이다. "오타와는 캐나다의" 다음을 본 학습 글은 오타와 문장 하나뿐이다. 앞을 길게 볼수록 본 것을 더 잘 지킨다.
    • 3단계: generate2("몬트리올은 캐나다의")는 IndexError로 멈춘다. 그 두 낱말 다음을 본 적이 없어 고를 낱말이 하나도 없다. LLM은 이럴 때 멈추지 않는다. 비슷한 글에서 배운 확률로 늘 무언가를 고르므로, 모르는 것도 그럴듯하게 이어 쓴다. 앞을 길게 보면 아는 것을 더 잘 지키지만, 모르는 것을 모른다고 말하게 되지는 않는다.

    AI와 함께 확인하기¶

    AI 활용 과제: 같은 질문을 여러 번, 지어낼 만한 질문으로

    1. AI 도구에서 새 대화를 열어 "Python 표준 라이브러리 statistics 모듈의 trimmed_mean 함수 쓰는 법을 예제와 함께 알려 줘"라고 묻는다. 새 대화로 세 번 묻고 답을 견준다.
    2. 답을 믿기 전에 python -c "import statistics; print(hasattr(statistics, 'trimmed_mean'))"로 그 함수가 있는지 확인한다.
    3. 같은 대화에서 "그 함수가 정말 있는지 확인할 방법을 알려 줘"라고 묻고, 그 방법이 무엇에 기대는지 본다.
    확인할 점
    • 2단계는 이 PC의 Python 3.14.0에서 False였다. statistics에는 trimmed_mean이 없다. AI가 없다고 바로 말했다면 잘 답한 것이고, 사용법과 결과까지 그럴듯하게 써 주었다면 3절의 환각이다. 이름이 그럴듯할수록(평균, 중앙값 함수가 모인 모듈에 있을 법한 이름) 지어낸 답도 그럴듯하다.
    • 세 번의 답이 서로 다르면 2절의 비결정성이다. 세 번 모두 같아도 맞다는 보장은 아니다(문제 2).
    • 확인은 AI 밖에서 한다. 공식 문서, help(statistics), 실제 실행이 근거다. AI에게 "확실해?"라고 다시 묻는 것은 확인이 아니다.

    더 알아보기¶

    이 모델은 세기만 해도 학습이다

    next_word.py는 학습 글을 세기만 했다. 그래도 이것이 학습이다. 앞 낱말 하나만 보는 모델 가운데서는, 다음 낱말의 확률을 이렇게 센 비율로 둘 때 학습 글이 나올 확률이 가장 커진다. LLM도 같은 목표, 곧 학습 글의 다음 토큰에 높은 확률을 주는 것을 목표로 학습한다. 다만 표에 세어 두는 대신, 신경망의 숫자를 오차가 줄도록 조금씩 고쳐 간다(1절 그림). 그래서 본 적 없는 글에도 비슷한 글에서 배운 확률을 매길 수 있다. 실습 3단계의 IndexError가 LLM에서는 일어나지 않는 까닭이다.

    토큰과 맥락

    LLM은 낱말이 아니라 토큰으로 글을 자른다. 자주 나오는 낱말은 토큰 하나, 드문 낱말은 여러 조각이 된다. 앞의 글을 볼 때는 정해진 수의 토큰까지만 본다. 이 범위를 맥락 창(context window)이라 한다. 위젯의 모델은 앞 낱말 하나, 실습의 generate2는 둘을 보았고, LLM은 그보다 훨씬 길게, 그리고 어느 토큰이 지금 중요한지 가려 가며 본다. 그래서 문제 3처럼 앞의 도시를 잊어서 생기는 틀림은 크게 준다.

    온도 0인데도 답이 달라질 때

    위젯과 next_word.py는 온도 0이면 늘 같은 문장을 낸다. 실제 서비스는 온도 0이어도 같은 입력에 다른 답을 낼 수 있다고 문서에 적는다(Anthropic 용어집). 확률 계산은 엄청난 양의 실수 덧셈인데, 실수 덧셈은 더하는 차례에 따라 끝자리가 달라진다. Python에서 (0.1 + 0.2) + 0.3은 0.6000000000000001, 0.1 + (0.2 + 0.3)은 0.6이다(4번(데이터 표현)). 서버가 여러 사람의 요청을 한꺼번에 묶어 계산할 때 그 묶음의 크기가 그때그때의 부하에 따라 바뀌고, 그러면 계산 차례가 바뀌어 거의 같은 두 후보의 순위가 뒤집힐 수 있다. Thinking Machines의 글은 이것을 서비스가 결정적이지 않은 주된 까닭으로 든다. 서비스에 따라서는 온도를 아예 바꾸지 못하게 막아 두기도 한다. Anthropic의 Messages API 문서는 Claude Opus 4.6 뒤에 나온 모델이 온도 1.0 말고는 받지 않는다고 적는다. 그래서 AI 기능을 시험할 때는 같은 입력을 여러 번 돌려 본다(95번(AI 기능의 평가)).

    모른다고 답하게 하려면

    LLM은 늘 무언가를 고르므로, "모른다"도 그렇게 답하도록 따로 가르쳐야 나온다. OpenAI 등의 연구진이 쓴 논문(Kalai 외, 2025)은 두 가지를 짚는다. 어떤 사람의 생일처럼 규칙 없이 외워야 하는 사실 가운데 20%가 학습 글에 딱 한 번만 나왔다면, 사전 학습만 마친 모델은 그런 사실 전체의 적어도 20%에서 지어낸다고 본다. 드물게 본 사실일수록 틀리기 쉽다는 문제 1, 3과 같은 이야기다. 그리고 널리 쓰는 평가가 대부분 맞으면 1점, 틀리거나 "모른다"면 0점이라, 모를 때도 찍는 모델이 점수를 더 받는다. 그래서 틀린 답은 감점하고 "모른다"는 0점으로 두되, 감점 크기를 문제에 미리 밝히도록 기존 평가의 채점을 바꾸자고 제안한다. 평가를 어떻게 채점하느냐가 모델의 버릇을 만든다는 이야기이고, 95번(AI 기능의 평가)에서 평가셋을 만들 때 다시 본다.

    정리¶

    • 머신러닝은 예시 데이터에 맞게 숫자를 고쳐 가며 배운다. LLM은 다음 토큰 맞히기를 배운 딥러닝 모델이고, 그 목표에는 사실인지가 없다.
    • LLM은 다음 토큰의 확률을 매겨 하나씩 뽑아 잇는다. 그래서 답이 매번 다를 수 있다. 온도는 많이 본 쪽으로 얼마나 쏠릴지를 정할 뿐, 많이 본 쪽이 맞는지는 정하지 않는다.
    • 본 조각을 이어 붙여 새 문장을 만들므로, 그럴듯하지만 틀린 문장(환각)이 맞는 문장과 같은 방법으로 나온다. LLM의 답은 확인하고 쓴다.
