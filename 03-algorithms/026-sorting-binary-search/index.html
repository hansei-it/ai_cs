    26. 정렬 알고리즘과 이진 탐색: 분할 정복과 O(log N)¶

    직접 AI 없이 직접 할 수 있어야 하는 항목

    정렬은 가장 많이 쓰는 알고리즘이다. 정렬해 두면 찾기가 O(n)에서 O(log n)으로 빨라지고, 중복 찾기(19번(알고리즘 효율성 분석))나 범위 찾기도 쉬워진다. 실무에서는 언어가 주는 정렬을 쓰지만, 방법에 따라 같은 입력에서 걸리는 시간이 왜 수십 배 차이 나는지, 반으로 나눠 푸는 "분할 정복"이 왜 빠른지는 직접 짜 봐야 안다. 직접형 항목이므로 삽입 정렬, 병합 정렬, 이진 탐색을 AI 없이 짜고 손으로 따라갈 수 있어야 한다. 예제는 Python이다.

    이 항목에서 배우는 것¶

    • 삽입·선택·병합·퀵 정렬이 비교하고 옮기는 방식을 설명하고, 입력 모양에 따라 비교 횟수가 어떻게 달라지는지 예측할 수 있다.
    • 분할 정복으로 병합 정렬이 O(n log n)이 되는 이유를 그림으로 설명할 수 있다.
    • 이진 탐색을 짜고, 경계(lo, hi)가 틀리는 실수를 찾을 수 있다.

    1. 정렬 방법에 따라 비교 횟수가 크게 다르다¶

    직접 해 보기정렬 비교정렬 방법과 처음 데이터 모양을 골라 실행하며, 막대가 자리를 찾아가는 모습과 비교 횟수를 네 가지 정렬로 비교한다
    새 창에서 크게 열기
    • 삽입 정렬은 앞쪽이 이미 정렬돼 있다고 보고, 다음 값을 알맞은 자리까지 한 칸씩 밀어 넣는다. 평균 O(n²)이지만 거의 정렬된 입력에서는 O(n)에 가깝다. 선택 정렬은 남은 것 중 가장 작은 값을 찾아 앞으로 보내기를 되풀이해서, 입력과 상관없이 늘 n(n−1)/2번 비교한다.
    • 병합 정렬과 퀵 정렬은 반으로 나눠 푼다. 병합 정렬은 입력과 상관없이 O(n log n)이다. 퀵 정렬은 평균 O(n log n)이지만, 기준값(피벗)을 늘 끝 값으로 고르면 이미 정렬된 입력에서 O(n²)이 된다.
    • 이 PC(Core i9-14900KF)의 Python 3.14로 8,000개를 정렬하면 삽입 정렬은 약 600ms, 병합 정렬은 약 8ms 걸렸다. 내장 sorted는 C로 짠 정렬이라 0.5~0.7ms였다. 실무에서는 sorted를 쓰고, 직접 짜는 것은 원리를 보기 위해서다.

    2. 반으로 나눠 정렬하고 합친다¶

    def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left = merge_sort(a[:mid])
    right = merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):   # 두 조각의 앞을 비교해 작은 쪽을 옮긴다
        if left[i] <= right[j]:
            out.append(left[i])
            i += 1
        else:
            out.append(right[j])
            j += 1
    out.extend(left[i:])                      # 남은 쪽은 그대로 붙인다
    out.extend(right[j:])
    return out

print(merge_sort([5, 2, 8, 1, 9, 3, 7, 4]))   # [1, 2, 3, 4, 5, 7, 8, 9]
    • 분할 정복은 문제를 같은 모양의 작은 문제로 나눠 풀고, 답을 합쳐 큰 문제의 답을 만든다. 병합 정렬은 반씩 나눠 한 칸이 될 때까지 내려간 뒤, 정렬된 두 조각을 앞에서부터 비교하며 합친다.
    • 합치는 일은 층마다 n개를 한 번씩 옮긴다. 층 수는 log₂n이라 전체 O(n log n)이다. 대신 합칠 때 n칸짜리 새 목록을 쓴다(공간 O(n), 19번(알고리즘 효율성 분석)).

    3. 정렬돼 있으면 반씩 버리며 찾는다¶

    def binary_search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1          # 오른쪽 반만 남긴다
        else:
            hi = mid - 1          # 왼쪽 반만 남긴다
    return -1

arr = [2, 5, 8, 12, 16, 23, 38, 45, 56, 72, 81, 90, 91, 95, 97, 99]
print(binary_search(arr, 72))   # 9
print(binary_search(arr, 70))   # -1
    • 이진 탐색은 남은 범위의 가운데 값과 비교해, 찾는 값이 있을 수 없는 반을 버린다. 비교 한 번마다 범위가 반이 되니 O(log n)이다. 정렬된 입력에서만 쓸 수 있다.
    • 이 PC에서 정렬된 100만 개에서 1,000번 찾는 데 선형 탐색(in)은 약 3초, 이진 탐색(bisect 모듈)은 1ms가 안 걸렸다.
    • lo <= hi, mid + 1, mid - 1 가운데 하나만 틀려도 값을 놓치거나 끝나지 않는다. 경계는 원소가 0개, 1개, 2개일 때로 확인한다.

    예측해 보기¶

    문제 1. 삽입 정렬이 비교하는 횟수를 센다. 무엇이 출력될까?

    def insertion_compares(a):
    a = a[:]
    count = 0
    for i in range(1, len(a)):
        x, j = a[i], i - 1
        while j >= 0:
            count += 1
            if a[j] > x:
                a[j + 1] = a[j]
                j -= 1
            else:
                break
        a[j + 1] = x
    return count

print(insertion_compares(list(range(1000))))
print(insertion_compares(list(range(1000, 0, -1))))
    정답과 해설 
    999
499500

    이미 정렬된 입력에서는 값마다 바로 앞과 한 번만 비교하고 멈춘다. 999번, O(n)이다. 거꾸로 된 입력에서는 값마다 앞의 모든 값을 지나야 해서 1 + 2 + … + 999 = 499,500번, O(n²)이다. 같은 알고리즘도 입력 모양에 따라 수백 배 차이가 난다. 위젯에서 "거의 정렬됨"과 "거꾸로"로 확인할 수 있다.

    문제 2. 정렬된 100만 개에서 없는 값(가장 큰 값보다 1 큰 값)을 이진 탐색으로 찾는다. while 반복이 몇 번 돌까?

    def count_steps(a, target):
    lo, hi, steps = 0, len(a) - 1, 0
    while lo <= hi:
        steps += 1
        mid = (lo + hi) // 2
        if a[mid] == target:
            return steps
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return steps

print(count_steps(list(range(1_000_000)), 1_000_000))
    정답과 해설

    20. 한 번 돌 때마다 범위가 반으로 준다. 2¹⁹ = 524,288 < 100만 < 2²⁰이라, 100만 → 50만 → … 으로 19번 돌고 나면 1칸이 남는다. 그 칸을 보는 20번째 반복 뒤에 범위가 비어 lo > hi가 되고 멈춘다. 선형 탐색이라면 100만 번을 다 봐야 없다는 것을 안다.

    직접 해보기¶

    실습: AI 없이 정렬과 탐색 짜기

    1. 삽입 정렬을 짜고, 무작위·정렬됨·거꾸로 된 입력에서 비교 횟수를 센다(문제 1의 함수에 정렬 결과도 돌려주게 고친다).
    2. 정렬된 목록에서 target 이상인 값이 처음 나오는 자리를 돌려주는 lower_bound를 짠다. 그런 값이 없으면 len(a)를 돌려준다. 표준 모듈의 bisect.bisect_left와 결과가 같은지 무작위 입력 1,000개로 비교한다.
    3. (이름, 점수) 목록을 점수가 높은 차례로, 점수가 같으면 이름 차례로 정렬한다. sorted의 key를 쓴다.
    정답

    예시. 1은 문제 1의 함수가 정렬한 목록도 함께 돌려주게 했다. 2는 찾는 값과 같아도 왼쪽으로 계속 가야 "처음 나오는 자리"가 된다.

    import bisect
import random

def insertion_sort_count(a):
    a = a[:]
    count = 0
    for i in range(1, len(a)):
        x, j = a[i], i - 1
        while j >= 0:
            count += 1
            if a[j] > x:
                a[j + 1] = a[j]
                j -= 1
            else:
                break
        a[j + 1] = x
    return a, count

data = random.Random(1).sample(range(10_000), 1000)   # 서로 다른 값 1,000개
r1, c1 = insertion_sort_count(data)
r2, c2 = insertion_sort_count(sorted(data))
r3, c3 = insertion_sort_count(sorted(data, reverse=True))
print(r1 == r2 == r3 == sorted(data))                 # True
print(c1, c2, c3)                                      # "249650 999 499500"

def lower_bound(a, target):
    lo, hi = 0, len(a)              # hi는 "여기까지는 아니다"인 자리 (끝 포함 안 함)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid                # a[mid]가 답일 수 있으니 남긴다
    return lo

rnd = random.Random(26)
ok = True
for _ in range(1000):
    a = sorted(rnd.randrange(20) for _ in range(rnd.randrange(10)))
    t = rnd.randrange(-2, 22)
    ok = ok and lower_bound(a, t) == bisect.bisect_left(a, t)
print(ok)                                              # True
print(lower_bound([1, 2, 2, 2, 3], 2))                 # 1

scores = [("kim", 90), ("lee", 85), ("park", 90), ("choi", 70)]
print(sorted(scores, key=lambda s: (-s[1], s[0])))     # [('kim', 90), ('park', 90), ('lee', 85), ('choi', 70)]
    • 1에서 무작위 입력은 249,650번으로, 거꾸로 된 입력(499,500번)의 절반쯤이다. 값마다 평균으로 앞의 절반쯤을 지나기 때문이다. 정렬된 입력만 O(n)이고, 무작위와 거꾸로는 O(n²)이다.
    • lower_bound는 범위를 [lo, hi)로 잡아 hi = mid로 줄인다. lo <= hi와 hi = mid를 섞으면, lo == hi인 칸에서 멈추지 못해 끝나지 않거나, 모든 값보다 큰 target에서 a[len(a)]를 읽어 IndexError가 난다.
    • 3은 점수에 마이너스를 붙여 큰 점수가 앞으로 오게 하고, 같으면 이름으로 가른다. Python의 정렬은 같은 키끼리 원래 차례를 지키므로(안정 정렬), 이름 차례로 한 번 정렬한 뒤 점수로 다시 정렬해도 결과가 같다.

    AI와 함께 확인하기¶

    AI 활용 과제: 같은 값이 여럿일 때의 이진 탐색

    1. AI에게 "정렬된 리스트에서 target이 처음 나오는 위치를 이진 탐색으로 찾고, 없으면 -1을 돌려주는 Python 함수"를 짜 달라고 한다.
    2. 실행하기 전에 다음 경우의 답을 적는다. [1, 2, 2, 2, 3]에서 2, [1, 2, 2, 2, 3]에서 4, 빈 목록에서 1, [5]에서 5, [1, 3]에서 3.
    3. 실행해 대조한다. 틀리거나 끝나지 않으면 그 입력을 보여 주고 고치게 한다.
    확인할 점
    • 답은 차례로 1, -1, -1, 0, 1이다. 같은 값이 여럿일 때 그냥 찾으면 2, 3 중 아무 자리나 돌려주기 쉽다. 찾은 뒤에도 왼쪽을 계속 봐야 한다.
    • lo = mid처럼 범위를 줄이지 않는 코드는 원소가 두 개 남았을 때 끝나지 않는다. [1, 3]에서 3을 찾으면 lo가 0에 머문다.
    • bisect.bisect_left를 쓰는 짧은 답도 맞다. 다만 돌려준 자리의 값이 정말 target인지, 자리가 len(a)가 아닌지 확인하는 줄이 있어야 한다.

    더 알아보기¶

    이 항목의 측정 프로그램

    1·3절의 값은 아래 프로그램을 이 PC(Core i9-14900KF, DDR5 64GB)의 Python 3.14로 3번 실행한 결과다. 삽입 정렬은 1,000 / 2,000 / 4,000 / 8,000개에서 9.0~9.1 / 37.8~38.0 / 148.7~158.2 / 598.0~605.5ms, 병합 정렬은 0.78~0.83 / 1.63~1.65 / 3.52~3.75 / 7.50~7.87ms, sorted는 0.055~0.059 / 0.116~0.123 / 0.249~0.250 / 0.533~0.733ms였다. n이 2배일 때 삽입 정렬은 약 4배, 병합 정렬은 2배 남짓 늘었다.

    import bisect
import random
import time

def insertion_sort(a):
    a = a[:]
    for i in range(1, len(a)):
        x, j = a[i], i - 1
        while j >= 0 and a[j] > x:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = x
    return a

def merge_sort(a):
    if len(a) <= 1:
        return a[:]
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    out.extend(left[i:]); out.extend(right[j:])
    return out

def ms(f, *args):
    t = time.perf_counter(); r = f(*args); return (time.perf_counter() - t) * 1000, r

rnd = random.Random(26)
for n in (1000, 2000, 4000, 8000):
    a = [rnd.randrange(10**9) for _ in range(n)]
    t1, r1 = ms(insertion_sort, a)
    t2, r2 = ms(merge_sort, a)
    t3, r3 = ms(sorted, a)
    assert r1 == r2 == r3
    print(f"n={n} 삽입 {t1:.1f}ms 병합 {t2:.2f}ms sorted {t3:.3f}ms")

big = list(range(0, 2_000_000, 2))          # 정렬된 100만 개
qs = [rnd.randrange(2_000_000) for _ in range(1000)]
t, c1 = ms(lambda: sum(q in big for q in qs))
t2, c2 = ms(lambda: sum(bisect.bisect_left(big, q) < len(big) and big[bisect.bisect_left(big, q)] == q for q in qs))
assert c1 == c2
print(f"100만 개에서 1000번 찾기: in(선형) {t:.0f}ms, bisect(이진) {t2:.2f}ms")
    정렬은 비교만으로는 n log n보다 빨라질 수 없다

    값끼리 비교만 해서 정렬하는 방법은 최악의 경우 적어도 약 n log₂n번 비교해야 한다는 것이 증명되어 있다. n개를 늘어놓는 경우의 수 n!개 가운데 하나를 비교의 예/아니오로 가려내려면 log₂(n!)번이 필요하기 때문이다. 값의 범위가 좁은 정수라면 비교하지 않고 개수만 세는 계수 정렬로 O(n)에 정렬할 수도 있다.

    정리¶

    • 삽입·선택 정렬은 O(n²), 병합 정렬은 O(n log n)이다. 퀵 정렬은 평균 O(n log n)이지만 피벗을 잘못 고르면 O(n²)이다. 같은 알고리즘도 입력 모양에 따라 비교 횟수가 크게 다르다.
    • 분할 정복은 반으로 나눠 풀고 합친다. 병합 정렬은 층마다 O(n), 층 수 log n이라 O(n log n)이다.
    • 이진 탐색은 정렬된 입력에서 범위를 반씩 버려 O(log n)이다. 경계 조건은 원소 0개, 1개, 2개로 확인한다.
