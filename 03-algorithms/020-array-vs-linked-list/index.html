    20. 자료구조의 필요성: 배열과 연결 리스트로 보는 메모리 연속성과 접근 효율¶

    직접 AI 없이 직접 할 수 있어야 하는 항목

    같은 값 여러 개를 담더라도 메모리에 어떻게 늘어놓느냐에 따라 빨라지는 일과 느려지는 일이 갈린다. 자료구조를 고르는 이유가 이것이다. 가장 기본인 배열과 연결 리스트로 이 차이를 본다. 직접형 항목이므로 연결 리스트를 AI 없이 짜고, 노드를 넣고 지울 때 포인터가 어떻게 바뀌는지 손으로 그릴 수 있어야 한다. 예제는 C다.

    이 항목에서 배우는 것¶

    • 배열과 연결 리스트가 메모리에 어떻게 놓이는지 그릴 수 있다.
    • 읽기, 넣기, 지우기의 비용을 두 자료구조에서 비교하고, 할 일에 맞는 쪽을 고를 수 있다.
    • 연결 리스트의 노드를 만들고, 잇고, 지우고, 돌려주는 코드를 AI 없이 짤 수 있다.

    1. 배열은 붙어 있고, 연결 리스트는 주소로 이어져 있다¶

    struct node {
    int value;
    struct node *next;   /* 다음 노드의 주소. 마지막 노드는 NULL */
};
    • 배열은 같은 크기의 칸이 빈틈없이 붙어 있다. 그래서 i번째 칸의 주소를 곱셈 한 번으로 구한다(10번(메모리 참조의 본질)의 주소 연산).
    • 연결 리스트는 값마다 노드를 따로 받고(11번(힙 메모리 관리)의 malloc), 노드마다 다음 노드의 주소(next)를 넣어 잇는다. 차례로 만들어도 메모리에서는 흩어져 있을 수 있다.
    • 배열은 처음에 칸 수를 정해야 하고, 연결 리스트는 노드를 하나씩 더 받으면 된다. 대신 노드마다 next 주소가 더 든다. x64에서 int 하나짜리 노드는 맞춤 여백까지 16바이트로 값의 4배이고, malloc이 붙이는 관리 정보도 따로 든다(11번(힙 메모리 관리)).

    2. 찾아가기는 배열이, 끼워 넣기는 연결 리스트가 잘한다¶

    직접 해 보기배열과 연결 리스트의 연산 비용연산과 위치를 골라 실행하며, 배열은 몇 칸을 옮기고 연결 리스트는 next를 몇 번 따라가는지 같은 데이터로 비교한다
    새 창에서 크게 열기
    • 읽기: 배열은 몇 번째든 O(1)이다. 연결 리스트는 head에서 next를 i번 따라가야 해서 O(n)이다.
    • 넣기와 지우기: 배열은 뒤의 칸을 모두 밀거나 당겨야 해서 O(n)이다. 연결 리스트는 자리만 알면 연결 두어 개만 바꿔 O(1)이다. 하지만 그 자리까지 찾아가는 데 O(n)이 든다. 그래서 연결 리스트가 확실히 이기는 곳은 맨 앞이다.
    • 배열의 칸이 다 차면 더 큰 배열을 받아 모두 옮겨 담아야 한다(realloc).

    3. 같은 O(n)이라도 붙어 있는 쪽이 빠르다¶

    • 맨 앞에 넣는 일은 연결 리스트가 훨씬 빨랐다. 배열은 넣을 때마다 모든 칸을 밀어서 n번 넣으면 전체가 O(n²)이 된다(19번(알고리즘 효율성 분석)).
    • 처음부터 끝까지 더하는 일은 셋 다 O(n)인데 약 40배, 500배 넘게 차이가 났다. 배열은 칸이 붙어 있어서, 메모리에서 한 번 가져온 64바이트 덩어리(캐시 라인, 5번(메모리 계층 구조))에 다음 값들이 함께 들어 있다. 연결 리스트는 next를 읽어야 다음 노드를 가지러 갈 수 있고, 노드가 흩어져 있을수록 매번 멀리서 가져온다.
    • 그래서 실제로는 배열을 먼저 생각하고, 맨 앞이나 가운데에 넣고 지우는 일이 아주 많을 때 연결 리스트를 고른다.

    예측해 보기¶

    문제 1. int 배열 arr가 0x1000번지에서 시작한다. arr[250]은 몇 번지일까? 연결 리스트의 250번째 노드(0번부터 센다)의 주소는 어떻게 알 수 있을까?

    정답과 해설

    0x13E8. 0x1000 + 250 × 4 = 4096 + 1000 = 5096 = 0x13E8이다. 곱셈과 덧셈 한 번이면 된다. 연결 리스트는 노드 주소에 규칙이 없어서 계산할 수 없다. head에서 next를 250번 따라가 읽어야 비로소 안다.

    문제 2. 무엇이 출력될까? 노드와 화살표를 종이에 그려 가며 따라간다.

    #include <stdio.h>
#include <stdlib.h>

struct node {
    int value;
    struct node *next;
};

struct node *push_front(struct node *head, int v) {
    struct node *p = malloc(sizeof(struct node));
    p->value = v;
    p->next = head;
    return p;
}

int main(void) {
    struct node *head = NULL;
    for (int i = 1; i <= 3; i++)
        head = push_front(head, i * 10);
    head->next = head->next->next;
    for (struct node *p = head; p != NULL; p = p->next)
        printf("%d\n", p->value);
    return 0;
}
    정답과 해설 
    30
10

    맨 앞에 10, 20, 30을 차례로 넣었으니 리스트는 30 → 20 → 10이다. head->next = head->next->next는 30의 next가 20을 건너뛰고 10을 가리키게 한다. 20이 든 노드는 리스트에서 빠졌지만 free하지 않았으니 누수다(11번(힙 메모리 관리)). 지울 노드는 연결을 바꾸기 전에 주소를 따로 들고 있다가 free한다. 이 프로그램은 남은 노드도 free하지 않는다(아래 실습에서 고친다).

    직접 해보기¶

    실습: AI 없이 연결 리스트 짜기

    1. push_front, 모든 값을 한 줄에 찍는 print_list, 노드 수를 세는 length, 모든 노드를 돌려주는 free_list를 짠다. 1~5를 맨 앞에 차례로 넣고 출력한다.
    2. 값이 v인 첫 노드를 지우는 remove_first를 짠다. 지운 노드는 free한다. head 노드를 지우는 경우도 맞게 돌아야 한다.
    3. 리스트를 제자리에서 뒤집는 reverse를 짠다. 짜기 전에 노드 세 개짜리 리스트로 포인터가 바뀌는 단계를 종이에 그린다.
    4. Visual Studio의 Debug 설정에서 main 끝에 _CrtDumpMemoryLeaks()를 불러 누수가 없는지 확인한다(11번(힙 메모리 관리)).
    정답

    예시. main의 출력은 아래와 같다.

    #include <stdio.h>
#include <stdlib.h>

struct node {
    int value;
    struct node *next;
};

struct node *push_front(struct node *head, int v) {
    struct node *p = malloc(sizeof(struct node));
    if (p == NULL)
        return head;                       /* 받지 못하면 그대로 둔다 */
    p->value = v;
    p->next = head;
    return p;
}

void print_list(const struct node *head) {
    for (const struct node *p = head; p != NULL; p = p->next)
        printf("%d ", p->value);
    printf("\n");
}

int length(const struct node *head) {
    int n = 0;
    for (const struct node *p = head; p != NULL; p = p->next)
        n++;
    return n;
}

void free_list(struct node *head) {
    while (head != NULL) {
        struct node *next = head->next;    /* free하기 전에 다음 주소를 챙긴다 */
        free(head);
        head = next;
    }
}

struct node *remove_first(struct node *head, int v) {
    if (head == NULL)
        return NULL;
    if (head->value == v) {                /* head를 지우면 새 head를 돌려준다 */
        struct node *next = head->next;
        free(head);
        return next;
    }
    for (struct node *p = head; p->next != NULL; p = p->next)
        if (p->next->value == v) {
            struct node *gone = p->next;
            p->next = gone->next;
            free(gone);
            break;
        }
    return head;
}

struct node *reverse(struct node *head) {
    struct node *prev = NULL;
    while (head != NULL) {
        struct node *next = head->next;    /* 1. 다음 노드를 챙기고 */
        head->next = prev;                 /* 2. 화살표를 뒤로 돌리고 */
        prev = head;                       /* 3. 한 칸씩 나아간다 */
        head = next;
    }
    return prev;
}

int main(void) {
    struct node *head = NULL;
    for (int i = 1; i <= 5; i++)
        head = push_front(head, i);
    print_list(head);
    printf("length %d\n", length(head));
    head = remove_first(head, 3);
    print_list(head);
    head = remove_first(head, 5);           /* head를 지운다 */
    print_list(head);
    head = reverse(head);
    print_list(head);
    free_list(head);
    return 0;
}

    5 4 3 2 1
length 5
5 4 2 1
4 2 1
1 2 4
    • remove_first가 새 head를 돌려주는 것은 head 자체가 지워질 수 있어서다. 포인터의 포인터(struct node **)를 받아 호출한 쪽의 head를 바꾸는 방법도 있다(10번(메모리 참조의 본질)).
    • free_list에서 free(head); head = head->next;로 쓰면 이미 돌려준 노드를 읽는 해제 후 사용이다(11번(힙 메모리 관리)).

    AI와 함께 확인하기¶

    AI 활용 과제: 지우기 함수의 경계 확인

    1. AI에게 "C 연결 리스트에서 값이 v인 노드를 모두 지우고 새 head를 돌려주는 함수"를 짜 달라고 한다.
    2. 실행하기 전에 다음 입력의 결과를 먼저 적는다. 1 1 2 1 3에서 1 지우기, 빈 리스트, 7 7 7에서 7 지우기.
    3. 실행해 대조하고, Debug 설정의 _CrtDumpMemoryLeaks()로 누수도 확인한다. 틀린 곳은 실행 결과를 보여 주고 고치게 한다.
    확인할 점
    • 결과는 차례로 2 3, 빈 리스트, 빈 리스트여야 한다. 맨 앞에 같은 값이 이어지는 1 1 ...과 전부 지워지는 7 7 7에서 head 처리가 틀리기 쉽다.
    • 지운 노드를 free하지 않거나, free한 노드의 next를 그다음에 읽는 코드가 흔하다. 앞의 것은 누수 보고로, 뒤의 것은 Debug 힙이 채워 둔 0xDD 값(11번(힙 메모리 관리))으로 드러난다.
    • 연속한 두 노드를 지울 때 하나를 건너뛰는지 본다. 지운 뒤에 포인터를 한 칸 더 옮기면 1 1의 두 번째 1이 남는다.

    더 알아보기¶

    이 항목의 측정 프로그램

    3절의 시간은 이 PC(Core i9-14900KF, DDR5 64GB)에서 아래 프로그램을 cl /O2로 빌드해 경우마다 5번 실행한 범위다. 그림의 막대 길이는 중앙값이다. 섞어서 이은 리스트는 실행마다 50~85ms로 크게 흔들렸다. 더하기는 0.2초 넘게 되풀이해 한 번에 걸린 시간으로 나눴다. "섞어서 이었다"는 노드를 다 받은 뒤 잇는 차례만 무작위로 바꾼 것이다. 오래 쓴 프로그램에서 넣고 지우기를 되풀이한 리스트가 이렇게 흩어진다.

    /* usage: walk.exe <0 배열 합 | 1 리스트 합(만든 차례) | 2 리스트 합(섞어 이음) | 3 배열 맨 앞 넣기 | 4 리스트 맨 앞 넣기> <n> */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <windows.h>

struct node { int value; struct node *next; };

static unsigned int seed = 7;
static unsigned int rnd(void) { seed = seed * 1103515245u + 12345u; return seed >> 1; }

static double now_ms(void) {
    static LARGE_INTEGER f; LARGE_INTEGER c;
    if (!f.QuadPart) QueryPerformanceFrequency(&f);
    QueryPerformanceCounter(&c);
    return (double)c.QuadPart * 1000.0 / (double)f.QuadPart;
}

int main(int argc, char **argv) {
    int mode = atoi(argv[1]), n = atoi(argv[2]);
    long long check = 0;
    double t0, t1;
    if (mode == 0) {
        int *a = malloc(n * sizeof(int));
        for (int i = 0; i < n; i++) a[i] = i;
        int reps = 0; t0 = now_ms();
        do { for (int i = 0; i < n; i++) check += a[i]; reps++; t1 = now_ms(); } while (t1 - t0 < 200);
        printf("%d %d %.4f ms %lld\n", mode, n, (t1 - t0) / reps, check);
    } else if (mode == 1 || mode == 2) {
        struct node **nodes = malloc(n * sizeof(struct node *));
        for (int i = 0; i < n; i++) { nodes[i] = malloc(sizeof(struct node)); nodes[i]->value = i; }
        if (mode == 2)   /* 잇는 차례를 섞는다 */
            for (int i = n - 1; i > 0; i--) { int j = rnd() % (i + 1); struct node *t = nodes[i]; nodes[i] = nodes[j]; nodes[j] = t; }
        for (int i = 0; i < n - 1; i++) nodes[i]->next = nodes[i + 1];
        nodes[n - 1]->next = NULL;
        struct node *head = nodes[0];
        int reps = 0; t0 = now_ms();
        do { for (struct node *p = head; p; p = p->next) check += p->value; reps++; t1 = now_ms(); } while (t1 - t0 < 200);
        printf("%d %d %.4f ms %lld\n", mode, n, (t1 - t0) / reps, check);
    } else if (mode == 3) {
        int *a = malloc(n * sizeof(int)); int len = 0;
        t0 = now_ms();
        for (int i = 0; i < n; i++) { memmove(a + 1, a, len * sizeof(int)); a[0] = i; len++; }
        t1 = now_ms();
        printf("%d %d %.4f ms %d\n", mode, n, t1 - t0, a[n / 2]);
    } else {
        struct node *head = NULL;
        t0 = now_ms();
        for (int i = 0; i < n; i++) { struct node *p = malloc(sizeof(struct node)); p->value = i; p->next = head; head = p; }
        t1 = now_ms();
        printf("%d %d %.4f ms %d\n", mode, n, t1 - t0, head->value);
    }
    return 0;
}
    이중 연결 리스트와 동적 배열

    노드마다 앞 노드의 주소(prev)도 두면 이중 연결 리스트다. 지울 노드만 알면 앞 노드를 찾아가지 않고 바로 지울 수 있지만, 노드마다 8바이트가 더 든다. 반대로 배열 쪽에서는 칸이 다 차면 일정한 비율로 큰 배열에 옮겨 담는 동적 배열을 흔히 쓴다. C#의 List<T>는 두 배로, Python의 list는 약 1.13배로 키운다(이 PC의 Python 3.14에서 sys.getsizeof로 확인했다). 비율로 키우면 옮겨 담는 일이 가끔만 생겨서, 끝에 넣는 일은 평균 O(1)이 된다.

    정리¶

    • 배열은 칸이 붙어 있어 i번째를 바로 찾고, 연결 리스트는 노드를 next로 이어 붙여 앞에서부터 따라간다.
    • 배열은 읽기 O(1), 넣기·지우기 O(n)이다. 연결 리스트는 읽기 O(n), 자리를 알 때 넣기·지우기 O(1)이다.
    • 같은 O(n)이라도 붙어 있는 배열이 훨씬 빠르다. 노드를 지울 때는 연결을 고친 뒤 free하고, free한 노드는 다시 읽지 않는다.
