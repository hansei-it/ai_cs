    28. 최적화 기법: 동적 계획법(DP)과 그리디 알고리즘¶

    직접 AI 없이 직접 할 수 있어야 하는 항목

    "가장 적은 동전으로 거슬러 주기", "가방에 가장 비싼 조합 담기", "가장 짧은 길 찾기"처럼 가장 좋은 답을 찾는 문제가 많다. 모든 경우를 다 따지면 경우의 수가 폭발한다. 동적 계획법은 작은 문제의 답을 적어 두고 다시 써서 이것을 피하고, 그리디는 매 순간 가장 좋아 보이는 것을 골라 빠르게 답한다. 그리디는 빠르지만 늘 맞지는 않는다. 직접형 항목이므로 두 방법을 AI 없이 짜고, 그리디가 틀리는 입력을 찾아낼 수 있어야 한다. 예제는 Python이다.

    이 항목에서 배우는 것¶

    • 같은 계산을 되풀이하는 재귀를 메모이제이션으로 고치고, 호출 횟수가 얼마나 주는지 셀 수 있다.
    • 작은 문제의 답으로 표를 채우는 동적 계획법을 짤 수 있다.
    • 그리디가 최적인 경우와 아닌 경우를 구분하고, 작은 입력으로 반례를 찾을 수 있다.

    1. 같은 계산을 다시 하지 않는다¶

    calls = 0

def fib(n):
    global calls
    calls += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(20))     # 6765
print(calls)       # 21891

    memo = {}

def fib_memo(n):
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib_memo(n - 1) + fib_memo(n - 2)   # 처음 한 번만 계산해 적어 둔다
    return memo[n]

print(fib_memo(90))   # 2880067194370816120
    • 그냥 재귀로 fib(n)을 구하면 호출이 n이 하나 커질 때마다 약 1.6배씩 늘어난다(O(1.6ⁿ)). 이 PC(Core i9-14900KF, Python 3.14)에서 fib(30)은 2,692,537번 호출에 99~107ms가 걸렸다. 같은 속도라면 fib(90)은 호출이 약 9.3 × 10¹⁸번이라 1만 년이 넘게 걸린다.
    • 한 번 구한 답을 사전에 적어 두고 다시 쓰는 것을 메모이제이션이라 한다. fib(30)이 59번 호출, 0.012~0.014ms로 끝났다. 서로 다른 부분 문제가 n개뿐이니 O(n)이다.

    2. 작은 문제의 답으로 표를 채운다¶

    직접 해 보기거스름돈: 그리디와 동적 계획법동전 종류와 금액을 골라, 큰 동전부터 고르는 그리디의 답과 작은 금액부터 표를 채우는 동적 계획법의 답을 한 칸씩 비교한다
    새 창에서 크게 열기 
    def min_coins(coins, amount):
    INF = float("inf")
    best = [0] + [INF] * amount          # best[a] = 금액 a를 만드는 가장 적은 동전 수
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                best[a] = min(best[a], best[a - c] + 1)   # 마지막에 동전 c를 쓰는 경우
    return best[amount] if best[amount] != INF else -1

print(min_coins([1, 4, 5], 8))   # 2
print(min_coins([5, 10], 3))     # -1
    • 동적 계획법은 큰 문제의 답을 작은 문제의 답으로 만들 수 있고, 같은 작은 문제가 여러 번 쓰일 때 쓴다. 금액 a의 답은 "마지막에 동전 c를 쓴다면 a − c의 답 + 1" 가운데 가장 작은 값이다.
    • 1절처럼 위에서 내려가며 메모하는 방법과, 여기처럼 작은 것부터 표를 채워 올라가는 방법이 있다. 표를 채우면 재귀 깊이 걱정이 없다(27번(그래프 탐색 (DFS·BFS)) 문제 2). 칸 수 × 동전 종류 수, 곧 O(금액 × 동전 수)다.
    • 먼저 "표의 한 칸이 무엇을 뜻하는가"를 한 문장으로 쓰고, 그 칸을 앞 칸들로 어떻게 구하는지(점화식)를 쓴다. 이 두 줄이 정해지면 코드는 짧다.

    3. 그리디는 지금 가장 좋아 보이는 것을 고른다¶

    def greedy_coins(coins, amount):
    count = 0
    for c in sorted(coins, reverse=True):     # 큰 동전부터
        count += amount // c
        amount %= c
    return count if amount == 0 else -1

print(greedy_coins([10, 50, 100, 500], 760))   # 5
print(greedy_coins([1, 4, 5], 8))              # 4
    • 그리디는 매 순간 가장 좋아 보이는 선택을 하고 되돌아보지 않는다. 표가 없어 빠르고 짧다. 하지만 "지금의 최선"이 "전체의 최선"으로 이어진다는 것이 증명된 문제에서만 맞는다.
    • 원화처럼 큰 동전이 작은 동전의 배수로 짜인 동전에서는 그리디가 늘 최적이다. 1·4·5원에서는 8원을 4 + 4로 만드는 것이 최적인데, 그리디는 5를 먼저 골라 4개를 쓴다.
    • 그리디가 맞는다고 증명된 대표적인 예는 회의실 배정(끝나는 시간이 이른 회의부터 고르기)과 최단 경로의 다익스트라 알고리즘(27번(그래프 탐색 (DFS·BFS)))이다. 증명이 없으면 작은 입력에서 동적 계획법이나 모든 경우와 비교해 반례가 없는지 확인한다(아래 실습 3).

    예측해 보기¶

    문제 1. 1절의 fib로 fib(10)을 구하면 fib가 모두 몇 번 호출될까?

    calls = 0
fib(10)
print(calls)
    정답과 해설

    177. 호출 수를 c(n)이라 하면 c(0) = c(1) = 1이고 c(n) = c(n−1) + c(n−2) + 1이다. 차례로 1, 1, 3, 5, 9, 15, 25, 41, 67, 109, 177이 된다. 피보나치 수처럼 늘어나서, n이 10 커질 때마다 약 120배가 된다(fib(20)은 21,891번).

    문제 2. 무엇이 출력될까? 위젯에서 동전 1, 3, 4와 금액 6으로 확인한다.

    print(greedy_coins([1, 3, 4], 6), min_coins([1, 3, 4], 6))
    정답과 해설

    3 2. 그리디는 4를 먼저 쓰고 남은 2를 1 + 1로 채워 3개다. 동적 계획법은 3 + 3의 2개를 찾는다. 4를 고른 첫 선택이 나머지를 나쁘게 만들었다.

    직접 해보기¶

    실습: AI 없이 표 채우기

    1. 계단을 한 번에 1칸이나 2칸씩 오른다. n칸을 오르는 방법의 수를 메모이제이션과 표 채우기 두 가지로 구한다. 10칸이면 몇 가지일까?
    2. 0/1 배낭: 무게와 가치가 (1, 1), (3, 4), (4, 5), (5, 7)인 물건이 하나씩 있고 가방은 무게 7까지 든다. 가치의 합이 가장 크게 담는다. 동적 계획법의 답과, "무게당 가치가 큰 것부터 담는" 그리디의 답을 비교한다.
    3. 동전 1, 7, 10에서 금액 1~30 가운데 그리디가 최적보다 많은 동전을 쓰는 금액을 모두 찾는다. 2절의 min_coins와 3절의 greedy_coins로 비교한다.
    정답

    예시.

    stairs_seen = {}                      # 1절의 memo처럼 함수 밖에 둔다

def stairs_memo(n):
    if n <= 2:
        return n                      # 1칸: 1가지, 2칸: 2가지(1+1, 2)
    if n not in stairs_seen:
        stairs_seen[n] = stairs_memo(n - 1) + stairs_memo(n - 2)   # 마지막에 1칸 또는 2칸
    return stairs_seen[n]

def stairs_table(n):
    ways = [0, 1, 2] + [0] * max(0, n - 2)
    for i in range(3, n + 1):
        ways[i] = ways[i - 1] + ways[i - 2]
    return ways[n]

print(stairs_memo(10), stairs_table(10))     # 89 89

def knapsack(items, cap):
    best = [0] * (cap + 1)                   # best[w] = 무게 w까지 담을 때 가장 큰 가치
    for w, v in items:
        for c in range(cap, w - 1, -1):      # 뒤에서부터: 같은 물건을 두 번 담지 않게
            best[c] = max(best[c], best[c - w] + v)
    return best[cap]

def knapsack_greedy(items, cap):
    total = 0
    for w, v in sorted(items, key=lambda x: x[1] / x[0], reverse=True):
        if w <= cap:
            cap -= w
            total += v
    return total

items = [(1, 1), (3, 4), (4, 5), (5, 7)]
print(knapsack(items, 7), knapsack_greedy(items, 7))    # 9 8

print([a for a in range(1, 31) if greedy_coins([1, 7, 10], a) > min_coins([1, 7, 10], a)])   # [14, 15, 16, 24, 25, 26]
    • 1의 답은 89가지다. 마지막 걸음이 1칸이면 n−1칸까지의 방법, 2칸이면 n−2칸까지의 방법이라 피보나치와 같은 꼴이 된다.
    • 2에서 동적 계획법은 (3, 4)와 (4, 5)를 담아 9를 얻는다. 무게당 가치가 가장 큰 (5, 7)(1.4)을 먼저 담는 그리디는 남은 무게 2에 (1, 1)만 더해 8에 그친다.
    • 3에서 14원은 그리디가 10 + 1 + 1 + 1 + 1(5개), 최적은 7 + 7(2개)이다. 작은 입력을 모두 대 보는 것이 그리디를 믿기 전의 가장 값싼 확인이다.

    AI와 함께 확인하기¶

    AI 활용 과제: 최소 동전 수 함수 판정하기

    1. AI에게 "동전 종류 목록과 금액을 받아 금액을 만드는 가장 적은 동전 수를 돌려주는 Python 함수. 만들 수 없으면 -1"을 짜 달라고 한다.
    2. 실행하기 전에 다음의 답을 적는다. [1, 4, 5]로 8, [5, 10]으로 3, [1, 5, 10]으로 0, [1, 5, 10, 25]로 63.
    3. 실행해 대조한다. 틀리면 그 입력을 보여 주고 고치게 한다. 금액을 1,000으로 키워 시간도 잰다.
    확인할 점
    • 답은 차례로 2, -1, 0, 6이다(63 = 25 + 25 + 10 + 1 + 1 + 1).
    • "큰 동전부터"인 그리디로 짜는 경우가 많다. 미국 동전(1, 5, 10, 25센트)에서는 맞아서 그럴듯해 보이지만 [1, 4, 5]로 8에서 4가 나온다.
    • 메모 없는 재귀로 짜면 작은 금액에서는 맞지만 금액이 커지면 끝나지 않는다. 금액 1,000에서 1초 안에 끝나는지 본다. 2절의 표 채우기는 1,000칸 × 동전 수만큼만 계산한다.

    • 메모를 단 재귀는 빠르지만, 금액에서 1씩 줄여 가며 부르므로 재귀 깊이가 금액만큼 깊어진다. 이 PC의 Python 3.14에서 [1, 5, 10, 25]로 금액 1,000을 구하면 RecursionError가 났고, min(f(a - c) for c in coins)처럼 제너레이터 안에서 부르는 꼴은 금액 500에서도 났다(27번(그래프 탐색 (DFS·BFS)) 문제 2). 표 채우기로 고치게 한다.

      print(min_coins([1, 5, 10, 25], 63))     # 6
print(min_coins([1, 5, 10], 0))          # 0

    더 알아보기¶

    functools.cache

    Python 표준 라이브러리의 @functools.cache(3.9부터)를 함수 위에 붙이면, 같은 인자로 부른 결과를 알아서 적어 두었다가 돌려준다. 1절의 fib에 붙이면 memo 사전을 직접 쓰지 않아도 된다. 다만 재귀 깊이 제한(27번(그래프 탐색 (DFS·BFS)) 문제 2)은 그대로라서, n이 1,000 가까이만 돼도 RecursionError가 난다. 이 PC의 Python 3.14에서 @functools.cache를 붙인 fib도, 1절의 fib_memo도 맨 바깥에서 부르면 n = 1,000에서 멈췄다. 다른 함수 안에서 부르면 그만큼 더 일찍 멈춘다. 그럴 때는 표 채우기가 낫다.

    이 항목의 측정 프로그램

    1절의 시간은 아래 프로그램을 이 PC(Core i9-14900KF, DDR5 64GB)의 Python 3.14로 5번 실행한 범위다. 그냥 재귀는 99~107ms, 메모이제이션은 0.012~0.014ms였다. 호출 수를 세는 calls += 1까지 시간에 들어 있다.

    # 28번 측정: fib(30)을 그냥 재귀와 메모이제이션으로 구할 때의 호출 수와 시간
import time

calls = 0

def fib(n):
    global calls
    calls += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

def fib_memo(n, memo):
    global calls
    calls += 1
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]

for name, run in [("plain", lambda: fib(30)), ("memo", lambda: fib_memo(30, {}))]:
    calls = 0
    t = time.perf_counter()
    r = run()
    ms = (time.perf_counter() - t) * 1000
    print(f"{name}: fib(30) = {r}, calls {calls:,}, {ms:.3f} ms")

    정리¶

    • 같은 부분 문제를 되풀이해 푸는 재귀는 답을 적어 두면(메모이제이션) 지수 시간에서 다항 시간으로 준다.
    • 동적 계획법은 "표의 한 칸이 뜻하는 것"과 "그 칸을 앞 칸으로 구하는 식"을 정한 뒤, 작은 칸부터 채운다.
    • 그리디는 지금의 최선을 고르는 빠른 방법이지만, 맞는다는 증명이 있을 때만 믿는다. 증명이 없으면 작은 입력에서 동적 계획법과 비교해 반례를 찾는다.
