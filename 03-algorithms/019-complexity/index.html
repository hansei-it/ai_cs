    19. 알고리즘 효율성 분석: 시간·공간 복잡도와 Big-O(점근 표기법)¶

    직접 AI 없이 직접 할 수 있어야 하는 항목

    같은 일을 하는 코드라도 입력이 커질 때 시간이 늘어나는 모양은 크게 다르다. 배열에 같은 값이 있는지 찾는 두 함수가 1만 개에서는 둘 다 눈 깜짝할 사이에 끝났는데, 10만 개에서는 하나가 7ms 안팎, 다른 하나가 1초 넘게 걸렸다. 이 항목은 코드의 반복을 세어 그 모양을 미리 아는 방법, Big-O를 다룬다. 직접형 항목이므로 AI 없이 반복 횟수를 손으로 셀 수 있을 때까지 연습한다. 예제는 C다.

    이 항목에서 배우는 것¶

    • 코드의 반복 구조를 보고 기본 연산 횟수를 n의 식으로 세고, Big-O로 줄일 수 있다.
    • n이 10배가 될 때 O(log n), O(n), O(n log n), O(n²)의 시간이 몇 배가 되는지 예측하고 측정으로 확인할 수 있다.
    • 입력 말고 더 쓰는 메모리(공간 복잡도)도 같은 방법으로 셀 수 있다.

    1. 입력이 10배가 되면 시간은 몇 배가 되나¶

    직접 해 보기입력이 10배가 되면n을 1,000에서 100만까지 10배씩 바꿔 가며, 네 함수의 실제 실행 시간이 몇 배로 늘어나는지 이론값과 함께 본다
    새 창에서 크게 열기
    • 합계는 모든 칸을 한 번씩 본다. n이 10배면 일도 10배다. 이런 모양을 O(n)이라 쓴다.
    • 모든 쌍 비교는 n개에서 둘씩 고른 모든 짝을 본다. n이 10배면 짝은 100배라 O(n²)이다. 10만 개에서 이미 1초가 넘었다.
    • 이진 탐색은 정렬된 배열을 반씩 줄여 가며 찾아서, n이 10배가 돼도 몇 번만 더 나누면 된다. O(log n)이다. qsort 정렬은 O(n log n)으로 O(n)보다 조금 빨리 늘어난다.
    • Big-O(점근 표기법)는 n이 커질 때 일의 양이 늘어나는 모양만 남긴 표기다. 정확한 시간이 아니라 "n이 10배면 몇 배가 되는가"를 알려 준다.

    2. 반복 횟수를 세고, 가장 빨리 자라는 항만 남긴다¶

    • 한 겹 반복은 n번, 짝을 모두 고르는 이중 반복은 n(n−1)/2번, 두 배씩 커지는 반복은 log₂n번쯤 돈다(i <= n이면 정확히 ⌊log₂n⌋ + 1번).
    • Big-O로 줄일 때는 상수 배와 더 느리게 자라는 항을 지운다. n이 커지면 n²에 비해 n은 무시할 만하고, 0.5배든 2배든 "n이 10배면 100배"라는 모양은 같기 때문이다.
    • 반복이 나란히 있으면 더하고(n + n = 2n → O(n)), 안에 겹쳐 있으면 곱한다(n × n → O(n²)). 반복 안에서 부르는 함수가 몇 번 도는지도 함께 센다(아래 "AI와 함께 확인하기").

    3. 공간도 같은 방법으로 센다¶

    • 공간 복잡도는 입력 말고 더 쓰는 메모리가 n에 따라 어떻게 늘어나는지다. 배열을 제자리에서 뒤집으면 O(1), 뒤집은 복사본을 만들면 O(n)이다.
    • 재귀는 부를 때마다 프레임이 쌓이므로(9번(함수 호출과 메모리)), 깊이가 n인 재귀는 스택을 O(n) 쓴다. 같은 일을 반복문으로 하면 O(1)이다.
    • 시간과 공간은 자주 맞바꾼다. 아래 실습의 "정렬해서 중복 찾기"는 n칸짜리 복사본을 더 쓰는 대신, 10만 개에서 모든 쌍 비교보다 200배 가까이 빨랐다.

    예측해 보기¶

    문제 1. 무엇이 출력될까?

    #include <stdio.h>

int main(void) {
    int n = 1000;
    long long count = 0;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            count++;
    printf("%lld\n", count);
    return 0;
}
    정답과 해설

    499500. i가 0일 때 999번, 1일 때 998번, … 998일 때 1번, 999일 때 0번 돈다. 합은 n(n−1)/2 = 1000 × 999 / 2 = 499,500이다. O(n²)이라서 n을 10배(10,000)로 하면 49,995,000으로 약 100배가 된다.

    문제 2. 무엇이 출력될까? 그림의 셈법을 그대로 쓴다.

    #include <stdio.h>

int main(void) {
    int n = 1000, a = 0, b = 0;
    for (int i = 0; i < n; i++)          /* 나란히 둔 두 반복 */
        a++;
    for (int j = 0; j < n; j++)
        a++;
    for (int i = 1; i <= n; i *= 2)      /* 두 배씩 커지는 반복 */
        b++;
    printf("%d %d\n", a, b);
    return 0;
}
    정답과 해설

    2000 10. 나란히 둔 반복은 더한다. n + n = 2n이라 O(n²)이 아니라 O(n)이다. 두 배씩 커지는 반복은 i가 1, 2, 4, …, 512일 때 돌고 1024에서 멈추므로 10번이다. log₂1000 ≈ 9.97이고, n이 1,000배인 100만이어도 20번이다. 이것이 O(log n)이다.

    직접 해보기¶

    실습: AI 없이 세고, 재고, 줄이기

    1. 아래 세 반복이 n = 1024일 때 몇 번 도는지 먼저 손으로 세고 Big-O로 줄인다. 그다음 실행해 확인한다.
    2. 배열에 같은 값이 있는지 찾는 함수를 두 가지로 짠다. 모든 쌍을 비교하는 has_dup_pairs와, 복사본을 qsort로 정렬한 뒤 이웃끼리 비교하는 has_dup_sorted다. Release로 빌드해 n = 10,000과 100,000에서 시간을 잰다.
    3. 배열을 뒤집는 함수를 제자리 방식(추가 메모리 O(1))과 복사본 방식(O(n)) 두 가지로 짠다.
    #include <stdio.h>

int main(void) {
    int n = 1024;
    long long a = 0, b = 0, c = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < 10; j++)
            a++;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < i; j++)
            b++;
    for (int i = n; i > 0; i /= 2)
        for (int j = 0; j < n; j++)
            c++;
    printf("%lld %lld %lld\n", a, b, c);
    return 0;
}
    정답

    10240 523776 11264. 1번의 답이다. 첫째는 10n이라 O(n)이다. 상수 10은 지운다. 둘째는 0 + 1 + … + (n−1) = n(n−1)/2라 O(n²)이다. 셋째는 바깥 반복이 i = 1024, 512, …, 1의 11번(⌊log₂n⌋ + 1)이고 안쪽이 n번이라 곱해서 11n, O(n log n)이다.

    2. 예시. 정렬하면 같은 값은 이웃에 모인다.

    int has_dup_pairs(const int *a, int n) {
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (a[i] == a[j])
                return 1;
    return 0;
}

int cmp_int(const void *p, const void *q) {
    int x = *(const int *)p, y = *(const int *)q;
    return (x > y) - (x < y);
}

int has_dup_sorted(const int *a, int n) {
    int *b = malloc(n * sizeof(int));     /* 추가 메모리 O(n) */
    if (b == NULL)
        return -1;
    memcpy(b, a, n * sizeof(int));
    qsort(b, n, sizeof(int), cmp_int);    /* O(n log n) */
    int found = 0;
    for (int i = 1; i < n; i++)           /* O(n) */
        if (b[i - 1] == b[i]) {
            found = 1;
            break;
        }
    free(b);
    return found;
}

    이 PC(Core i9-14900KF)에서 중복이 없는 배열(가장 오래 걸리는 경우)로 Release 빌드를 5번 재니, n = 10,000에서 has_dup_pairs는 12.6~13.7ms, has_dup_sorted는 0.53~0.66ms였다. n = 100,000에서는 1,249~1,287ms와 6.3~7.3ms였다. 앞의 것은 100배, 뒤의 것은 12배쯤 늘었다. n log n이 10배가 되면 12.5배다. 측정 프로그램은 아래 "더 알아보기"에 있다.

    3. 예시. 제자리 방식은 양 끝을 바꿔 가며 가운데로 온다. 복사본 방식은 돌려받은 배열을 호출한 쪽이 free한다(11번(힙 메모리 관리)).

    void reverse_in_place(int *a, int n) {
    for (int i = 0, j = n - 1; i < j; i++, j--) {
        int tmp = a[i];
        a[i] = a[j];
        a[j] = tmp;
    }
}

int *reverse_copy(const int *a, int n) {
    int *r = malloc(n * sizeof(int));
    if (r == NULL)
        return NULL;
    for (int i = 0; i < n; i++)
        r[i] = a[n - 1 - i];
    return r;
}

    AI와 함께 확인하기¶

    AI 활용 과제: 반복 조건 속에 숨은 반복

    1. 아래 count_a의 시간 복잡도를 AI에게 묻는다.
    2. 길이 10만과 20만인 문자열로, 최적화를 끈 빌드(/Od. Visual Studio Debug 구성의 최적화 설정이다)와 Release(/O2)에서 각각 시간을 잰다.
    3. AI의 답과 측정을 대조하고, 어느 빌드에서나 O(n)이 되게 고친다.
    int count_a(const char *s) {
    int c = 0;
    for (size_t i = 0; i < strlen(s); i++)   /* 반복할 때마다 strlen을 부른다 */
        if (s[i] == 'a')
            c++;
    return c;
}
    확인할 점
    • i < strlen(s)는 반복할 때마다 strlen을 부르고, strlen은 문자열 끝까지 센다. 그래서 n번 × n번 = O(n²)이다. "반복문이 하나니까 O(n)"이라는 답은 틀렸다.
    • 이 PC에서 최적화를 끈 빌드는 10만 자에 266~275ms, 20만 자에 1,066~1,088ms가 걸렸다. 길이가 2배일 때 약 4배, O(n²)의 모양이다.
    • Release에서는 100만 자도 1ms가 안 걸렸다. 기계어를 보니 컴파일러가 strlen을 반복 전에 한 번만 부르도록 바꿔 놓았다. 같은 코드가 빌드에 따라 O(n²)도 되고 O(n)도 된다. 최적화에 기대지 말고 size_t len = strlen(s);로 길이를 미리 구해 두고 i < len으로 비교한다.

    더 알아보기¶

    이 항목의 측정 방법

    위젯의 값은 이 PC(Core i9-14900KF, DDR5 64GB)에서 아래 프로그램을 cl /O2로 빌드해, 함수와 n마다 5번 실행한 중앙값이다(모든 쌍 비교의 n = 100,000은 3번). 한 번 실행에 0.2초 이상 걸리도록 같은 일을 되풀이해 QueryPerformanceCounter로 재고, 한 번 부르는 데 걸린 시간으로 나눴다. 배열에는 서로 다른 값을 섞어 넣어서 모든 쌍 비교가 끝까지 돌게 했다. 정렬은 섞은 배열 16개를 번갈아 정렬했다. 같은 배열만 되풀이해 정렬하면 CPU가 비교 결과를 익혀 버려(분기 예측) n = 1,000에서 시간이 40%쯤 짧게 나온다. 결과(check)를 출력해야 컴파일러가 계산을 없애지 않는다(5번(메모리 계층 구조)의 측정 함정).

    /* usage: growth.exe <알고리즘 0~3> <n>  출력: 한 번 부르는 데 걸린 시간(ns)과 검증값 */
#include <stdio.h>
#include <stdlib.h>
#include <windows.h>

static unsigned int seed = 12345;
static unsigned int rnd(void) { seed = seed * 1103515245u + 12345u; return seed >> 1; }

static int cmp_int(const void *a, const void *b) {
    int x = *(const int *)a, y = *(const int *)b;
    return (x > y) - (x < y);
}

static int binary_search(const int *a, int n, int key) {      /* O(log n) */
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == key) return mid;
        if (a[mid] < key) lo = mid + 1; else hi = mid - 1;
    }
    return -1;
}

static long long sum(const int *a, int n) {                   /* O(n) */
    long long s = 0;
    for (int i = 0; i < n; i++) s += a[i];
    return s;
}

static int has_dup_pairs(const int *a, int n) {               /* O(n^2) */
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (a[i] == a[j]) return 1;
    return 0;
}

static double now_ns(void) {
    static LARGE_INTEGER f; LARGE_INTEGER c;
    if (!f.QuadPart) QueryPerformanceFrequency(&f);
    QueryPerformanceCounter(&c);
    return (double)c.QuadPart * 1e9 / (double)f.QuadPart;
}

int main(int argc, char **argv) {
    int alg = atoi(argv[1]), n = atoi(argv[2]);
    int pool = alg == 2 ? 16 : 1;                               /* 정렬은 섞은 배열 16개를 번갈아 쓴다 */
    int *a = malloc(sizeof(int) * n * pool), *b = malloc(sizeof(int) * n);
    for (int p = 0; p < pool; p++) {
        int *q = a + p * n;
        for (int i = 0; i < n; i++) q[i] = i * 2;              /* 서로 다른 값 */
        for (int i = n - 1; i > 0; i--) { int j = rnd() % (i + 1), t = q[i]; q[i] = q[j]; q[j] = t; }
    }
    long long check = 0;
    int reps = 0;
    if (alg == 0) qsort(a, n, sizeof(int), cmp_int);          /* 이진 탐색은 정렬된 배열에서 */
    double t0 = now_ns(), t1;
    do {
        switch (alg) {
        case 0: for (int k = 0; k < 1000; k++) check += binary_search(a, n, (int)(rnd() % (2u * n))); break;
        case 1: check += sum(a, n); break;
        case 2: {
            const int *q = a + (reps % pool) * n;
            for (int i = 0; i < n; i++) b[i] = q[i];
            qsort(b, n, sizeof(int), cmp_int);
            check += b[n / 2];
            break;
        }
        case 3: check += has_dup_pairs(a, n); break;
        }
        reps++;
        t1 = now_ns();
    } while (t1 - t0 < 2e8 && !(alg == 3 && t1 - t0 > 1e9));
    printf("%d %d %.1f %lld %d\n", alg, n, (t1 - t0) / reps / (alg == 0 ? 1000.0 : 1.0), check, reps);
    return 0;
}

    실습 2의 시간은 아래 프로그램을 cl /O2로 빌드해 쟀다. 서로 다른 값을 섞은 배열로 두 함수를 한 번씩 부르고, 앞뒤의 QueryPerformanceCounter 값 차이를 ms로 출력한다. 마지막 두 수는 두 함수의 답(0 = 중복 없음)이다.

    #include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <windows.h>

int has_dup_pairs(const int *a, int n) {
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (a[i] == a[j])
                return 1;
    return 0;
}

int cmp_int(const void *p, const void *q) {
    int x = *(const int *)p, y = *(const int *)q;
    return (x > y) - (x < y);
}

int has_dup_sorted(const int *a, int n) {
    int *b = malloc(n * sizeof(int));
    if (b == NULL)
        return -1;
    memcpy(b, a, n * sizeof(int));
    qsort(b, n, sizeof(int), cmp_int);
    int found = 0;
    for (int i = 1; i < n; i++)
        if (b[i - 1] == b[i]) {
            found = 1;
            break;
        }
    free(b);
    return found;
}

static double now_ms(void) {
    static LARGE_INTEGER f; LARGE_INTEGER c;
    if (!f.QuadPart) QueryPerformanceFrequency(&f);
    QueryPerformanceCounter(&c);
    return (double)c.QuadPart * 1000.0 / (double)f.QuadPart;
}

int main(void) {
    unsigned int seed = 12345;
    int sizes[] = { 10000, 100000 };
    for (int k = 0; k < 2; k++) {
        int n = sizes[k];
        int *a = malloc(n * sizeof(int));
        for (int i = 0; i < n; i++) a[i] = i * 2;
        for (int i = n - 1; i > 0; i--) { seed = seed * 1103515245u + 12345u; int j = (seed >> 1) % (i + 1), t = a[i]; a[i] = a[j]; a[j] = t; }
        double t0 = now_ms();
        int r1 = has_dup_pairs(a, n);
        double t1 = now_ms();
        int r2 = has_dup_sorted(a, n);
        double t2 = now_ms();
        printf("n=%d pairs %.2f ms sorted %.3f ms (%d %d)\n", n, t1 - t0, t2 - t1, r1, r2);
        free(a);
    }
    return 0;
}
    O, Ω, Θ

    엄밀히는 Big-O는 "이보다 빨리 자라지 않는다"는 위쪽 경계, Big-Ω는 "이보다 느리게 자라지 않는다"는 아래쪽 경계, Big-Θ는 둘 다를 뜻한다. 입력에 따라 횟수가 다를 때는 어느 경우인지도 정해야 한다. 이진 탐색은 가운데 칸에서 바로 찾으면 1번에 끝나지만(최선), 보통은 가장 오래 걸리는 경우(최악)의 횟수를 말한다. 최선·최악은 "어떤 입력이냐"이고, O·Ω·Θ는 "그 횟수를 어떤 경계로 나타내느냐"라서 서로 다른 이야기다. 실무와 대부분의 글에서는 Big-O를 "늘어나는 모양" 정도의 뜻으로 쓴다.

    정리¶

    • Big-O는 n이 커질 때 일의 양이 늘어나는 모양이다. n이 10배일 때 O(n)은 10배, O(n²)은 100배, O(log n)은 거의 그대로다.
    • 반복 횟수를 세고, 상수 배와 느리게 자라는 항을 지운다. 나란한 반복은 더하고, 겹친 반복은 곱한다. 반복 조건과 반복 안에서 부르는 함수의 비용도 센다.
    • 공간 복잡도는 입력 말고 더 쓰는 메모리다. 재귀는 깊이만큼 스택을 쓴다. 시간을 줄이려고 메모리를 더 쓰는 경우가 많다.
