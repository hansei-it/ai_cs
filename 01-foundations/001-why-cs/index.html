    1. AI 시대 컴퓨터 전공자는 무엇을 배우는가: 판단하고 책임지는 엔지니어, 그리고 CS 기초가 더 중요해진 이유¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    AI가 코드를 써 주는 시대에 컴퓨터 전공자는 무엇을 배워야 할까. 이 항목은 이 과정 전체의 지도다. 실행은 되지만 틀린 코드, 바뀌는 엔지니어의 일, 항목의 세 유형, 그리고 모든 항목에서 쓰는 공부 방법인 "예측하고, 실행하고, 대조하기"를 차례로 본다.

    이 항목에서 배우는 것¶

    • AI가 만든 결과물을 겉모습이 아니라 근거로 판단해야 하는 이유를 설명할 수 있다.
    • 직접형, 원리형, 위임형이 무엇이고 각각 어떻게 공부하는지 설명할 수 있다.
    • 실행하기 전에 결과를 예측하고, 실행한 결과와 대조할 수 있다.

    1. 실행은 되는데 틀린 코드가 남는다¶

    AI는 문법 오류 없이 실행되는 코드를 빠르게 만든다. 그래서 남는 위험은 실행은 되는데 틀린 코드다. 위 다섯 사례는 2번(소프트웨어 동작의 물리적 본질), 3번(컴퓨터 핵심 구성 요소), 4번(데이터 표현), 5번(메모리 계층 구조)에서 직접 확인한다.

    틀린 결과를 알아채려면 "원래 이렇게 나와야 한다"는 기대가 있어야 하고, 그 기대는 원리를 알 때 생긴다. 0.1 + 0.2가 0.3이 아니라는 것을 아는 사람만 == 비교를 의심한다. AI의 결과는 맞을 때와 틀릴 때 겉모습이 같다. 말투도, 자신감도, 코드의 깔끔함도 같다. 그래서 기초 지식과 실험으로 가려야 한다. AI가 왜 그럴듯하게 틀리는지는 93번(LLM의 동작 원리)에서 다룬다.

    2. 엔지니어는 판단하고 책임진다¶

    • 판단: AI의 결과가 맞는지, 요구한 것을 했는지, 더 나은 방법은 없는지 가린다. 그러려면 결과를 미리 예측할 수 있어야 하고, 말보다 실행 결과를 근거로 삼아야 한다.
    • 책임: 문제가 생기면 AI가 아니라 그 결과를 받아들인 사람이 책임진다. AI는 책임을 질 수 없다. 저작권, 개인정보, 최종 책임의 소재는 99번(책임과 윤리)에서 다룬다.

    3. 항목마다 공부하는 방법이 다르다¶

    이 과정의 항목은 직접형 39개, 원리형 59개, 위임형 2개다. 항목 제목 아래의 색 배지가 유형을 나타낸다. 유형에 따른 수업과 평가 방식은 부록 A에, 학년별 AI 사용 원칙은 부록 B에 있다.

    4. 예측하고, 실행하고, 대조한다¶

    이 과정의 거의 모든 항목에는 "예측해 보기"가 있다. 순서는 늘 같다.

    1. 예측: 실행하기 전에 결과를 적는다. 머릿속으로만 하면 틀린 예측을 나중에 맞았다고 착각하기 쉽다.
    2. 실행: 실제로 돌려 본다.
    3. 대조: 다르면 왜 다른지 설명한다. 내 생각이 틀렸는지, 코드가 틀렸는지, 측정 방법이 틀렸는지 가린다.

    예측이 틀렸을 때가 가장 많이 배우는 때다. 예측과 대조를 기록하면 내가 어디서 자주 틀리는지, AI가 어디서 자주 틀리는지가 보인다. 이 습관을 AI의 결과에 쓰는 방법은 97번(AI 출력 검증)에서 더 깊이 다룬다.

    예측해 보기¶

    문제 1. 자주 듣는 아래 세 설명은 어디가 틀렸을까?

    1. "AI가 코드를 다 써 주니 CS 기초는 덜 중요해졌다."
    2. "AI가 짠 코드가 테스트 몇 개를 통과했으면 맞는 코드다."
    3. "AI의 설명이 자신 있고 자세하면 믿을 만하다."
    정답과 해설
    1. AI가 코드를 많이 쓸수록 사람은 더 많은 결과를 판단해야 한다. 판단의 기준은 기초 지식에서 나온다. 기초가 없으면 AI의 결과를 그대로 받아들이는 것 말고는 할 수 있는 일이 없다.
    2. 테스트는 시험한 입력에 대해서만 말해 준다. 2번(소프트웨어 동작의 물리적 본질)의 1부터 N까지 합 프로그램은 N = 4에서 맞게 10을 냈지만 N = 0에서는 128을 냈다. 4번(데이터 표현)에서 본 것처럼 0.1f + 0.2f == 0.3f는 우연히 참이지만 0.3f + 0.4f == 0.7f는 거짓이다. 0, 음수, 가장 큰 값처럼 어떤 입력을 시험해야 하는지 아는 것도 기초 지식이다.
    3. AI의 말투와 자신감은 내용이 맞는지와 관계가 없다. 3번(컴퓨터 핵심 구성 요소)에서 본 캐리와 오버플로처럼, 자세하고 그럴듯한 설명도 틀릴 수 있다. 실행 결과와 원리로 확인한다.

    문제 2. 아래 두 일 중 위임형으로 다뤄도 되는 것은 무엇인가? 위 그림의 질문으로 판단한다.

    1. 실수 두 개가 같은지 비교하는 코드
    2. 웹 페이지에서 버튼의 색과 배치를 바꾸는 코드
    정답과 해설

    2. 버튼의 색이나 배치가 틀리면 화면을 보는 순간 드러나므로, AI에게 맡기고 실행해서 확인하면 된다. 실수 비교는 틀려도 오류 없이 실행되고 특정 값에서만 드러나므로(4번(데이터 표현)), 원리를 알아야 알아챌 수 있다.

    AI와 함께 확인하기¶

    AI 활용 과제: AI의 예측과 실제 결과 대조하기

    1. AI에게 "C와 Python에서 7 / 2, -7 / 2, -7 % 2의 결과는 각각 무엇인가?"를 묻는다. Python은 //로 바꿔 묻는다.
    2. AI의 답을 기록한 뒤, C는 Visual Studio에서, Python은 실제로 실행해 대조한다. 설치와 설정은 실습 환경에 있다.
    3. 새 대화나 다른 AI에게도 같은 질문을 해서 답이 같은지 본다.
    4. AI가 틀린 곳이 있으면 실행 결과를 보여 주고 설명하게 한다. 그 설명이 맞는지도 실행으로 확인한다.
    실제 결과
    식 C Python
    7 / 2 (Python은 7 // 2) 3 3
    -7 / 2 (Python은 -7 // 2) −3 −4
    -7 % 2 −1 1
    • 음수 나눗셈과 나머지에서 두 언어가 다르다. C는 0 쪽으로, Python은 아래쪽으로 내린다. "홀수인지 확인하려고 n % 2 == 1을 쓰는 코드"는 C에서 음수 홀수를 놓친다.
    • 이 과제의 목적은 AI가 틀리는지 맞히는지가 아니라, 어떤 답이든 실행으로 확인하는 습관이다. AI가 모두 맞혔다면, 그것도 실행으로 확인했기 때문에 아는 것이다.

    정리¶

    • AI 시대에 엔지니어의 일은 쓰기에서 판단과 책임으로 옮겨 간다. 결과에 대한 책임은 AI가 아니라 사람에게 있다.
    • 실행은 되지만 틀린 결과를 알아채려면 기대값이 있어야 하고, 기대값은 기초 지식에서 나온다.
    • 항목은 "AI가 틀렸을 때 알아채고 고치려면 무엇이 필요한가"로 직접형, 원리형, 위임형으로 나뉜다.
    • 모든 항목에서 예측하고, 실행하고, 대조한다. 예측이 틀렸을 때 가장 많이 배운다.

    관련 항목¶

    • 2번(소프트웨어 동작의 물리적 본질), 3번(컴퓨터 핵심 구성 요소), 4번(데이터 표현), 5번(메모리 계층 구조): 실행은 되지만 틀린 예들이 나온 항목
    • 93번(LLM의 동작 원리): AI가 왜 그럴듯하게 틀리는가
    • 96번(작업 분해와 맥락 제공): 문제를 쪼개고 AI에게 일을 맡기는 방법
    • 97번(AI 출력 검증): AI 출력을 예측하고 대조하며 믿을 정도를 정하는 방법
    • 99번(책임과 윤리): AI 생성 코드의 저작권, 개인정보, 최종 책임
