    2. 소프트웨어가 동작한다는 것의 물리적 본질: 폰 노이만 구조와 명령어 실행 주기¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    프로그램은 메모리에 놓인 숫자다. CPU는 그 숫자를 하나씩 가져와 실행하는 일을 1초에 수십억 번 되풀이한다. 그림 두 장과 작은 가상 CPU로 이 과정을 따라가 본다.

    이 항목에서 배우는 것¶

    • 명령어와 데이터가 같은 메모리에 같은 모양(숫자)으로 들어 있다는 것을 설명할 수 있다.
    • CPU가 가져오기 → 해석 → 실행을 되풀이하는 과정을 따라갈 수 있다.
    • 데이터가 명령어로 실행되면 무슨 일이 생기는지 예측할 수 있다.

    1. 프로그램도 메모리에 있다¶

    • 메모리 칸에는 숫자만 들어 있다. 명령어인지 데이터인지는 칸에 적혀 있지 않다.
    • PC(프로그램 카운터)가 가리키는 칸은 명령어로 읽힌다. 명령어가 가리키는 칸(13, 14, 15번)은 데이터로 읽히고 쓰인다.
    • 13번 칸의 05도 명령어로 읽으면 HALT다. 무엇으로 읽힐지는 CPU가 그 칸을 어떻게 쓰느냐로 정해진다.

    1945년 폰 노이만이 정리한 이 구조를 프로그램 내장 방식이라 하고, 오늘날 거의 모든 컴퓨터가 이렇게 동작한다.

    그림의 숫자는 이 항목에서 쓰는 작은 가상 CPU(토이 CPU)의 명령어다. 16진수 두 자리 중 앞자리가 명령, 뒷자리가 칸 번호다. 1D는 1(LOAD)과 D(13)라서 LOAD 13이다.

    토이 CPU 명령어 표
    값 명령어 하는 일
    0_ HALT 멈춘다
    1a LOAD a ACC ← a번 칸
    2a STORE a a번 칸 ← ACC
    3a ADD a ACC ← ACC + a번 칸
    4a SUB a ACC ← ACC − a번 칸
    5a JMP a PC ← a
    6a JZ a ACC가 0이면 PC ← a
    7_ OUT ACC를 출력한다
    8_ ~ F_ (없음) 알 수 없는 명령어. CPU가 멈춘다

    ACC는 계산하는 값을 담아 두는 CPU 안의 칸이다. 값은 8비트라서 255를 넘으면 256을 뺀 값이 된다(255 + 1 = 0).

    2. CPU는 세 단계를 되풀이한다¶

    1. 가져오기: PC가 가리키는 칸을 IR(명령어 레지스터)로 가져오고, PC를 1 늘린다.
    2. 해석: 앞자리로 무슨 일인지, 뒷자리로 어느 칸인지 읽는다.
    3. 실행: 계산하거나, 메모리를 읽고 쓰거나, PC를 바꾼다.

    PC를 바꾸는 명령어(JMP, JZ)가 있어서 반복과 분기를 만들 수 있다. 프로그래밍 언어의 if와 반복문도 기계어에서는 PC를 바꾸는 명령어다.

    아래 토이 CPU에서 "한 단계"를 눌러 위 그림의 세 단계를 직접 따라가 본다. 위젯의 부품 그림에서 단계마다 쓰이는 부품에 불이 켜진다.

    직접 해 보기토이 CPU‘한 단계’를 눌러 CPU가 명령어를 가져오고, 해석하고, 실행하는 모습을 본다. 메모리 칸도 고칠 수 있다
    새 창에서 크게 열기

    3. 데이터가 명령어가 되면¶

    칸에 구분이 없으니, PC가 데이터가 있는 칸으로 가면 CPU는 그 데이터를 명령어로 실행한다.

    예측해 보기. 아래 프로그램은 3번 칸(52)과 4번 칸(112)을 더해 164를 출력하려 했는데, 끝에 HALT를 빼먹었다. 무엇이 출력될까? 먼저 적은 다음, 위 토이 CPU의 "HALT를 빼먹으면" 예제로 확인한다.

    주소 0 1 2 3 4
    값 13 34 70 34 70
    쓴 사람의 뜻 LOAD 3 ADD 4 OUT 데이터 52 데이터 112
    정답과 해설

    164, 20. OUT 다음에 PC가 3번 칸으로 넘어간다. 52는 16진수 34, 즉 ADD 4라서 ACC가 164 + 112 = 276이 되고, 8비트라 256을 빼 20이 된다. 112는 70, 즉 OUT이라 20이 출력된다. 5번 칸의 0(HALT)에서 멈춘다.

    이 성질은 보안 문제로 이어진다. 공격자가 입력 데이터에 기계어를 숨기고 프로그램이 그곳으로 건너뛰게 만들면, 데이터가 공격자의 프로그램이 된다. 그래서 운영체제는 데이터를 두는 메모리 영역에서는 실행을 막는다(8번(프로세스의 메모리 레이아웃)). AI의 프롬프트 인젝션도 지시와 데이터가 같은 통로로 섞여 들어와 생긴다(79번(AI 시스템 고유의 보안 위협)).

    예측해 보기¶

    문제 1. 토이 CPU의 "카운트다운" 예제는 무엇을 출력하고, 멈출 때까지 명령어를 몇 개 실행할까? 예제를 불러와 메모리를 읽고 예측한 뒤 "끝까지 실행"으로 확인한다.

    정답과 해설

    3, 2, 1을 출력하고 명령어 15개를 실행한다. 처음 LOAD 13 1개, ACC가 3, 2, 1일 때마다 JZ, OUT, SUB, JMP 4개씩 12개, ACC가 0이 되어 건너뛰는 JZ 1개, HALT 1개다.

    문제 2. "자기 수정" 예제는 3번 칸이 HALT인데도 무언가를 출력한다. 무엇을, 왜 출력할까?

    정답과 해설

    42. 1번 칸의 STORE 3이 3번 칸에 112(70, 즉 OUT)를 쓴다. 그래서 3번 칸에 도착했을 때는 이미 OUT으로 바뀌어 있다. 프로그램이 실행 중에 자기 자신을 바꿀 수 있다는 것도 프로그램 내장 방식의 결과다.

    직접 해보기¶

    실습: 토이 CPU 프로그램 짜기

    1. 13번 칸의 9에서 14번 칸의 4를 뺀 값을 출력하는 프로그램을 종이에 짠 뒤, 토이 CPU의 "빈 메모리"에 넣어 실행한다.
    2. (도전) 반복으로 3 × 4를 출력하는 프로그램을 짠다. 남은 횟수를 메모리에 두고 1씩 뺀다.
    정답
    1. LOAD 13, SUB 14, OUT, HALT를 0~3번 칸에, 9와 4를 13, 14번 칸에 넣는다. 5가 출력된다.
    2. 예시: 0~10번 칸에 LOAD 15, ADD 13, STORE 15, LOAD 14, SUB 12, STORE 14, JZ 8, JMP 0, LOAD 15, OUT, HALT, 데이터는 12번 칸 1, 13번 칸 3, 14번 칸 4, 15번 칸 0이다. 12가 출력되고 명령어는 34개 실행된다.

    AI와 함께 확인하기¶

    AI 활용 과제: AI가 짠 기계어 프로그램을 실행으로 판정하기

    1. AI에게 위의 토이 CPU 명령어 표를 주고, "14번 칸의 N까지 1부터 더한 합을 출력하는 프로그램"을 16칸 안에 짜 달라고 한다.
    2. 토이 CPU에 넣어 N = 4, 1, 0으로 실행한다. 올바른 출력은 10, 1, 0이다.
    3. 틀린 출력이 나오면 그 결과를 AI에게 보여 주고 고치게 한다.
    확인할 점
    • N = 0이 가장 많이 틀린다. 1을 뺀 뒤에야 0인지 확인하면, 0 − 1이 255가 되어(4번(데이터 표현)) 255번을 더 돈다. 이렇게 짠 프로그램은 N = 0에서 128을 출력한다.
    • 더하기 전에 0인지 먼저 확인하면 된다. 예: LOAD 14, JZ 8, ADD 15, STORE 15, LOAD 14, SUB 13, STORE 14, JMP 0, LOAD 15, OUT, HALT (13번 칸 1, 14번 칸 N, 15번 칸 0). N = 4, 1, 0에서 10, 1, 0을 출력한다.

    더 알아보기¶

    진짜 CPU의 명령어도 숫자다

    C 함수 하나를 Visual Studio 2026의 컴파일러로 컴파일해 보면(cl /c /O2 /FAc add.c), return a + b; 한 줄이 기계어 바이트 8d 04 11(더하기)과 c3(돌아가기), 명령어 2개가 된다. Debug 설정(/Od)으로 컴파일하면 같은 줄이 명령어 7개가 된다. C 한 줄이 명령어 몇 개가 될지는 컴파일러와 설정이 정한다(7번(소스코드가 기계어가 되기까지)).

    int add(int a, int b) {
    return a + b;
}
    폰 노이만 병목

    명령어도 데이터도 같은 메모리에서 같은 길로 가져오므로, CPU가 아무리 빨라도 메모리에서 가져오는 속도에 묶인다. 이를 폰 노이만 병목이라 하고, 캐시 같은 메모리 계층이 이 병목을 줄인다(5번(메모리 계층 구조)).

    3GHz의 한 박자

    CPU는 클럭이라는 일정한 박자에 맞춰 동작한다. 3GHz는 1초에 30억 번이고, 한 박자는 약 0.33나노초다. 그동안 빛도 약 10cm밖에 못 간다. 칩을 작게 만드는 물리적인 이유 중 하나다.

    정리¶

    • 프로그램 내장 방식: 명령어와 데이터가 같은 메모리에 숫자로 들어 있고, 어느 칸이 명령어인지는 PC가 정한다.
    • CPU는 가져오기 → 해석 → 실행을 되풀이한다. 반복과 분기는 PC를 바꿔서 만든다.
    • 데이터가 명령어로 실행되면 엉뚱한 결과나 보안 문제가 생긴다.
