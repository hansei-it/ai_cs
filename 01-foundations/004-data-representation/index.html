    4. 데이터 표현: 2진수, 비트 연산, 2의 보수, 부동소수점 오차, UTF-8 문자 인코딩의 원리¶

    직접 AI 없이 직접 할 수 있어야 하는 항목

    컴퓨터 안의 데이터는 모두 0과 1이다. 같은 비트도 정수로 읽는지, 실수로 읽는지, 문자로 읽는지에 따라 다른 값이 된다. 네 가지 읽는 법을 그림으로 보고, 비트 탐색기로 직접 바꿔 본다.

    이 항목에서 배우는 것¶

    • 2진수와 16진수를 손으로 바꾸고, 비트 연산을 계산할 수 있다.
    • 2의 보수로 음수를 나타내고, 오버플로가 언제 생기는지 설명할 수 있다.
    • 실수가 근삿값으로 저장되는 이유를 설명하고, 실수를 올바르게 비교할 수 있다.
    • 글자 하나가 UTF-8로 몇 바이트가 되는지 계산할 수 있다.

    실습 환경: 이 항목은 /utf-8을 켠다

    예제는 C로 쓰고, 소스 파일은 서명 있는 UTF-8로 저장한다. Visual Studio의 프로젝트 속성 → 구성 속성 → C/C++ → 명령줄 → 추가 옵션에 /utf-8을 넣는다. 넣지 않으면 한글 문자열이 CP949로 저장되어 strlen("한글")이 6이 아닌 4가 된다. 소스 저장과 콘솔 출력은 실습 환경에 정리했다.

    1. 2진수는 자리마다 2배¶

    • 10진수는 자리가 하나 올라갈 때마다 10배, 2진수는 2배다. 1인 자리의 값을 더하면 10진수가 된다.
    • 10진수를 2진수로 바꿀 때는 2로 계속 나누고 나머지를 아래에서 위로 읽는다. 13은 1101이다.
    • 16진수는 2진수 네 자리를 한 자리(0~9, A~F)로 묶은 것이다. 1바이트가 딱 두 자리라서 바이트를 볼 때 쓴다. C에서는 0xAF처럼 쓴다.
    • 비트 연산은 자리마다 따로 계산한다. &는 둘 다 1이면 1, |는 하나라도 1이면 1, ^는 서로 다르면 1이다. 쓰임새는 아래 "더 알아보기"에 있다.

    2. 음수는 2의 보수로 나타낸다¶

    • 만드는 법: 비트를 뒤집고 1을 더한다. 5 = 0000 0101 → 뒤집기 1111 1010 → +1 → 1111 1011 = −5.
    • 읽는 법: 맨 앞 비트의 자리값을 음수로 본다. 8비트면 −128이라서 1111 1011 = −128 + 64 + 32 + 16 + 8 + 2 + 1 = −5다.
    • 오버플로: 크기가 정해진 정수는 끝에서 한 바퀴 돈다. 그림처럼 가장 큰 양수에 1을 더하면 가장 작은 음수가 된다.

    아래에서 비트를 눌러 켜고 끄거나, +1과 −x 버튼으로 오버플로와 2의 보수를 직접 확인한다.

    직접 해 보기비트 탐색기비트를 눌러 켜고 끄거나 값을 넣어, 같은 비트가 정수·실수·문자로 어떻게 읽히는지 본다
    새 창에서 크게 열기

    3. 실수는 가장 가까운 근삿값으로 저장된다¶

    • 0.1은 2진수로 바꾸면 0.000110011001100…처럼 끝없이 이어져서 정확히 담을 수 없다. 담을 수 있는 수 가운데 가장 가까운 값이 저장된다.
    • 이 작은 차이가 쌓여서 0.1 + 0.2 == 0.3이 거짓이 된다.
    printf("%.17g\n", 0.1 + 0.2);      /* 0.30000000000000004 */
printf("%d\n", 0.1 + 0.2 == 0.3);  /* 0: 거짓 */
    • 실수는 == 대신 허용 오차로 비교한다(fabs(a - b) < 1e-9). 돈은 실수로 계산하지 않고 원 단위 정수로 계산한다.

    아래에 0.1을 넣으면 실제로 저장된 값과 입력값의 차이가 보인다.

    직접 해 보기비트 탐색기비트를 눌러 켜고 끄거나 값을 넣어, 같은 비트가 정수·실수·문자로 어떻게 읽히는지 본다
    새 창에서 크게 열기

    4. 글자는 UTF-8로 1~4바이트가 된다¶

    • 유니코드가 글자마다 번호를 붙이고, UTF-8이 그 번호를 바이트로 바꾼다. 영문은 1바이트, 한글은 3바이트, 😀 같은 이모지는 4바이트다.
    • 첫 바이트의 앞머리가 몇 바이트짜리 글자인지 알려 주고, 이어지는 바이트는 모두 10으로 시작한다.
    • 그래서 글자 수와 바이트 수는 다르다. C의 strlen은 바이트 수를 센다.
    printf("%zu\n", strlen("한글"));  /* 6 */

    아래에 글자를 넣으면 바이트와 앞머리 비트가 보인다.

    직접 해 보기비트 탐색기비트를 눌러 켜고 끄거나 값을 넣어, 같은 비트가 정수·실수·문자로 어떻게 읽히는지 본다

    예측해 보기¶

    문제 1. 8비트 부호 있는 정수에서 0111 1111 + 0000 0001은 10진수로 얼마인가?

    정답과 해설

    −128. 결과 1000 0000은 맨 앞 비트의 자리값이 −128이라 −128로 읽힌다. 수레바퀴에서 가장 큰 양수 다음 칸이다.

    문제 2. 무엇이 출력되는가?

    printf("%zu\n", strlen("AI 시대"));
    정답과 해설

    9. 영문자와 공백이 1바이트씩, 한글이 3바이트씩이라 1 + 1 + 1 + 3 + 3 = 9다. 글자 수는 5개다.

    문제 3. 무엇이 출력되는가?

    float f = 0.1;
printf("%d\n", f == 0.1);
    정답과 해설

    0. f에는 float로 반올림된 0.10000000149…가, 오른쪽 0.1에는 double로 반올림된 0.10000000000000000555…가 담겨 서로 다르다. f == 0.1f로 쓰면 1이 된다. Visual Studio는 첫 줄에 "'double'에서 'float'(으)로 잘립니다"(C4305) 경고를 낸다.

    직접 해보기¶

    실습: AI 없이, 종이와 펜으로

    1. 45를 2진수와 16진수로 바꾼다.
    2. −20을 8비트 2의 보수로 나타내고 16진수로 쓴다.
    3. 가(U+AC00)의 UTF-8 바이트를 16진수로 구한다.
    4. 0xAF & 0x0F, 0xAF | 0x0F, 0xAF ^ 0xFF를 2진수로 풀어 계산하고 16진수로 쓴다.
    5. UTF-8 문자열의 글자 수를 세는 utf8_len(const char *s)를 작성한다. utf8_len("AI 시대")는 5여야 한다.

    1~3은 위의 비트 탐색기로 확인한다.

    정답
    1. 101101, 0x2D
    2. 20 = 0001 0100 → 뒤집기 1110 1011 → +1 → 1110 1100 = 0xEC
    3. AC00 = 1010 1100 0000 0000 → 1010 | 110000 | 000000 → 11101010 10110000 10000000 = EA B0 80
    4. 1010 1111과 0000 1111의 &는 0000 1111 = 0x0F, |는 1010 1111 = 0xAF다. 1111 1111과의 ^는 0101 0000 = 0x50이다. & 0x0F는 아래 네 비트만 남기고, ^ 0xFF는 모든 비트를 뒤집는다.

    5. 이어지는 바이트(10으로 시작)가 아닌 바이트, 즉 글자의 첫 바이트만 센다.

      size_t utf8_len(const char *s) {
    size_t n = 0;
    for (; *s; s++)
        if (((unsigned char)*s & 0xC0) != 0x80)
            n++;
    return n;
}

    2. 실행하기 전에 아래 입력의 결과를 예측해 적는다.
    3. 결과를 아래 print_hex로 바이트까지 출력해, 글자 중간에서 잘렸는지 확인한다. 틀리면 그 입력을 AI에게 보여 주고 고치게 한다.
    입력 최대 바이트 결과 (먼저 적어 보기)
    "한글한글" 4
    "AI 시대" 5
    "😀" 3 
    void print_hex(const char *s) {
    for (; *s; s++)
        printf("%02X ", (unsigned char)*s);
    printf("\n");
}
    예상 결과

    "한"(ED 95 9C), "AI "(41 49 20, 끝에 공백), ""(빈 문자열). 글자를 반쯤 남기지 않고, 들어가는 만큼의 온전한 글자만 남겨야 한다. 흔한 잘못은 snprintf나 strncpy로 바이트만 자르는 것이다. 그러면 "한글"을 4바이트로 자를 때 '글'의 첫 바이트 하나가 남는다.

    더 알아보기¶

    비트 연산과 플래그

    a = 1100(12), b = 1010(10)일 때 a & b = 1000(8), a | b = 1110(14), a ^ b = 0110(6), a << 1 = 11000(24), a >> 2 = 11(3)이다. 여러 켜짐/꺼짐을 정수 하나에 담는 비트 플래그에 쓴다.

    #define READ  0x4   /* 100 */
#define WRITE 0x2   /* 010 */
#define EXEC  0x1   /* 001 */

unsigned perm = READ | WRITE;          /* 110: 읽기·쓰기 권한을 켠다 */
printf("%d\n", (perm & WRITE) != 0);   /* 1: 쓰기 권한이 있다 */
perm = perm & ~WRITE;                  /* 쓰기 권한만 끈다 → 100 */
printf("%d\n", (perm & EXEC) != 0);    /* 0: 실행 권한이 없다 */

    괄호를 빼고 perm & WRITE != 0이라고 쓰면 C는 !=를 먼저 계산해 perm & 1이 된다. 쓰기 권한이 있어도 0이 나온다. Visual Studio는 이 줄에 C4554 경고를 낸다.

    C의 오버플로: 부호 없는 수와 부호 있는 수 
    unsigned char u = 255;
u = u + 1;            /* 0: 부호 없는 정수는 넘치면 0부터 다시 센다 */

int x = INT_MAX;      /* 2147483647 */
x = x + 1;            /* 정의되지 않은 동작 */

    부호 있는 정수의 오버플로는 C 표준이 결과를 정하지 않는다. Visual Studio에서 실행하면 −2,147,483,648이 나오지만, 컴파일러나 최적화 옵션에 따라 달라질 수 있다. C#의 int는 기본 설정에서 넘치면 −2,147,483,648이 되고, Python의 정수는 크기 제한이 없어 넘치지 않는다.

    float로 바꾸면 맞는다? 우연이다

    0.1f + 0.2f == 0.3f는 1(참)이다. 오차가 우연히 같은 값으로 반올림됐을 뿐이다. 반대로 0.3 + 0.4 == 0.7은 double에서 참, float에서는 거짓이다. 몇 번 시험해서 맞았다고 ==를 써도 되는 것은 아니다.

    printf("%.20f\n", 0.1);    /* 0.10000000000000000555 (double) */
printf("%.20f\n", 0.1f);   /* 0.10000000149011611938 (float) */
    큰 정수도 실수로 바꾸면 근삿값이 된다

    float는 \(2^{24}\) = 16,777,216, double은 \(2^{53}\) = 9,007,199,254,740,992를 넘는 정수부터 정확히 담지 못하는 수가 생긴다. (float)16777217은 16777216이 된다. JavaScript의 숫자(Number)는 double이라서, JSON으로 큰 ID를 주고받을 때 숫자가 바뀌는 문제가 여기서 생긴다(63번(JSON과 직렬화)).

    /utf-8 없이 컴파일하면

    아래 코드를 /utf-8 없이 컴파일하면 4 : C7 D1 B1 DB, 켜고 컴파일하면 6 : ED 95 9C EA B8 80이 나온다. 옵션이 없으면 컴파일러가 문자열을 Windows 기본 인코딩인 CP949로 바꿔 저장하고, CP949는 한글 한 글자를 2바이트로 나타낸다. 같은 글자도 인코딩에 따라 바이트가 다르다.

    const char *s = "한글";
printf("%zu :", strlen(s));
for (; *s; s++)
    printf(" %02X", (unsigned char)*s);
printf("\n");

    정리¶

    • 같은 비트도 정수, 실수, 문자 중 무엇으로 읽느냐에 따라 값이 다르다.
    • 음수는 2의 보수(뒤집고 1을 더하기)로 나타낸다. 크기가 정해진 정수는 끝에서 한 바퀴 돈다.
    • 실수는 가장 가까운 근삿값이다. ==로 비교하지 않고, 돈은 정수로 계산한다.
    • 한글 한 글자는 UTF-8로 3바이트다. strlen은 글자 수가 아니라 바이트 수를 센다.
