    11. 힙 메모리 관리: 동적 할당(malloc/free, new/delete)과 메모리 누수¶

    직접 AI 없이 직접 할 수 있어야 하는 항목

    스택의 변수는 함수가 끝나면 저절로 사라지고 크기도 미리 정해야 한다. 실행하면서 크기를 정하거나 함수가 끝난 뒤에도 남겨야 하는 데이터는 힙에 둔다. 힙은 직접 받고 직접 돌려주는 메모리라서, 돌려주는 일을 잊거나 잘못하면 오류 메시지 없이 프로그램이 조금씩 망가지거나 엉뚱한 곳에서 멈춘다. 직접형 항목이므로 받고 돌려주는 짝을 손으로 맞출 수 있을 때까지 연습한다.

    이 항목에서 배우는 것¶

    • malloc과 free로 필요한 만큼 메모리를 받고 돌려줄 수 있다.
    • 누수, 해제 후 사용, 이중 해제가 어떻게 생기는지 설명하고 코드에서 찾을 수 있다.
    • 스택의 포인터와 힙의 블록이 서로 다른 때에 사라진다는 것을 설명할 수 있다.

    1. 힙은 직접 받고 직접 돌려주는 메모리다¶

    #include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n = 5;                               /* 실행 중에 정해지는 크기라고 하자 */
    int *scores = malloc(n * sizeof(int));   /* 힙에서 20바이트를 받는다 */
    if (scores == NULL) {                    /* 받지 못하면 NULL이 온다 */
        printf("memory error\n");
        return 1;
    }
    for (int i = 0; i < n; i++)
        scores[i] = (i + 1) * 10;
    printf("%d\n", scores[4]);
    free(scores);                            /* 다 쓰면 돌려준다 */
    scores = NULL;                           /* 해제한 주소를 들고 있지 않는다 */
    return 0;
}
    • malloc(크기)는 힙에서 그 크기의 블록을 받아 주소를 돌려준다. 받은 블록은 free할 때까지 남아 있다. 함수가 끝나도, 그 주소를 들고 있던 지역 변수가 사라져도 남는다.
    • 받은 블록의 처음 값은 정해져 있지 않다. 0이 필요하면 calloc을 쓴다.
    • C++에서는 new와 delete로 같은 일을 하고, 짝은 C처럼 사람이 맞춘다. C#에서는 돌려주는 일을 가비지 컬렉터(12번(가비지 컬렉션))가 대신한다.

    2. 세 가지 실수: 누수, 해제 후 사용, 이중 해제¶

    직접 해 보기힙 실험실malloc, free 문장이나 실수 시나리오를 눌러, 힙 블록이 생기고 풀리는 모습과 누수·해제 후 사용·이중 해제가 어떻게 생기는지 본다
    새 창에서 크게 열기
    • 누수: 블록을 돌려주지 않은 채 그 주소를 잃는다. 포인터에 다른 주소를 넣거나, 포인터 변수가 있던 함수가 끝나면 잃는다. 프로그램은 멀쩡히 돈다.
    • 해제 후 사용: free한 블록을 옛 주소로 다시 읽거나 쓴다. 그 자리를 다른 malloc이 다시 받았다면 남의 데이터를 망가뜨린다. 이 PC에서 같은 코드를 Release로 20번 실행하면 2번만 그렇게 되어서, 몇 번 시험해서는 드러나지 않는다.
    • 이중 해제: 같은 블록을 두 번 free한다. 이 PC에서 Debug 설정은 어설션 창(_CrtIsValidHeapPointer(block))을 띄웠고, Release는 0xC0000374(힙 손상)로 멈췄다. 그런데 두 번째 free 전에 다른 malloc이 그 자리를 다시 받았다면, 두 설정 모두 멈추지 않고 그 블록을 풀어 버렸다(위젯에서 free(p); 다음 q = malloc(16);, free(p);).

    세 실수 모두 "누가 언제 돌려주는가"가 흐려질 때 생긴다. free한 뒤에는 포인터를 NULL로 지우고, 블록 하나를 여러 포인터가 가리키면 돌려줄 책임을 하나에만 둔다.

    3. 누수는 쌓인다¶

    • 누수는 한 번에는 작아도 실행하는 동안 계속 쌓인다. 오래 켜 두는 서버, 게임, 편집기에서 특히 문제가 된다.
    • Visual Studio의 Debug 설정에서는 _CrtDumpMemoryLeaks()로 남은 블록을 찾을 수 있다. 프로그램 끝에서 부르면 "Detected memory leaks!"와 함께 블록마다 받은 소스 파일의 줄 번호와 크기를 출력 창에 보여 준다(아래 "직접 해보기" 3번).

    예측해 보기¶

    문제 1. process(50), process(200), process(300)을 차례로 부르면 몇 바이트가 샐까? (int는 4바이트)

    int process(int n) {
    int *buf = malloc(n * sizeof(int));
    if (n > 100)
        return -1;          /* 여기서 나가면 buf를 돌려주지 않는다 */
    for (int i = 0; i < n; i++)
        buf[i] = i;
    free(buf);
    return 0;
}
    정답과 해설

    2,000바이트(800 + 1,200). n이 100보다 크면 free에 닿기 전에 돌아간다. process(200)의 800바이트와 process(300)의 1,200바이트가 샌다. _CrtDumpMemoryLeaks()도 이 PC에서 800바이트와 1,200바이트 블록 두 개를 보고했다. 오류를 처리하는 일찍 나가는 길에서 free를 빠뜨리는 것이 흔한 누수다.

    문제 2. 무엇이 출력되고 어떻게 끝날까?

    #include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *a = malloc(sizeof(int));
    int *b = a;
    free(a);
    printf("first\n");
    fflush(stdout);
    free(b);
    printf("second\n");
    return 0;
}
    정답과 해설

    first. b는 a와 같은 블록을 가리키므로 free(b)는 이중 해제다. 이 PC의 Release(그리고 명령줄 cl의 기본 옵션)에서는 0xC0000374(힙 손상)로 멈춰 second가 나오지 않았다. Debug 설정에서는 free(b)에서 _CrtIsValidHeapPointer(block) 어설션 창이 떴다. 다만 보안 프로그램이 감시하는 폴더에서 새로 만든 실행 파일을 처음 실행했을 때는 second까지 찍힌 뒤 같은 코드로 끝나기도 했다. 이중 해제는 정의되지 않은 동작이라 언제 드러나는지가 환경마다 다르다. 두 포인터가 같은 블록을 가리킬 때는 한쪽만 돌려준다.

    직접 해보기¶

    실습: AI 없이 받고 돌려주는 짝 맞추기

    1. 1부터 n까지를 담은 배열을 힙에 만들어 돌려주는 int *make_range(int n)를 짠다. 받지 못하면 NULL을 돌려준다. 호출한 쪽에서 출력하고 free한다.
    2. 문제 1의 process가 새지 않도록 고친다.
    3. Visual Studio에서 문제 1의 코드 앞에 아래 세 줄을 넣는다. main을 만들어 process(50), process(200), process(300)을 부르고, main 끝에서 _CrtDumpMemoryLeaks();를 부른다. F5로 실행한 뒤 출력 창에서 누수 보고를 찾는다.
    #define _CRTDBG_MAP_ALLOC
#include <stdlib.h>
#include <crtdbg.h>
    정답

    1. 예시:

      int *make_range(int n) {
    int *a = malloc(n * sizeof(int));
    if (a == NULL)
        return NULL;
    for (int i = 0; i < n; i++)
        a[i] = i + 1;
    return a;            /* 돌려줄 책임은 호출한 쪽에 넘어간다 */
}

    2. 일찍 나가는 길에서도 돌려준다. 받기 전에 검사하면 더 간단하다.

      int process(int n) {
    if (n > 100)
        return -1;       /* 받기 전에 나간다 */
    int *buf = malloc(n * sizeof(int));
    if (buf == NULL)
        return -1;
    for (int i = 0; i < n; i++)
        buf[i] = i;
    free(buf);
    return 0;
}

    3. "Detected memory leaks!" 아래에 소스파일.c(줄) : {번호} normal block at 0x…, 800 bytes long.처럼 블록마다 받은 줄과 크기가 나온다. Data: 줄의 CD는 Debug 힙이 "받았지만 아직 아무것도 쓰지 않은 칸"을 채워 두는 값이다.

    AI와 함께 확인하기¶

    AI 활용 과제: 문자열을 이어 붙이는 함수 판정하기

    1. AI에게 "두 문자열을 이어 붙인 새 문자열을 힙에 만들어 돌려주는 C 함수 concat"을 짜 달라고 한다.
    2. Visual Studio의 새 프로젝트(Debug)에서 빌드하고, 반복문 안에서 1000번 부른 뒤 _CrtDumpMemoryLeaks()로 확인한다.
    3. 아래 "확인할 점"으로 판정하고, 문제가 있으면 실행 결과를 보여 주고 고치게 한다.
    확인할 점
    • '\0' 자리: malloc(strlen(a) + strlen(b))처럼 끝의 '\0' 한 바이트를 빼먹는 일이 흔하다. 출력은 멀쩡히 나오지만, 이 PC의 Debug 설정에서는 free할 때 "HEAP CORRUPTION DETECTED: after Normal block … CRT detected that the application wrote to memory after end of heap buffer."가 떴다. 길이는 strlen(a) + strlen(b) + 1이다.
    • 돌려줄 책임: 함수가 힙의 블록을 돌려주면, 다 쓴 뒤 free할 책임은 호출한 쪽에 있다. 함수 설명에 그 사실이 적혀 있는지, 호출한 코드가 free하는지 본다. 반복문에서 free를 빼먹으면 1000개 블록이 누수로 보고된다.

    • strcpy와 SDL 검사: AI가 strcpy, strcat을 쓰면, SDL 검사가 켜진 Visual Studio 새 프로젝트에서는 C4996이 오류가 되어 빌드되지 않는다. 길이를 이미 알므로 memcpy로 복사하면 된다.

      char *concat(const char *a, const char *b) {
    size_t la = strlen(a), lb = strlen(b);
    char *s = malloc(la + lb + 1);
    if (s == NULL)
        return NULL;
    memcpy(s, a, la);
    memcpy(s + la, b, lb + 1);   /* b의 '\0'까지 */
    return s;                    /* 호출한 쪽이 free한다 */
}

    더 알아보기¶

    Debug 힙이 채워 두는 값

    Visual Studio의 Debug 설정은 실수를 드러내려고 힙을 특정 값으로 채운다. 이 PC에서 malloc 직후의 int를 읽으면 -842150451(0xCDCDCDCD), free한 뒤에 읽으면 -572662307(0xDDDDDDDD)이 나왔다. 디버거에서 이런 값을 보면 "아직 안 쓴 메모리" 또는 "이미 해제한 메모리"를 읽고 있다는 신호다. Release에는 이런 채우기가 없어서 그때그때 다른 값이 나온다.

    C++의 new와 delete

    C++에서는 int *scores = new int[n];으로 받고 delete[] scores;로 돌려준다(배열이면 delete[]). 1절의 프로그램을 이렇게 바꿔 C++로 빌드해도 50이 출력된다. C++은 객체가 범위를 벗어날 때 자동으로 돌려주는 도구(스마트 포인터)를 함께 쓰는 것이 보통이다.

    정리¶

    • 힙의 블록은 malloc으로 받고 free로 돌려줄 때까지 남는다. 그 주소를 든 포인터는 스택에 있어서 먼저 사라질 수 있다.
    • 누수(돌려주지 않음)와 해제 후 사용(돌려준 뒤 씀)은 오류 없이 지나가거나 가끔만 드러난다. 이중 해제(두 번 돌려줌)는 대개 멈추지만, 그 자리를 다시 받은 블록이 있으면 조용히 그 블록을 풀어 버린다.
    • 받는 곳마다 돌려주는 곳을 짝지어 두고, free한 포인터는 NULL로 지운다. Debug 설정의 누수 보고와 힙 검사를 활용한다.
