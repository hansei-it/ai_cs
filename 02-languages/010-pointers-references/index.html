    10. 메모리 참조의 본질: 포인터, 주소 연산, 값 타입 vs 참조 타입¶

    직접 AI 없이 직접 할 수 있어야 하는 항목

    변수에는 값이 있고, 그 값은 메모리의 어느 주소에 있다. 포인터는 그 주소를 값으로 담는 변수다. 포인터를 알면 "함수가 호출한 쪽의 변수를 바꾸는 법", "배열이 함수에 넘어갈 때 생기는 일", "대입이 복사인지 공유인지"가 한 번에 보인다. 직접형 항목이므로 메모리 그림을 손으로 그릴 수 있을 때까지 연습한다.

    이 항목에서 배우는 것¶

    • &(주소 구하기)와 *(가리키는 칸)로 포인터를 만들고 쓸 수 있다.
    • 포인터에 1을 더하면 몇 바이트 움직이는지 계산할 수 있다.
    • 값을 복사하는 것과 같은 것을 가리키는 것을 구분하고, 주소를 넘겨 호출한 쪽의 변수를 바꿀 수 있다.

    1. 포인터는 주소를 담는 변수다¶

    • &a는 a가 있는 주소다. int *p = &a;는 "int를 가리키는 포인터 p에 a의 주소를 넣는다"는 뜻이다.
    • *p는 p가 가리키는 칸이다. *p = 7은 a를 7로 바꾼다. 같은 칸을 a와 *p 두 이름으로 부르는 것이다.
    • 초기화하지 않은 포인터는 어디를 가리키는지 모른다. Visual Studio는 이런 코드에 경고 C4700을 내고, 새 프로젝트의 기본값인 SDL 검사(/sdl)가 켜져 있으면 오류로 막는다. 아무것도 가리키지 않는 NULL을 *로 읽으면 0xC0000005로 멈춘다.

    2. 주소 연산은 칸 단위다¶

    아래 실험실에서 문장 버튼을 눌러 실행한다. p = &a;와 *p = *p + 100;으로 1절의 *p를 확인하고, p = arr; 다음 p = p + 1;을 눌러 주소가 몇 바이트 움직이는지 본다.

    직접 해 보기포인터 실험실C 문장 버튼을 눌러 실행하며, 포인터 p가 가리키는 칸과 *p로 바뀌는 값, p + 1이 움직이는 거리를 메모리 그림으로 본다
    새 창에서 크게 열기
    • 포인터에 1을 더하면 주소가 1이 아니라 가리키는 타입 하나의 크기만큼 늘어난다. 이 PC에서 int *는 4바이트, char *는 1바이트, double *는 8바이트 움직였다.
    • 배열 이름을 식에 쓰면 첫 칸의 주소가 된다. 그래서 arr[i]와 *(arr + i)는 같은 칸이다. sizeof(arr)처럼 sizeof 안에 쓸 때만 배열 전체를 뜻한다.
    • 배열을 함수에 넘기면 첫 칸의 주소, 곧 포인터 하나만 넘어간다. 함수 안에서 sizeof(arr)는 배열 전체가 아니라 포인터의 크기다. 그래서 배열을 받는 함수는 길이를 따로 받는다.

    예측해 보기. 무엇이 출력될까?

    int arr[3] = { 10, 20, 30 };
int *p = arr;
p = p + 2;
printf("%d %d\n", *p, (int)((char *)p - (char *)arr));
    정답과 해설

    30 8. p + 2는 int 두 칸, 곧 8바이트 뒤인 arr[2]를 가리킨다. 두 번째 값은 바이트 단위로 센 거리라서 2가 아니라 8이다. 포인터 실험실에서 p = arr; 다음 p = p + 1;을 두 번 눌러 확인할 수 있다.

    3. 복사하느냐, 가리키느냐¶

    struct point { int x; };
struct point p = { 1 };
struct point q = p;      /* 값을 복사한다 */
q.x = 9;
printf("%d\n", p.x);     /* 1 */
struct point *r = &p;    /* p를 가리킨다 */
r->x = 9;
printf("%d\n", p.x);     /* 9 */
    • 9번(함수 호출과 메모리)에서 swap(x, y)가 x와 y를 바꾸지 못한 것은 값이 복사되어 넘어갔기 때문이다. swap(&x, &y)처럼 주소를 넘기고 함수 안에서 *a, *b를 바꾸면 호출한 쪽의 x와 y가 바뀐다.
    • C#은 이 차이를 타입에 정해 둔다. struct로 만든 타입은 대입하면 복사되는 값 타입이고, class로 만든 타입의 변수는 처음부터 객체를 가리키는 참조 타입이다. 같은 코드도 타입이 struct인지 class인지에 따라 결과가 다르다(아래 문제 2).

    예측해 보기¶

    문제 1. count는 배열의 칸 수를 돌려주려고 짠 함수다. 64비트로 빌드하면 무엇이 출력될까?

    #include <stdio.h>

int count(int arr[]) {
    return sizeof(arr) / sizeof(arr[0]);
}

int main(void) {
    int scores[5] = { 90, 80, 70, 60, 50 };
    printf("%d\n", (int)(sizeof(scores) / sizeof(scores[0])));
    printf("%d\n", count(scores));
    return 0;
}
    정답과 해설 
    5
2

    main 안의 scores는 배열이라 sizeof가 20바이트, 칸 수 5가 나온다. count의 arr는 이름만 배열처럼 썼을 뿐 포인터라서 sizeof(arr)는 8, 8 / 4 = 2다. 32비트로 빌드하면 1이 나온다. Visual Studio는 /W4에서도 이 코드에 경고를 내지 않았다. 배열을 받는 함수는 int count(int arr[], int n)처럼 길이를 따로 받는다.

    문제 2. 아래 C# 코드는 PointS(struct)와 PointC(class)에 같은 일을 한다. 두 줄에 무엇이 출력될까?

    var s1 = new PointS { X = 1 };
var s2 = s1;
s2.X = 9;
Console.WriteLine(s1.X);

var c1 = new PointC { X = 1 };
var c2 = c1;
c2.X = 9;
Console.WriteLine(c1.X);

struct PointS { public int X; }
class PointC { public int X; }
    정답과 해설 
    1
9

    struct는 값 타입이라 s2 = s1에서 값이 복사되고, s2를 바꿔도 s1은 그대로다. class는 참조 타입이라 c2 = c1에서 같은 객체를 가리키게 되고, c2.X = 9는 c1.X도 바꾼다. .NET 10에서 실행해 확인했다. 대입이 복사인지 공유인지는 12번(가비지 컬렉션)과 14번(객체 지향 4대 특징과 인터페이스)에서도 계속 중요하다.

    직접 해보기¶

    실습: AI 없이, 메모리 그림으로

    1. 아래 코드를 한 줄씩 실행할 때마다 a, b, p의 값을 표로 적는다. 포인터 실험실에서 p = &a;부터 같은 순서로 눌러 확인한다.
    2. 배열의 모든 칸에 v를 더하는 void add_all(int *arr, int n, int v)를 포인터로 짠다. arr[i]를 쓰지 않고 *(arr + i)나 p++로 짜 본다.
    3. 두 정수를 받아 큰 값을 첫 번째 변수에, 작은 값을 두 번째 변수에 넣는 void order(int *big, int *small)를 짠다.
    int a = 5, b = 8;
int *p = &a;
*p = *p + 100;
p = &b;
*p = 0;
printf("%d %d\n", a, b);   /* 105 0 */
    정답
    1. p = &a 뒤 *p는 a라서 a가 105가 된다. p = &b 뒤 *p = 0은 b를 0으로 바꾼다. 출력은 105 0이다.

    2. 예시:

      void add_all(int *arr, int n, int v) {
    for (int *p = arr; p < arr + n; p++)
        *p += v;
}

    3. 예시:

      void order(int *big, int *small) {
    if (*big < *small) {
        int t = *big;
        *big = *small;
        *small = t;
    }
}

    AI와 함께 확인하기¶

    AI 활용 과제: 배열 길이를 구하는 함수 판정하기

    1. AI에게 "C에서 배열을 받아 그 배열의 원소 개수를 돌려주는 함수"를 짜 달라고 한다.
    2. 5칸 배열을 넘겨 실행해 본다. x64와 x86 둘 다 해 본다.
    3. 결과가 5가 아니면 실행 결과를 보여 주고 이유를 설명하게 한 뒤, 고친 방법을 다시 실행해 판정한다.
    확인할 점
    • 문제 1의 sizeof(arr) / sizeof(arr[0])를 그대로 내놓는 경우가 있다. 이 PC에서 x64는 2, x86은 1이 나왔고, 컴파일러는 경고하지 않았다. 오류 없이 틀린 값이 나오는 대표적인 경우다.
    • 함수 안에서 배열의 길이를 알아내는 방법은 없다. 길이를 매개변수로 함께 받거나, 배열이 선언된 곳에서 sizeof(scores) / sizeof(scores[0])로 구해 넘긴다.
    • AI가 "배열은 함수에 넘기면 포인터로 바뀐다"고 설명하면, 그 설명을 이 항목의 그림으로 다시 확인한다.

    더 알아보기¶

    Visual Studio의 SDL 검사

    새로 만든 C/C++ 프로젝트는 SDL 검사(/sdl)가 켜져 있다. 이 옵션은 일부 경고를 오류로 바꾼다. 초기화하지 않은 포인터를 쓰는 코드는 cl /W3에서는 경고 C4700만 나오고 빌드되어 실행 중 0xC0000005로 멈췄지만, /sdl을 붙이면 같은 C4700이 오류가 되어 빌드가 멈췄다. 켜고 끄는 곳은 실습 환경 3절에 있다.

    포인터의 포인터

    포인터도 변수라서 주소가 있다. int **pp = &p;는 포인터 p의 주소를 담는다. **pp는 p가 가리키는 칸, 곧 a다. 함수가 호출한 쪽의 포인터 자체를 바꿔야 할 때 쓴다. 예를 들어 함수 안에서 malloc으로 받은 주소를 호출한 쪽의 포인터에 넣어 주려면 int **out을 받아 *out = malloc(...)처럼 쓴다.

    정리¶

    • 포인터는 주소를 담는 변수다. &로 주소를 구하고 *로 가리키는 칸을 읽고 쓴다.
    • 포인터 + 1은 가리키는 타입 하나만큼 움직인다. 배열을 함수에 넘기면 포인터가 되어 길이 정보가 사라진다.
    • 대입은 값을 복사하고, 주소를 담으면 같은 것을 함께 본다. 함수가 호출한 쪽의 변수를 바꾸려면 주소를 넘긴다.
