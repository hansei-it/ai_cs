    42. 도메인 네임 시스템(DNS)의 계층적 질의 구조¶

    원리 동작을 예측하고 이상을 알아챌 수 있어야 하는 항목

    사람은 www.example.com 같은 이름을 기억하고, 컴퓨터는 IP 주소로 찾아간다(40번(IP 주소 체계와 NAT)). 이름을 IP 주소로 바꿔 주는 것이 DNS다. 세상의 이름을 서버 하나가 다 알 수는 없어서, 이름을 나무 모양으로 나눠 단계마다 다른 서버가 맡는다. 이 항목은 그 나무를 따라 묻는 과정과 캐시를 이 PC에서 직접 따라가 본다. 브라우저에 주소를 넣으면 가장 먼저 일어나는 일이다(44번(URL 입력부터 렌더링까지)).

    이 항목에서 배우는 것¶

    • 도메인 이름의 단계(루트, 최상위 도메인, 도메인)와 단계마다 맡는 서버를 설명할 수 있다.
    • 내 PC, DNS 서버(리졸버), 루트와 그 아래 서버가 주고받는 질문과 답의 차례를 말할 수 있다.
    • 캐시와 TTL이 있을 때 이름을 찾는 단계와 시간을 예측할 수 있다.

    1. 이름은 나무 모양으로 나눠 맡는다¶

    • 도메인 이름은 점으로 나뉜 단계이고 오른쪽이 위다. 맨 위가 루트(.)이고, 그 아래가 최상위 도메인(TLD: com, org, kr), 그 아래가 example.com 같은 도메인이다.
    • 단계마다 맡은 서버가 다르다. 위 단계는 바로 아래 단계를 맡은 서버가 누구인지만 알려 준다(위임). 이름의 IP 주소를 실제로 아는 곳은 그 도메인을 맡은 서버뿐이다.
    • 그래서 주인이 서버 주소를 바꿀 때는 자기 도메인의 서버만 고치면 된다. 루트와 .com을 맡은 쪽은 아무것도 고치지 않는다.

    2. DNS 서버가 루트부터 차례로 묻는다¶

    • 내 PC는 설정된 DNS 서버에 "끝까지 알아봐 달라"고 한 번만 묻는다(재귀 질의). 이 PC에서는 학교 DNS 서버였다.
    • 그 서버(리졸버)는 루트에 물어 .com을 맡은 서버를, .com 서버에 물어 example.com을 맡은 서버를 알아낸다. 마지막으로 그 서버에서 답을 받는다(반복 질의). 이 PC에서 루트부터 직접 물어 따라가니 세 서버에 32.7, 68.4, 5.7ms(5번의 중앙값)가 걸렸다.
    • 질문과 답은 UDP로 한 번씩 주고받는다(41번(전송 계층 (TCP·UDP))). www.example.com의 질문은 수십 바이트뿐이다(문제 1). 답이 오지 않으면 리졸버가 다시 묻는다. 이 PC에서도 측정 중 한 번은 답이 오지 않았다.

    3. 답은 TTL 동안 캐시에 둔다¶

    직접 해 보기DNS 캐시와 TTL이름을 묻고 시간을 흘려 보내며, 내 PC와 학교 DNS 서버의 캐시가 TTL에 따라 남고 사라지는 모습과, 그때마다 몇 단계를 거쳐 몇 ms가 드는지 본다
    새 창에서 크게 열기
    • 이름을 찾을 때마다 루트부터 물으면 느리고 루트에 질문이 몰린다. 그래서 리졸버와 내 PC는 받은 답을 TTL(초) 동안 캐시에 둔다. www.example.com의 IP 주소는 TTL이 300초였고, example.com을 맡은 서버는 172,800초(2일)였다.
    • 이 PC에서 학교 DNS 서버의 캐시에 있는 이름을 물으면 0.76ms, Windows 캐시에 있으면 0.09ms였다(20번의 중앙값). 캐시가 비어 루트부터 물으면 www.example.com은 100ms 남짓이다.
    • 같은 학교의 누군가가 먼저 물은 이름은 학교 DNS 서버의 캐시에 있어서 나에게도 빠르다. 대신 서버 주소를 바꿔도 TTL이 다할 때까지는 옛 주소를 알려 준다(문제 3).

    예측해 보기¶

    문제 1. DNS 질문 메시지를 직접 만든다. 무엇이 출력될까?

    import struct

name = "www.example.com"
q = struct.pack("!HHHHHH", 0x1234, 0x0100, 1, 0, 0, 0)   # 머리: 번호, 플래그(끝까지 알아봐 달라), 질문 1개
q += b"".join(bytes([len(p)]) + p.encode() for p in name.split(".")) + b"\0"
q += struct.pack("!HH", 1, 1)                            # 종류 A(IPv4 주소), 클래스 IN
print(len(q))
print(q[12:29])
    정답과 해설 
    33
b'\x03www\x07example\x03com\x00'

    이름은 점을 쓰지 않고, 단계마다 길이 한 바이트를 앞에 붙인다. www(3), example(7), com(3)이고 끝은 길이 0이다. 머리 12바이트, 이름 17바이트, 종류와 클래스 4바이트를 더해 33바이트다. 이것을 UDP로 DNS 서버의 53번 포트에 보내면 답이 온다(더 알아보기의 측정 프로그램).

    문제 2. 캐시가 빈 학교 DNS 서버에 www.example.com을 묻고, 5분 뒤에 다시 묻는다. 두 번째는 어느 서버까지 묻고 몇 ms쯤 걸릴까? 내 PC의 캐시도 TTL이 같다. 위젯의 시간으로 어림한다.

    정답과 해설

    학교 DNS 서버와 example.com의 서버, 6.46ms. 답의 TTL(300초)이 다해 내 PC와 학교 DNS 서버의 캐시에서 답이 사라졌다. 하지만 example.com을 맡은 서버는 172,800초 동안 캐시에 있으므로 루트와 .com 서버에는 다시 묻지 않는다. 0.76 + 5.7 = 6.46ms다. 위젯에서 "묻기", "5분 지나기", "묻기"를 차례로 눌러 확인할 수 있다.

    문제 3. 학교가 www.hansei.ac.kr의 IP 주소를 바꿨다. 바로 전에 집의 PC가 통신사 DNS 서버를 거쳐 옛 주소를 받아 두었다면, 집에서 새 주소로 가기까지 길게는 얼마나 걸릴까?

    정답과 해설

    하루. 이 이름의 답은 TTL이 86,400초였다. 통신사 DNS 서버와 집 PC의 캐시는 그동안 옛 주소를 알려 준다. 그래서 서버를 옮기기 며칠 전에 TTL을 몇 분으로 줄여 두고, 옮긴 뒤에 다시 늘린다. TTL이 짧으면 바꾼 주소가 빨리 퍼지지만, 리졸버가 그만큼 자주 물어야 한다. 학교 안은 다르다. 학교 DNS 서버가 hansei.ac.kr을 맡은 서버이기도 해서(실습 1의 확인할 점) 바뀐 주소를 바로 알려 준다. 학교 PC의 Windows 캐시에 남은 옛 답만 TTL 동안 쓰인다.

    직접 해보기¶

    실습: 이름을 찾는 길 따라가기

    1. 명령 프롬프트에서 nslookup www.example.com을 실행한다. 맨 위의 "서버"가 내 PC에 설정된 DNS 서버다.
    2. nslookup -type=NS example.com으로 example.com을 맡은 서버들을 본다.
    3. "더 알아보기"의 측정 프로그램 1에서 이름을 바꿔(www.naver.com 등) 실행하고, 몇 서버를 거치는지 센다.
    4. 위젯에서 www.kisa.or.kr(.kr을 관리하는 한국인터넷진흥원)을 묻고 "1일 지나기" 뒤에 다시 묻는다. 어느 서버부터 묻는지 보고 까닭을 TTL로 설명한다.
    확인할 점
    • 1에서 이 PC는 학교 DNS 서버의 이름이 보였다. 답 앞에 "권한 없는 응답"이라고 나오면, 그 도메인을 맡은 서버가 아니라 리졸버가 캐시나 대신 물어 온 답을 준 것이다.
    • nslookup www.hansei.ac.kr에는 "권한 없는 응답"이 나오지 않았다. 이 학교의 DNS 서버는 리졸버이면서 hansei.ac.kr을 맡은 서버이기도 해서, 이 이름은 대신 묻지 않고 자기가 맡은 기록으로 답했다.
    • 2에서 example.com을 맡은 서버는 Cloudflare의 서버 둘(*.ns.cloudflare.com)이었다.
    • 3에서 www.naver.com은 이 PC에서 6번 물었다. naver.com의 서버가 IP 주소 대신 다른 이름(www.naver.com.nheos.com, CNAME)을 알려 줘서, 그 이름을 루트부터 다시 찾았기 때문이다. 캐시가 없는 이 프로그램이라서 루트부터 물었고, 실제 리졸버는 캐시에 둔 .com 서버부터 묻는다. 마지막 답의 TTL은 60초였다.
    • 4에서는 .kr 서버부터 묻는다. 답(TTL 600초)과 kisa.or.kr을 맡은 서버(86,400초, 1일)는 사라졌지만, .kr을 맡은 서버는 172,800초라 남아 있다.

    AI와 함께 확인하기¶

    AI 활용 과제: 라이브러리 없이 DNS 묻기

    1. AI에게 "dnspython 없이 Python 소켓만으로, 루트 서버(198.41.0.4)에 www.example.com의 A 레코드를 묻고 답을 모두 찍는 코드"를 짜 달라고 한다.
    2. 실행하기 전에 루트 서버가 IP 주소를 알려 줄지, 무엇을 알려 줄지 예측한다.
    3. 실행해서 찍힌 서버 이름이 맞는지 본다. 깨진 이름이나 오류가 나오면 이유를 AI에게 묻는다.
    확인할 점
    • 루트 서버는 IP 주소를 모른다. .com을 맡은 서버 13개(a~m.gtld-servers.net)를 알려 줄 뿐이다. "루트 서버가 모든 이름의 주소를 안다"는 설명은 틀렸다.
    • 답 속의 이름은 압축되어 있다. 앞에 나온 이름과 겹치는 부분은 첫 바이트가 0xC0 이상인 2바이트로, 앞의 위치를 가리킨다. 이 압축을 따라가지 않는 코드는 서버 이름을 깨뜨리거나 멈춘다. 측정 프로그램 1의 read_name이 이 일을 한다.
    • 질문의 플래그에 "끝까지 알아봐 달라"(0x0100)를 켜도 루트 서버는 대신 찾아 주지 않는다. 그 일은 리졸버의 몫이다.

    더 알아보기¶

    이 항목의 측정 프로그램

    2절, 3절, 그림, 위젯의 시간은 이 PC(학교 유선망)에서 아래 두 프로그램을 5번씩 실행한 값의 중앙값이다. 측정 프로그램 1은 질문을 직접 만들어 루트부터 차례로 묻고, 서버마다 묻고 받는 데 걸린 시간을 찍는다. 학교 DNS 서버도 같은 학교망에 있으므로, 그 서버가 바깥 서버들에 묻는 시간도 이 PC에서 잰 값과 비슷하다고 보았다. 서버들의 답이 가끔 100ms 넘게 늦거나 오지 않았다.

    # 42번 측정 1: 루트 서버부터 차례로 물어 이름을 IP 주소로 바꾸고, 서버마다 묻고 받는 데 걸린 시간을 찍는다
import random
import socket
import struct
import time

ROOT = ("a.root-servers.net", "198.41.0.4")


def question(name, rd=0):                     # rd=1이면 "끝까지 알아봐 달라"(재귀 질의)
    q = struct.pack("!HHHHHH", random.randrange(65536), rd << 8, 1, 0, 0, 0)
    q += b"".join(bytes([len(p)]) + p.encode() for p in name.split(".")) + b"\0"
    return q + struct.pack("!HH", 1, 1)       # 종류 A(IPv4 주소), 클래스 IN


def read_name(data, i):                       # 이름을 읽는다. 0xC0으로 시작하면 앞에 나온 이름을 가리킨다(압축)
    labels, end = [], None
    while data[i]:
        if data[i] >= 0xC0:
            end = end or i + 2
            i = ((data[i] & 0x3F) << 8) | data[i + 1]
            continue
        labels.append(data[i + 1:i + 1 + data[i]].decode())
        i += 1 + data[i]
    return ".".join(labels), end or i + 1


def records(data):                            # (구역, 이름, 종류, TTL, 값)의 목록
    counts = struct.unpack("!HHHH", data[4:12])
    i = read_name(data, 12)[1] + 4            # 질문 하나를 건너뛴다
    out = []
    for sec, n in zip(["answer", "authority", "additional"], counts[1:]):
        for _ in range(n):
            name, i = read_name(data, i)
            typ, _cls, ttl, size = struct.unpack("!HHIH", data[i:i + 10])
            i += 10
            val = socket.inet_ntoa(data[i:i + 4]) if typ == 1 else read_name(data, i)[0] if typ in (2, 5) else None
            out.append((sec, name, typ, ttl, val))
            i += size
    return out


def ask(server, name):
    for _ in range(3):                        # UDP는 잃어도 다시 보내 주지 않으므로, 답이 없으면 다시 묻는다
        with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as s:
            s.settimeout(3)
            t = time.perf_counter()
            s.sendto(question(name), (server, 53))
            try:
                data = s.recv(4096)
            except TimeoutError:
                print("  (3초 안에 답이 없어 다시 묻는다)")
                continue
        return records(data), (time.perf_counter() - t) * 1000
    raise TimeoutError(server)


def resolve(name):
    sname, server = ROOT
    while True:
        rr, ms = ask(server, name)
        print(f"  {sname}: {ms:.1f} ms")
        for sec, n, typ, ttl, val in rr:
            if sec == "answer" and typ == 1 and n == name:
                return val, ttl
            if sec == "answer" and typ == 5:                     # 다른 이름(CNAME)으로 가라
                print(f"  {name} -> {val}")
                return resolve(val)
        ns = [val for sec, n, typ, ttl, val in rr if sec == "authority" and typ == 2]
        glue = {n: val for sec, n, typ, ttl, val in rr if sec == "additional" and typ == 1}
        sname = next((n for n in ns if n in glue), ns[0])
        server = glue.get(sname) or resolve(sname)[0]           # 주소가 함께 오지 않으면 그 이름부터 찾는다


for name in ["www.example.com", "www.kisa.or.kr"]:
    print(name)
    ip, ttl = resolve(name)
    print(f"  -> TTL {ttl}")

    측정 프로그램 2는 이 PC에 설정된 DNS 서버(학교 DNS 서버)에 묻는 시간과, Windows 캐시에서 찾는 시간을 20번씩 재어 중앙값을 찍는다.

    # 42번 측정 2: 이 PC에 설정된 DNS 서버(학교 DNS 서버)에 묻는 시간과, Windows 캐시에서 찾는 시간 (20번의 중앙값)
import random
import socket
import statistics
import struct
import subprocess
import time

server = subprocess.run(["powershell", "-NoProfile", "-Command",
                         "(Get-NetIPConfiguration | Where-Object IPv4DefaultGateway | Select-Object -First 1)"
                         ".DNSServer | Where-Object AddressFamily -eq 2 | ForEach-Object { $_.ServerAddresses[0] }"],
                        capture_output=True, text=True).stdout.split()[0]


def ask(name):                                # 끝까지 알아봐 달라(재귀)는 질문 하나
    q = struct.pack("!HHHHHH", random.randrange(65536), 0x0100, 1, 0, 0, 0)
    q += b"".join(bytes([len(p)]) + p.encode() for p in name.split(".")) + b"\0" + struct.pack("!HH", 1, 1)
    with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as s:
        s.settimeout(3)
        t = time.perf_counter()
        s.sendto(q, (server, 53))
        s.recv(4096)
    return (time.perf_counter() - t) * 1000


def lookup(name):                             # Windows를 거쳐 찾기 (캐시에 있으면 캐시에서)
    t = time.perf_counter()
    socket.getaddrinfo(name, 80, socket.AF_INET)
    return (time.perf_counter() - t) * 1000


lookup("www.example.com")                     # 한 번 찾아 Windows 캐시에 넣는다
print("DNS server", f"{statistics.median(ask('www.example.com') for _ in range(20)):.2f} ms")
print("Windows cache", f"{statistics.median(lookup('www.example.com') for _ in range(20)):.2f} ms")

    정리¶

    • 도메인 이름은 오른쪽이 위인 나무이고, 단계마다 맡은 서버가 다르다. 위 단계는 아래 단계를 맡은 서버만 알려 준다(위임).
    • 내 PC는 리졸버에 한 번 묻고(재귀 질의), 리졸버는 루트, TLD 서버, 그 도메인의 서버에 차례로 묻는다(반복 질의). 질문과 답은 UDP로 오간다.
    • 답은 TTL 동안 리졸버와 내 PC의 캐시에 남는다. 캐시 덕에 대부분 1ms 안쪽에 끝나지만, 주소를 바꿔도 TTL 동안은 옛 주소가 쓰인다.
